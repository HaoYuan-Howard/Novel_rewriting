# Handoff：小说重构流水线 · 审校台

## 这是什么

一个本地单人工具的前端。后端已经跑通：把一本网络小说的原作，经 stage0–stage7 的流水线重构成一本新书——情节骨架保留、文字全部重写、人名全部替换，最后落一个成书 txt。

这个前端要解决的不是「怎么跑流水线」，而是**每一层跑完之后，人怎么确认它没跑歪**。所以它通篇是审阅界面：左边是判据 / 材料 / 上游，右边是产物，人对完点确认，下一层才允许开跑。

## 包里的文件是设计稿，不是要直接上线的代码

`审校台.dc.html` 是用 HTML 做的**高保真设计稿**——真实数据、可点、状态齐全，用来说明「长什么样、怎么动」。你的任务是**在目标工程里重建它**，用那边已有的框架和组件库；如果目标工程还没有，按下面「技术栈」选型自己搭。

不要把这个 HTML 直接塞进产品：它是一个自包含的演示文件，所有逻辑压在一个类里，样式全是内联，没有路由、没有构建、没有类型。

## 保真度

**高保真（hifi）**。颜色、字号、间距、状态色、文案全部是最终值，照抄。留白和密度也是定过的——「中等密度」，不要自作主张改成紧凑或宽松。

React + TypeScript + Vite，本地单人、跑在 `127.0.0.1`，不做多租户、不做鉴权。

## 三道缝：这是这次交接最重要的部分

设计稿里已经把这三道缝切好了，重建时**保住它们**，别在重写时糊掉。

### 1. 数据缝 —— 所有数据只从一条路进来

设计稿里：

```js
const MOCKS = { novels: 'novels.json', s0: 'stage0_extras.json', … };

need(keys) {                                  // 按屏声明依赖，去重、防重复请求
  keys.forEach((k) => {
    if (data[k] || loading[k] || failed[k]) return;
    fetch('./mocks/' + MOCKS[k])
      .then(r => r.json())
      .then(j => setState(data: {...data, [k]: j}))
      .catch(() => setState(failed: {...failed, [k]: true}));
  });
}
```

屏幕**从不自己取数**，只读 `state.data[key]`。接真后端就是把 `MOCKS` 换成 API client——一个模块的事。

请落成：`src/api/client.ts`（真实 HTTP）+ `src/api/mock.ts`（读 `mocks/*.json`），同一个接口，用环境变量切。`mocks/` 里 20 份 JSON 是**抓自现役后端的真实响应**，字段名、嵌套、空值都别改，它就是契约。

`failed[key]` 这条路要留着：请求失败时界面必须显示「取不到」，不能显示空白（见下面 U-00）。

### 2. 静态 / 动态分离

**静态**（设计契约，不是数据，落成 `src/constants/vocabulary.ts`，前后端共用一份枚举）：

| 常量 | 是什么 | 取值 |
|---|---|---|
| `FRESH` | 产物新鲜度四态 | `fresh` 新鲜 / `stale` 过期 / `unknown` 无从判断 / `missing` 不在盘上 |
| `SEV` | 判据四级 | `hard` 阻断 / `info` 提示 / `metric` 度量 / `unver` 查不了 |
| `BADGE` | 校验器徽章 | `pass` / `amber` / `fail` |
| `STAGES` | 八个阶段的编号与名字 | stage0…stage7 |
| `RAIL` | 左导航的屏序 | 见「屏清单」 |

每个条目自带 `color` / `bg` / `label` / `shape`。**颜色只从这里取**，不要在组件里写死十六进制。

**动态**：只有服务端响应（`mocks/` 里那 20 份的真身）。

### 3. 渲染缝 —— 一屏一个纯函数

设计稿里每屏一个 `valsNN()`：输入 `state.data`，输出这一屏要显示的所有东西（含事件回调）。它是纯的、可单测的。

请落成 `src/screens/<name>/useXxxScreen.ts`（或 selector 函数），**一屏一个文件，不要合并**。组件只负责摆放，不做判断。

## 硬规则（`brief/03_ui_rules.md` 是完整版，当验收清单逐条对）

### U-00 ·「不知道」永远不能画成「没问题」

贯穿全部。这个工具最贵的错误不是显示错，是**让人以为已经确认过了**。所以：

- 数据取不到 → 明说「取不到」，不显示 0、不显示空、不显示灰色占位
- 校验没跑过 → 「没跑过」，虚线圆点，不是绿色
- `unver`（查不了）→ 独立一级，虚线圆点 + 独立颜色，**绝不能并进「通过」**
- amber 徽章 = 通过了但有 N 项查不了 → 文案必须写出「它不是绿的」
- 只抓了某一本 / 某一章的样本时 → 明说「这一份响应没有在样本里」，**绝不拿另一本的数据顶上**

设计稿里有一个专门的「缺样本」屏在演示这条，务必保留这个行为。

### 状态语言 = 色 + 形 + 文字，三者齐备

不能只靠颜色区分状态。四态各有自己的形状：

| 状态 | 形 |
|---|---|
| fresh / pass / hard / info | 实心圆点（hard 更大 + 描边） |
| stale | 实心方块 |
| unknown / unver | 虚线圆点 |
| metric | 一条底线（不是点） |

每个点旁边永远跟着文字标签。

### 花钱的操作要拦一道

调 LLM 的按钮统一是橙色 `oklch(0.55 0.16 38)`，点了先弹确认框，框里**原样摆出将要执行的命令行**，并写明「发起后没有取消——调用在途时钱已经花了」。免费但写盘的操作（重跑校验、提升产物、归档旧轮）用深色按钮 + 一个小 `写盘` 角标。

## 屏清单（11 屏 + 1 常驻面板）

左侧常驻阶段导航，按流水线顺序排；已确认的屏在导航上带 `✓`，上游没过的屏带`锁`且半透明。

| # | 屏 | 干什么 | 版式是需求？ |
|---|---|---|---|
| — | **语料库** `corpus` | 所有书的产物矩阵 + 新鲜度；顶部是「开一本新书」上传口 | |
| 0 | **剔除番外** `stage0` | 扫番外/后记/作者有话说，确认删除范围；扫不到时人工逐块圈 | ★ 左右并排 |
| 1 | **分章报告** `stage1` | 切分结果 ↔ 原文未切分全文，下滑对照 | ★ 左右并排 |
| 2 | **原文↔骨架** `read` | 这一章原文里哪些被抽成骨架、哪些漏了 | ★ 左右并排 |
| 2 | **全局设定** `global` | 人物、关系、世界规则、情节弧 | |
| 3 | **文风画像** `style` | 要模仿的那支笔：语感区间、习惯、钩子写法 | |
| 4 | **计划↔上下文** `stage4` | 每一拍的重构计划 ↔ 写手真正拿得到的材料 | ★ 左右并排 |
| — | **挑深度章节** `depth` | 写作前选哪些章深度重构（默认前 3 章），其余浅层 | |
| 5 | **成稿↔材料** `stage5` | 左=判据报了什么，中/右=成稿 ↔ 原文，就地改 | ★ 三栏 |
| 6 | **开篇文案** `stage6` | 先从三候选里定稿一条；定稿后左=校验、中=原作文案、右=重构文案（可编辑） | ★ 定稿后三栏 |
| 7 | **人名+成书** `stage7` | 人名替换表、残留检查、拼装成书 | |
| — | **待办** `inbox` | 全书还卡着什么 + 七层校验器状态。**只路由，不提供编辑** | |
| P | **作业面板** | 底部常驻抽屉，日志实时流，四态：running / ok / failed / unknown | |

标★的几屏，**并排结构本身就是需求**，不能改成上下堆叠或标签页切换——人要的就是左右对照。

### 关于「待办」这一屏的分工（重要）

判据和校验结论**下沉到各自的阶段屏**，改也只在阶段屏发生。「待办」回答阶段屏答不上的问题：这本书现在总共卡着几件事、坏在哪一层。它是入口，不是编辑面。**不要在这一屏放任何编辑控件**，否则同一条问题会有两个能改的地方。

## 闸门（流程的核心，别做成装饰）

每一屏底部有一条闸门。设计稿里的依赖关系：

```
stage0 剔番外 ──► stage1 切分 ──┬──► stage2（全局设定 + 逐章骨架，两屏都要过）──► stage4 计划 ──┐
                                └──► stage3 文风 ──────────────────────────────────────────────┤
                                                                                                ├──► 挑深度章节 ──► stage5 成稿 ──► stage6 文案 ──► stage7 成书
```

关键点：

- **stage2 和 stage3 并行**：stage1 一确认，两条腿同时发起，互不等待
- **stage2 要两屏都看过才能确认**：闸门上用 chip 显示「✓ 全局设定 / · 原文↔骨架」，缺哪个一目了然
- **stage2 确认即发起 stage4**，不等 stage3
- **stage3 + stage4 都确认**，才允许进 stage5；进之前先挑深度重构章节（默认前 3 章）
- **锁必须是真的**：上游没确认时，下游按钮走禁用态（`opacity 0.4` + `cursor: not-allowed` + 点击无效），文案改成「等 stage6 文案确认」这类说明，并在 chip 里列出缺什么。导航上写着「锁」、屏上却能点，是这次评审揪出来的真实缺陷，别复现。

闸门状态**按 sid 存**（`gate[sid]`），不能是全局的——否则换一本书就自带一排 ✓。同理 `seen` / `deep` / `writing` 都按 sid 存。

### 排版

- 正文：`"PingFang SC","Hiragino Sans GB","Source Han Sans SC","Noto Sans CJK SC","Microsoft YaHei",system-ui,sans-serif`

- 圆角：卡片 11px · 面板内块 9–10px · 按钮与 chip 5–7px · 小标签 4px

- 间距：屏 padding `24–26px 30px`；卡片内 `11–18px`；列表行 `9–13px`；栅格 gap `10 / 14 / 16 / 18px`
- 布局一律 flex/grid + `gap`，不要用 margin 拼间距

## 需要的状态

按 sid 存：`gate`（s0…s7 八个布尔）、`seen`（stage2 两屏是否看过）、`deep`（深度重构章号数组，默认 `[1,2,3]`）、`writing`（是否已开写）。

全局：`screen`、`ordinal`（当前章）、`data`（按 key 存响应）、`loading`、`failed`、`job`（在跑的作业）、`jobLog`、`confirm`（确认框）、`drawerOpen`。

屏内：选中的判据、编辑中的文本、并排/单栏切换、候选选择等。

**一本书同时只跑一个作业**（stage5 的两条除外）。没有取消。
