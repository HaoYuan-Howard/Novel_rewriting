# 15 条踩过的坑

**这份文档只管一件事：那些「改一行就静默失效、而没有任何东西会出声」的形态。**
它不复述需求（那在 `docs/REQUIREMENTS.md`），也不记进度（那在仓根 `README.md`）。

每条的形式是**结论 → 实测代价 → 本仓落点**。
所有数字都是真跑出来的，不是估的；所有落点都由 `tests/test_docs_references.py` 验着存在。

> **为什么值得单独立一份。** 这个项目最贵的一类故障不是崩溃，是**沉默**：
> 一条读起来和有守卫的约束一模一样、而没有任何代码在查；一盏保证会亮的绿灯；
> 一条指向已改名字段的消费方安静地什么也不做。
> 下面 15 条**每一条都对应一次已经发生的损失**。

---

## 一、关于「有没有守卫」这件事

### 1. 一条只写在 prompt 或文档里的约束，它的遵守率是没人在测的

而它读起来与有守卫的那些**一模一样**——同样出现在【硬约束】段里、
同样被别处当成「结构上不可能」引用。要分辨「在守」与「只是在写」，
唯一的办法是去问**哪一段代码在查它**。

**实测代价**：写作节点的三条硬约束（只并相邻拍 / 只并同层拍 / 按写作顺序排）
在盘上**各违反一次，全链没有一层出声**。

**反过来的同一个病也要防**：一条只写在关卡里、**产地从没被告知过**的要求。
两者的共同点是**约束与守卫不在同一个地方**，而后者更亏——模型本可以第一次就做对，
现在要为同一件事付第二次费。实测：`章首漏抓` 是阻断级判据，
而抽取节点的 prompt 不但没说「第一拍要从章首起」，还明写「两条之间允许有空隙」；
三本书 5 处漏抓**全在章首**。

**落点**：`docs/REQUIREMENTS.md` 每条需求的「谁在查」列 + `tests/test_coverage.py` 的双向覆盖率。
⚠ 那一列的价值全在于「说得出是哪段代码在守」——`结构` 与 `载体` 两个取值
**必须在格子里写出代码落点或字段名**，否则它只是「无守卫」的化妆品。

### 2. 一条从不执行的判据，和一条不存在的判据，在报告上长得一样

**「保证会亮的绿灯」不携带信息。** 三种已实测的形态：

| 形态 | 实例 |
|---|---|
| 判据跑在一道确定性修复**之后** | 埋点章判据：落盘前有代码把不合法的埋点章直接裁掉 ⇒ 校验器读到的一定合法 ⇒ 这条 `HARD` 在新鲜产物上**结构性不可能红**，而它照常打印「0 个埋点章，均严格早于其回收章」 |
| 判据的**输入是空的** | `name_leak` 拿一张过滤后为空的名表去扫，0 命中是必然的 |
| 判据**全仓 0 行实现** | `rn_unregistered` 注册着、是 `info`、每本每次打绿灯；更糟的是它挂在一句「本节点唯一能发现漏网的东西」下面，**读的人会以为有两道防线，其实只有一道** |

**处置**：绿灯必须报出自己的**分母**。「拿 37 个专名扫过 21 个文本字段，0 命中」
与「根本没扫」，在旧形状上同形。

**落点**：`contracts/schema/report.py::RuleLine` 的 `scanned` 字段 ·
判据的三态（没有输入 ⇒ `unver`，不是 `ok`）· `docs/REQUIREMENTS.md` 的 `R-2.9` / `R-4.5` / `R-6.7`。

### 3. 每新加一条 HARD 判据，就要有一份会让它红的样本

**「见过它通过」不是证据，「见过它红一次」才是。**

**现状（登记，不是验过了）**：已移植三层合计 **36 条 HARD 盘上 0 反例样本**
（stage4 16 · stage6 5 · stage7 15）。补过的合成样本只走通了 3 条。

⚠ 反例样本还有一个副作用值得知道：**判据吃 `dict` 不吃模型**，才配得出反例。
一旦判据跑在已经过了 Pydantic 模型的对象上，「必填齐全」这类判据**在结构上构造不出反例**
——它必然全绿，于是又回到第 2 条那盏灯。

**落点**：`tests/test_ingest_fixtures.py::test_every_hard_judge_this_layer_added_has_a_violating_sample`。

### 4. 守卫会**静默失去扫描面**，而失去的方式往往很隐蔽

两种已实测的形态，方向相反、危害相同——**报告不再携带信息**：

- **契约改版而关卡没改。** 关卡不会报错，它会继续输出一个看起来正常的结论。
  实测：四条确定性检查在新契约下**三条静默失效、一条全量误报**（结论恒为「需修订」）。
- **参数化只覆盖「还没做的那一半」。** 一条测试只参数化**未移植**的层，
  于是**移植一层反而让覆盖面缩小**，而且正好缩在漏改的那一格上。
  实测：`_dispatch` 在移植第二层的那一刻会安静地跑第一层的实现、
  读第一层的产物，**报出一份属于另一层的报告——退出码 0、格式正确、内容全错**，
  而当时的守卫抓不到。⇒ 守卫要盯**已完成**的那一侧（`runnable_stages() == PORTED_STAGES`）。

**处置**：每条扫描类测试都要配一条**「守卫的守卫」**——断言它真的扫到了东西。
正则失配时上面那些断言会**全绿**，而那正是最坏的情况。

**落点**：`tests/test_docs_references.py::test_the_scan_actually_finds_something`（`ids > 100`）·
`tests/test_coverage.py` 里那句 `assert checked >= 32` · `Q-12`。

## 二、关于「不知道」

### 5. 「不知道」与「没问题」必须可区分

**这是本系统最贵的一条。** 四个落点，一个都不能省：

- 产物新鲜度**三态**（新 / 陈旧 / **不知道**）——指纹缺失记作「不知道」不是「匹配」
- 结论严重度**四级**——「查不了」独立一级，既不是通过也不是失败
- 校验徽章**三态**——「通过 + N 项未验证」渲染成**琥珀而不是绿**
- 作业状态含「不知道」——服务重启后「运行中」一律改判「不知道」，不是「成功」

**实测代价**：某次 23 章成稿与任何一版上下文都配不上（匹配 1/23），
而产出它的那份上游已被覆盖，**配对关系永久丢失**——**而界面当时全绿**。

**同一个形状的第二种表现**：**「跑过且无损」与「从没跑过」在盘上同形**。
恒等基线整个输出只有 `print` + 返回码 ⇒ 跑完就把结论扔掉了 ⇒ 产物里一个键都没有。
⇒ **结论必须落进产物**，「没跑过时报『没跑过』」也是一行输出，不是不输出这一行。

⚠ 别把「新鲜度今天几乎恒为 `unknown`」顺手兜成 `fresh`——
**「没声明读了什么」不是「读的东西没变」**。那正是这一格要防的事。

**落点**：`docs/REQUIREMENTS.md` 的 `Q-2` · `contracts/invariants.py` 的
`FRESHNESS` / `SEVERITY` / `JOB_STATE` / `FRESHNESS_REASON`。

## 三、关于契约与字段

### 6. 「盘上 3/3」不等于「必填非空」，而且样本再多也补不出没发生过的分支

**两条实测，方向是递进的**：

1. `platform` 在盘上 3 本全是 `'FQ'`，看起来像必填非空字符串——
   而**全语料 163 本里有 120 本它是 `null`**。只按盘上定 schema，
   会定出一个**在 74% 的语料上崩掉**的契约。
2. 扩到 163 本修好了 `platform`，但 `source_encoding` 仍然只有 `utf-8`（候选集有五个）。
   **那种字段的取值面只能从代码来。**

⇒ 凡是「盘上零样本」或「盘上取值面明显偏窄」的字段，都要去**全语料**或**代码**再确认一次。

⚠ **有「人修完再落盘」这条路的层，归档目录必须一起反推**——正式产物是**修完之后**的状态，
它会把「修之前才出现的取值」整个抹掉。实测：某字段在 3 份正式产物上是**单值**（19/19），
而 8 份归档里有 **35 条**另一个值。

**落点**：`docs/schema/_README.md` 的「证据」列四取值 · `tools/derive_schema.py`。

### 7. 删字段之前的三问，顺序不能颠倒

| 顺序 | 问题 | 是 ⇒ 怎么办 |
|---|---|---|
| ① | **它恒等于一个常量吗？** | **删字段**，常量回到唯一落点。不是「给它一个类型」，也不是「给它一条判据」 |
| ② | **能 0 成本现算吗？** | **别落盘**。存一份就是抄第二份，而两份同源数据不一致时**没人知道该信谁** |
| ③ | **该归判据还是归载体？** | **按失败成本划，不是按「类型表达得了吗」划** |

第 ③ 问展开：**载体拒收 ⇒ 整份响应作废 ⇒ 再花一次钱**；
**判据拦下 ⇒ 问题稿留一份 + 人手改一行 + 0 成本提升 ⇒ 不花钱**。
⇒ 模型写的、人手改一个数就能救的留判据；跨产物不变量只能是判据。

**实测代价**：某个字段被**连追三轮才判对**，三轮都是判宽了——
① 先给它的记账分两栏 + 补出口（而那 17 条记账 **17/17 全是「本来是空的」**，
那是**初始化**不是改写）· ② 再把它的取值面判据归成「代码的后置条件，留着」
（而单字段取值面归载体）· ③ 最后仍留着字段，理由是「它是预算带的键」
——**循环论证**：一个只有一个合法值的「键」是常量查表。

⇒ 还有一个**先于这三问**的问句：**「消费方读的是这个字段，还是它恒等于的那个常量？」**

⚠ 与 ① 配套的一条：**不是每一次「落盘前写入」都值得记账。**
判准是**那个位置本来有没有东西**——有，才叫改写（原值被销毁 ⇒ 记账 + 判据断言计数）；
没有，那叫**初始化**，记一份「本来是空的」只会制造恒定的噪声。

**落点**：`contracts/invariants.py`（常量的唯一落点）· `docs/REQUIREMENTS.md` 的 `Q-1` 那个反面框。

### 8. 零消费审计有四类假阴，照着 grep 结果删字段会造成真损失

| 假阴 | 为什么 grep 看不见 |
|---|---|
| 整份 dict **迭代**下发 | 键名从不字面出现 |
| 整份 dict **复制**下发 | 同上 |
| 模型写的**决策** vs 代码解析的**结果** | 两边名字不同 |
| **工具本身用错了** | 在错的目录下跑的 grep，报「0 读者」 |

**实测代价**：`voice` 八维初次 grep **全部报「0 下游」**——删了等于把写手的整个声音底座删掉。

**处置**：字段名 grep 全部下游模块 + **逐个人工核实**；
报「0 读者」之前**先确认那次搜索真的搜过那个目录**。
⚠ 而且要**先问「谁在读」，再问「读它干什么」**——只问第一问会留下一个
「唯一的读者是把一个内部数字 id 插进 prompt」的字段。

## 四、关于漂移

### 9. 单一落点：prompt 里那一份必须是**插值**来的，不许手抄

一个枚举 / 词表 / 区间 / 判定，全系统只能有一份定义。

**实测漂过两次**：写法词表在 prompt 里手抄了一个子集（**15 个词只提了 2 个**，
而且写的是「象征/强化感官」而真词表是「意象/感官」）· 另一处**漏了整整一档**篇幅带。
**模型按 A 算、校验按 B 判，谁也不会出声。**

**配套的两条**：

- 模板引擎的选型判据只有一条：**占位符缺值时必须抛异常**。
  缺值渲染成空串会静默产出一个带窟窿的 prompt，与「显式终态」正相反。
- 常量表**自动并进渲染**之后，「手抄一个子集」在结构上做不到；
  而调用点传同名参数要**当场拒**——静默覆盖比手抄更难发现，它连 diff 都看不出来。

**落点**：`contracts/invariants.py`（唯一落点）· `novel/llm/prompts.py::fill`。

### 10. 「模板逐字」还不够，**渲染出来的那一段**也要逐字

**实测**：某层的 system 模板确实与原型**逐字节相同**，
而从原型搬进常量表的**三句说明**被**转述**了一遍，渲染结果短了 **48 字**
——丢掉的正是那一层**唯一还禁的东西**（一条硬约束）。

**只钉模板的测试抓不到它**：占位符两侧一个字节都没变。

⇒ 钉的必须是**发出去的字节**。已移植四层各配一条 `..._is_byte_for_byte_too`。

⚠ 同一形状的第三种：**同一份数据在下发面该严、在检测器该宽，两处的正确方向相反。**
修探针的时候别顺手把「原文有据」那一侧也改了。

### 11. 文档里的引用会悬空，而且**不会报错**

读的人会去找一个不存在的文件、或去查一条不存在的需求，**然后按自己的猜测把它读通**。
三种已实测的形态：

| 形态 | 实例 |
|---|---|
| 指向**改名过的文件** | 某份契约文档指着「tests/fixtures_stage1.py」，而盘上叫 `tests/fixtures_ingest.py` |
| 指向**拆分过的编号** | 「R-0.3」拆成 `R-0.3a` / `R-0.3b` 之后，还有一处引用留在旧编号上 |
| 指向**行号** | 三处代码注释写着「REQUIREMENTS.md:793」，而那一行早就不是它们说的那条需求了——**行号一定会漂**，而漂了不会有任何东西出声 |

**处置**：引用写成 `路径::名字` 或稳定锚，**别写行号**；并配一条会红的测试。

**落点**：`tests/test_docs_references.py`（扫 `README.md` / `docs/REQUIREMENTS.md` /
`docs/LESSONS.md` / `docs/schema/*.md`，查编号存在 + 仓内路径存在）。

⚠ 上表三个实例**刻意不用反引号**——它们是「已经失效的名字」，
加了反引号就会被那条守卫当成真引用而判红。**举例与引用必须在形态上分得开**，
这与 `contracts/requirements.py` 里「定义与引用靠行首形态区分」是同一条纪律。
〔本条上线的第一次运行就抓到了这两处，形态与它自己描述的一模一样。〕

## 五、关于判断

### 12. 在没有 ground truth 之前，补一条判据不是「更安全」，可能是**更危险**

**两具尸体在案**：

- 一道在抽象层做语义判定的护栏，**自己成了发明源**——整节退役。
- 把「闭卷 2.4% / 开卷 96.8%」两个**差 40 倍**的量放进一条线里，
  那条线无论定在哪，**都会对其中一条臂说错话**。

⇒ 处置不是「关掉」，是把**「不查」写成明文**：条目照旧留在无守卫清单里，
因为**「没报违规」与「根本没在查」必须能区分**。
报告里要一直写着**「探针报 0 条 ≠ 约束生效」**。

⚠ 相关的一条：**判据的判别力是（判据 × 书）的属性，不是判据的属性。**
恒等基线在每本书上判死的是**不同**的集合；三本书的干净集**交集只剩一条**。
别把某本书上「这条判据有用」外推成判据的属性。

**落点**：`docs/REQUIREMENTS.md` 的 `B-01` / `B-03` / `B-19`~`B-22`。

### 13. 名字先于证据定下来，后来读报告的人就按名字去解释数字

**探针的名字要等标定完再起。**

**实测代价**：

- 一个叫「幻觉探针」的东西真跑出来幻觉 **0 例**，它抓到的是**另外两件事**
  ——都是真问题，都不在它的名字上。
- 某条判据的取值面实际取的是「姓氏映射的值」（实测取到 `东`，**12 次**），
  而报告里那一列写着「新姓字」。
- 一句对实测现象的**误读**（把「同一个角色的第二种写法」写成「她的家人」）
  被**抄进五个地方，其中两处每次都印给人看**。

⇒ 名字/描述先于证据定下来，读的人就按这个名字去解释数字，**而数字不会反驳它**。

### 14. 「照抄一条理由」比照抄一段代码更危险

代码抄错了多半会报错；**理由抄错了不会**。

**实测**：某层对一份上游走裸读，理由抄的是另一层那条
（「来源账的键只取两级，反查拼不出路径」）——**而那条理由在这里不成立**，
那份上游本来就是两级路径。照抄的结果是**本层的上游边少了一条，而没人出声**。
更糟的是：真正要防的那件事（整份指纹一变就把本层判成陈旧），
**正是字段级投影要解的问题**——理由抄错还顺手放弃了正确的解法。

⇒ 移植时**逐条重新论证**每一条理由在新上下文里成不成立，别按相似度复用。

### 15. **产生面删干净，判定面退役而不删**——两者反过来都会出事

**⚠ 这一条最容易被记成一句笼统的「退役而不删」，而那是错的。**
本仓同一时期做过方向完全相反的两件事，两件都是对的：

| 面 | 对象 | 处置 | 实际规模 |
|---|---|---|---|
| **产生面** | 契约字段 · prompt 里的指令 · 常量的值 | **彻底删** | `tests/corpus.py::CUT` **71 个字段**，覆盖 12 种产物 |
| **判定面 / 证据面** | 判据 · 描述与结论 · 坏数据 | **退役 + 标注** | `contracts/rules.py::RetiredRule` **14 条**，留在表里 |

**最干净的一个实例是同一个特性的两半**：字段 `op` 恒等于一个常量 ⇒ **整个删掉**
（常量回 `contracts/invariants.py`）；而查它的判据 `op_enum` ⇒ **进退役表**。

**为什么方向相反——判准只有一句话：**

> **删掉一个字段，报告上什么都不会少；
> 删掉一条判据，报告上会少一行——而少掉的恰好是「这一类没在查」。**

展开：

- **字段删得掉，是因为删除本身就是强制的。** 载体一律 `extra='forbid'`（见附）⇒
  谁再产出这个字段，那份响应**当场被拒**。所以删字段不是「希望它不再出现」，
  是**结构上回不来**。⚠ 「留着读存量旧产物」这个理由已被实测否掉：
  新契约裁掉一批字段之后，原型产的 **3/3 本产物全部加载失败**——没有东西读得进存量。
- **判据删不掉，是因为判据【就是】报告的一行。** 删掉它，
  「这一类没在查」与「查了没问题」在界面上**长得一模一样**。
  退役之后报告里换成常驻一行「这一类没在查」——**信息量是增加的**。
  实测反面：某条判据**全仓 0 行实现**却注册着，每本每次打绿灯，
  而它挂在一句「本节点唯一能发现漏网的东西」下面 ⇒
  **读的人以为有两道防线，其实只有一道。**
- **坏数据同理**：把修不好的数据删掉，这一次会响亮报错，**下一次跑就没得报了**
  ——一次性告警会退化成静默降级。
- **描述与结论同理**：一份没有标记的退役描述会继续**以现役身份被引用**。
  实测：一份外部审阅照着一条**被推翻的旧判据**得出结论，并据此推了一条**错误的处方**。

**⚠ 标注必须是可执行的事实，不是一句注释**：退役的脚本留在盘上但入口即显式终态退出；
退役的判据进 `RetiredRule`，`why` 里写清「为什么撤」与「**什么条件下可以复活**」。
`Registry` 另有一条：**一个 id 不许同时又活着又退役**——
报告会既列判定又列「已退役」，而人只会信其中一行。

**⚠ 有一类东西看起来像字段、但归判定面：一个被删字段的【取值面常量】。**
`op` 删了，而 `OPS` / `OP_BAND` 留着并标注成「**解锁时的落点，不是读存量的取值面**」
——因为把那个产品决定改回去的那天，要放回来的不止字段本身，
还有跟着它一起复活的一条判据和一条静默分支。

**⚠ 同一条纪律的第二种用法：改一格不能只是改，还必须说清为什么。**
**只换一句话而不标注，读的人会以为那个坑还在，或者以为规则被偷偷放宽了。**
已按它办过两次（把一条已被 `novel/run.py::RunContext` 消灭的理由标成退役 ·
把「绝不落盘」收窄成「绝不落产物盘」）。

**落点**：`docs/REQUIREMENTS.md` 的 `Q-8` · `contracts/rules.py::Registry` 的
`retire` 与 `retired_of_stage` · `tests/corpus.py::CUT`（那 71 个字段的清单）。

## 附：本仓自己的两条载体级纪律

**Pydantic v2 有两条默认行为与上面这些纪律相反，必须显式改掉**：

| 默认 | 为什么与本项目相反 |
|---|---|
| `extra` 默认是 `ignore`——**未知字段被静默丢弃** | 上游多写了一个字段、或字段名拼错，校验照常通过而那个值消失了。**一律 `extra='forbid'`** |
| 给可选字段配默认值 | 会让「没有这个字段」和「字段是 `null`」混掉——那是第 5 条那个三态问题的重现。需要区分时用 `Field(...)` 强制必填，或**显式建模成三态** |

⚠ 还有一条同形的：`model_dump(exclude_none=True)` 的 `exclude_none` 是**全局的**，
它会同时剥掉「三态字段的 `None`」（意思是「这个键不该在」）
与「可空字段的 `None`」（意思是「键在，值就是不知道」）——
**两者长得一样、语义相反**，一个全局开关同时管两种，必然把其中一种搞错。
实测代价：**落下去的产物读不回来**，而它是靠「落盘前先证明读得回来」这道往返闸抓住的。
