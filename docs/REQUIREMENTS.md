# 小说重构系统 — 需求规格

**立于 2026-08-10（重写版）。** 用于正式开发：先按它定契约，再搭骨架，再移植。

---

## 这份文档怎么读

### 它是自足的

**全文 0 处外部引用。** 不引 `CONTRACTS.md`、不引 `PROTOTYPE_FINDINGS.md`、不引任何 F 编号、
不引任何已归档的交接件。需要的事实一律**就地写出来**，包括实测数字。

理由：这份文档要活得比它的来源久。一条写着「详见某文档某节」的需求，在那份文档被归档、
改版或删除之后，就变成了一条**读起来完整、实际上空心**的需求——而没有任何东西会为此报错。

代价是它会重复一些别处也有的话。这是有意的。

### 核心机制：每条需求带「谁在查」

需求表的最后一列是 **「谁在查」**，取值只有五种：

| 取值 | 含义 |
|---|---|
| **`HARD`** | 有确定性代码在查，违反即阻断（不落盘 / 非零退出 / 显式终态） |
| **`INFO`** | 有确定性代码在查，违反只报不拦 |
| **`闸门`** | 落盘之前跑的校验，不通过就不覆盖现役产物 |
| **`人`** | 按设计就由人判，没有也不该有确定性判据 |
| **`无守卫 → B-xx`** | **这条要求只写在 prompt 或文档里，没有任何代码在查它** |

第五种是这份文档存在的主要理由。

> **一条只写在 prompt 里的约束，它的遵守率是没人在测的。**
> 而它读起来与有守卫的那些**一模一样**——同样出现在【硬约束】段里、同样被别处当成
> 「结构上不可能」引用。要分辨「在守」与「只是在写」，唯一的办法是去问**哪一段代码在查它**。
>
> 已实测的代价：写作节点的三条硬约束（只并相邻拍 / 只并同层拍 / 按写作顺序排）
> 在盘上**各违反一次，全链没有一层出声**。

反过来的同一个病也要防：**一条只写在关卡里、产地从没被告知过的要求**。
两者的共同点是**约束与守卫不在同一个地方**，而后者更亏——模型本可以第一次就做对，
现在要为同一件事付第二次费。已实测：`章首漏抓` 是阻断级判据，而抽取节点的 prompt
不但没说「第一拍要从章首起」，还明写「两条之间允许有空隙」；三本书 5 处漏抓**全在章首**。

⇒ **验收本文档的方法是双向的**：
① 每条 `无守卫` 都要有处置（补判据 / 收走自由度 / 明知不查但写明）；
② 每条现役守卫都要能追到本文档里的一条需求（见最后一节的反向覆盖率）。

### 编号

- **`R-1` ~ `R-12`** — 功能需求，按处理阶段编排（**1:1 重建**：形态可以变，能力与守卫不许缩水）
- **`R-13` ~ `R-14`** — **相对原型新增的两项能力**（批量队列 · 断点续跑），用户裁决
- **`Q-1` ~ `Q-12`** — 工程约束，跨阶段成立
- **`B-01` ~ `B-22`** — 无守卫清单 = **关卡层的施工清单**

**`B-01` 与 `B-03` 需要裁决才能往下定契约**，见「待裁决」一节。

## 一、系统是什么

把一本中文网络小说的原作，经 7 个阶段处理成一本**新书**：情节骨架保留，文字全部重写，
人名全部替换，最终交付一个 `book.txt`。

**部署形态**：单人、本机、桌面浏览器。服务只绑 `127.0.0.1`。无登录、无多用户、无权限。

**成本模型**：每个阶段的核心是一次或多次 LLM 调用，**花真钱**。
确定性部分（分章、锚点回取、替换、组装、全部校验器）不花钱。
一次全链约 40~50 次调用；一本 8 章的小书跑完在数十分钟量级。

**最高风险不是「出不了书」，是「错误的剧情被静默接受」。**
LLM 的错误不会崩溃：它会造一个读起来毫无破绽的假事实、会在第 1 章说出第 14 章才揭晓的秘密、
会把一段该保留的关键台词整段丢掉而成稿依然通顺。
系统的全部设计张力都在这里——**这决定了本文档里绝大多数的 `Q-` 条目**。

### 处理链

```
stage0  非正文剔除 + 人工审阅闸门              0 成本，无 LLM，**必须人批准才能往下走**
stage1  摄入 + 分章                          0 成本，无 LLM
stage2  全书级抽取（人物/关系/规则/秘密/弧线）  1 次调用
        逐章抽取（事件拍 + 必须保真的原文点）    分批调用
stage3  文风画像（描述 + 代码实测的形态档位）    1~2 次调用
stage4  重构计划（只存决策，一个字内容都不经它） 1 次调用
        写作上下文（确定性组装，写作的唯一输入） 0 成本
stage5  逐章写作，两条臂：闭卷重构 / 开卷改写    逐章 1 次调用
        全书验收（判成品）+ 修订式反哺           0 成本 / 逐章调用
stage6  开篇文案：一次调用产三候选，人定稿       1 次调用
stage7  人名替换：一次调用产新人物表（只产决策）  1 次调用
        替换与成书组装                          0 成本
```

**章的唯一键一律是阅读序整数 `chapter_ordinal`。输出章号恒等于源章号**——
不合并、不重排、不删、不拆分，四条是同一个恒等式的分解。

> ### ✅ 阶段命名已裁决（2026-08-10）：**两层，`n1..n9` 整套退役**
>
> **病根：两个正交的概念被压成了一个轴。**
> `stage` 是产物目录 + schema 层 + 需求节的归属；`node` 是可跑的作业单元。两者不是 1:1——
> stage2 有两个节点、stage5 有写作与验收两相、stage4 的上下文组装是 0 成本节点、
> stage0 有三个人参与的动作。
> 原型的 `n1`~`n9` 是**节点轴用 stage 编号命名**的产物，于是它必然坏掉
> （`05_samples/enums.json` 的 `actions[36]` / `job_kinds[12]`，真实抓包）：
>
> | 原型作业 key | 病 |
> |---|---|
> | `n1_partition` | label 写着「stage1 摄入+分章」——**「摄入」已经搬到 stage0 了**。手写的 label 会说谎 |
> | `n5_write` / `n6_write` / `stage5_review` | **两个 n 号一个 stage**，且第三个是脚本名泄漏 |
> | `n8_hook` · `n9_rename` | **没有 `n7`**，编号是断的 |
> | — | **stage0 一个 action 都没有** |
>
> **裁决**：
> 1. **`stage0`~`stage7` 只做产物层**（目录 / schema / Pydantic 模块 / `Rule.stage` /
>    `PORTED_STAGES` / 校验报告路由），**永不用作作业 id**。
> 2. **作业 id = `<stage>.<动词>`**，唯一落点 `contracts/invariants.py` 的 `NODES`。
>    用动词不用新编号：**编号会过期，动词不会**——`n` 那套坏掉正是因为把序数编进了标识符。
>    label 从 `NODES` 派生，不再手写。stage0 的三个作业（剔除 / 批准 `R-0.3a` / 编辑 `R-0.4`）
>    随之补齐。
> 3. **写作两条臂是参数不是两个节点**：`stage5.write --mode deep|shallow`
>    （两臂只差 (system prompt, 给不给源章原文)，产物形状逐字节相同，判据表只有一张，
>    且 `R-7` 一节同时管两臂）。⇒ `R-11.10` 的互斥键是 `(sid, node, mode)`。
> 4. **没有 `check` 节点**，复检一律是 `--check-only` flag；作业 kind = `(node, flags)` 二元组。
>    原型两头都有（`check_partition` 是独立脚本、`n3_style --check-only` 是 flag），
>    正是 `Q-3` 点名的「三个节点行为不一致」。
> 5. `/api/enums` 从 `invariants` 整份生成，必须是现有 `enums.json` 的**超集**——
>    `tests/test_invariants.py::test_enum_matches_live_backend` **正在逐值比对**其中 6 个，
>    前端也是运行时取（不许硬编码）。`job_kinds`/`actions` 的**形状不变，只有 `kind` 的取值变**。
>
> **⚠ 这套命名同时修好了一条隐形的测试 bug**：R 节的编排轴一直就是**节点**
> （`R-2`/`R-3` 是 stage2 的两个、`R-5`/`R-6` 是 stage4 的、`R-7`/`R-8` 是 stage5 的两相），
> 而正向覆盖率曾用 `'R-' + stage.removeprefix('stage')` 去找需求节——
> 那个式子**只在 stage0/stage1 上对**，`stage3` 拿到的是 stage2 逐章抽取的需求。
> `PORTED_STAGES` 为空时它整个藏在 `pytest.skip` 后面。
> ⇒ 现在 `STAGE_SECTIONS` 从 `NODES` 派生，且 `tests/test_coverage.py` 有一条测试专盯
> 「有人把它改回那个式子」。

## 二、功能需求 R-0 ~ R-12

### R-0 · 非正文剔除与人工审阅（stage0）　★ 2026-08-10 新增

把原始 txt 里的**非正文体**（番外/后记/尾声/作者有话说）删掉，交人审阅，
**批准之后才允许进 stage1**。产物是「一本只有文案和正文的小说」。**这一层不调 LLM。**

> #### 为什么值得单独一层，而不是留在 stage1 里
>
> **① 它把破坏性操作变成了可审阅的操作。** 剔除的正确性没有任何结构判据能查
> （`R-1.8` / `B-20`：番外体已丢弃、盘上不留副本）。留在 stage1 里，判据错一次就静默吃掉半本书；
> 提到 stage0 并配审阅闸门之后，**stage1 里的同一套判据降级成一道断言**——
> 它不再切任何东西，只在「已批准的文本里居然还认出非正文标记」时报错。
> ⇒ 判据出错的代价从「吃掉半本书」变成「报一个假警」。**方向反过来了。**
>
> **② 闸门必须在 stage2 之前。** stage2 是第一个花钱的层。
> 事后审阅（S-03）发现问题时钱已经花了。
>
> **③ 番外混进正文不是「有点脏」，是会污染文风测量。**（用户裁决时给的理由）
> 某些番外**换视角、换人称**。它留在正文里会一路往下污染：
> stage2 抽出番外里的人物与关系 · **stage3 量到的是混合人称**（`R-4.1` 的形态数字、
> `GRAMMATICAL_PERSON`）· stage5 按被污染的声音写。
> `R-4.2` 已经规定「正文与开篇文案段分开测、互不污染」——**番外是第三个污染源，
> 此前它在需求里没有名字。**
>
> **④ 模式匹配补不掉的那部分，只能靠人直接编辑。** 实测确认过：番外若用纯数字章节标记写
> （`9` 换行、内容是番外），它和正常章节**长得一模一样**，没有任何结构信号
> （「章号回退」信号实测 0/3 精确率，见 `R-1.7` 的加词流程一节）。

| # | 要求 | 谁在查 |
|---|---|---|
| R-0.1 | 自动剔除用的是 `R-1.7` 的同一套判据与同一张 `NONBODY_KINDS`——**只有一份** | `HARD` |
| R-0.2 | 剔除逐段记账：标记行、行号、码点区间、字数、首尾预览。**番外体不进产物目录** | `HARD` |
| R-0.3a | **人工批准这个动作本身**——「这一段到底是不是番外」没有结构不变量可查，只能人看 | **`人`**，见 `B-20` |
| R-0.3b | **未批准的书，stage1 必须拒绝启动**；队列要明确说出在等谁（同 `R-13.5`） | `HARD` |
| R-0.4 | 人可以**直接编辑**待剔除的范围，也可以直接改正文——判据漏掉的那类只能这么修 | **`人`** |
| R-0.5 | 人工编辑记 `origin=human`，上一版归档进 `stage0/_rounds/`（同 stage5 的 `--apply-edit`） | `HARD` |

| R-0.7 | 剔除的**正确性**——「这一段到底是不是番外」 | **`人`**，见 `B-20` |
| R-0.8 | 重跑 stage0 **不许静默覆盖人工编辑**；要覆盖必须显式（同 `REVALIDATE_ONLY_NEW_ERRORS` 的精神） | `HARD` |

| R-0.12 | 归一化**只做两件事**：去 BOM、换行统一为 `\n`。**不做 NFC/NFKC、不 strip 行尾**。〔从 `R-1.2` 移交〕 | `HARD` |
| R-0.13 | 目录寻址只有一把尺子：文件名结尾有 `_<数字>` 就用它当 id，否则用书名本身当键；写盘前断言目录名能被同一把尺子解析回来且是不动点。〔从 `R-1.10` 移交〕 | `HARD` |

> #### 为什么摄入的这四条（`R-0.11` ~ `R-0.14`）也跟着搬
>
> **谁读原始 txt，谁就负责解码、归一化、寻址和「同目录不同正文」。**
> 加了 stage0 之后读原始 txt 的是它，stage1 的输入变成 `stage0/clean_text.txt`——
> 一份**恒 utf-8 / 恒 `\n`** 的文件，没有编码可猜、没有 BOM 可去。
> 把这几条留在 stage1，就是四条永远走不到的分支：
> `source_encoding` 恒 `utf-8`、BOM 分支恒不触发。
> ⚠ 这正是本项目最忌讳的形态——**一条从不执行的判据，和一条不存在的判据，在报告上长得一样。**

> #### ⚠ `R-0.6` 为什么必须是两个指纹
>
> 加了 stage0 之后，**stage1 的输入不再是原始 txt**。
> 只记一个指纹，「有人换过原始小说」和「有人改过 stage0 的剔除结果」就分不开了——
> 而这两件事的处置完全相反：前者要从头重跑，后者是**人有意为之、必须保住**。
> `R-1.3` / `R-1.11` 那两条 `HARD` 判的是前者，`R-0.5` 的归档管的是后者。

> #### ⚠ 已知代价，登记在案
>
> **① 人工编辑打破 0 成本复算（`Q-3`）。** 人一改，stage0 就不再是确定性的。
> 模式照搬 stage5/stage6 的 `--apply-edit` / `origin=human` / `_rounds/`，但影响面大得多：
> stage5 的编辑只影响那一章，**stage0 的编辑是全链输入，一改下游七层全部陈旧**。
> 那是真回归不是假回归，但界面要让人预期到。
>
> **② 闸门的吞吐成本。** 实测 163 本里只有 **27 本**有能被判据检出的非正文，**136 本是干净的**。
> 「全量审阅」能覆盖盲区但要 163 次人工；「只审检出的」吞吐高，但**盲区①（检出数为 0）
> 永远不会进队列**——而防它正是加这一层的理由之一。
> ⇒ **覆盖策略待定**（2026-08-10 裁决：先把机制和模块做出来，跑通几本，
> 之后按真实上传的书来定）。**这是登记的待定项，不是默认全量。**

> 下给模型的规则里写得清清楚楚，**三条 `HARD` 在守，而需求 0 处落点**。
>
> **`R-10.15` 值得单记**：它是全链**唯一**把「定向返工只许改判据点名的部分」
> （`R-4.10`）做成**数据结构**的地方——别处都只是 prompt 里的一句叮嘱。移植时照搬这个形状。

> **R-10.10 的实测**：某本成稿里有一个字面（原文 2 次）不在上游人物表里，
> 只按人物表替换就会原样留着——**除残留探针外全链没有第二处能发现它。**
> 别把「残留 0 条」读成「人名都换干净了」。
>
> ⚠ **2026-08-10 复算，改了这条注的措辞**：原文写的是「**她**改了名而**她的家人**原样留着，
> 凭空多出一个姓氏孤儿」。逐条核对原文之后，三处都不成立——那个角色是**他**；
> 漏掉的那个字面**不是家人，就是同一个人**（原作自己把名字写成了两种形，人物表只收了其中一种）；
> 人物表漏收的因此**不是一个角色，是同一个角色的第二种写法**。
> **结论不变，探针仍是必需件**，但漏网要分成两个子类——**「漏收一个人」补整个角色，
> 「原作异写/错字」只补一条指向同一个新名的映射**，两者的修法不一样。
> 〔判据 32：名字/描述先于证据定下来，后来读报告的人就按它去解释数字。
> 这句误读曾被抄进五个地方，其中两处每次都印给人看。〕

> **残留探针的覆盖率阈值只有分布支持，且它会反向**：比率 =（总数−残留）/总数，
> 当漏网形就是该姓的**主用法**时，分母里装的主要就是分子，比率自我压低——
> 实测两个姓分别是 40% / 60%（都落在「基本是普通词」那一侧）而**两个都是真漏网**。
> **两个信号打架时以结构信号为准**（它不受这个反馈回路影响，实测 6/6 全真）。

> **一族已知同形的残留**：`X家` / `X府` / 职务式称呼，**四本同形**（`陆家`×3 · 30 处 ·
> `刘家`×6 + 手帕上绣的「柳」字 · `沈总`/`周秘书`）。根因是人物表的称谓收的是「人的叫法」，
> 不收「门第」形，也常漏收职务式称呼。补充映射后覆盖率回到 100%。

> ### R-11.3 的理由改写（2026-08-11 · 骨架 B1）
>
> `Q-8`：**退役的东西不能只是不删，还必须带标注。**
> **只换一句话而不标注，将来读的人会以为那个坑还在**（同 `R-14.6` 记的那个形态）。
>
> 原型走子进程有**五条**理由，骨架落地那一刻消灭了其中**三条**：
>
> | 原理由 | 现状 | 落点 |
> |---|---|---|
> | 来源账是**进程级**的、键不含书名 ⇒ 同一进程里读过 A 书再写 B 书会落一条**看不出来的假匹配边** | **已消灭** | 来源账改成 run 级的实例字段（一本书 · 一个节点 · 一次跑 = 一个 `RunContext`），串扰**在结构上不存在**；由 `tests/test_store.py` 钉死 |

> · **CPU 密集会阻塞。** 重合度 / LCS 是秒级的纯 Python，跑在服务进程里会把界面卡死，
>   而这一层的主体动作恰恰是「把两份东西并排放在一起让人看」。
> · **`R-11.8` 要求展示与执行共用同一个 argv 构造函数**：摊开显示的那条命令必须**真的能粘进终端跑**。
>   ⇒ CLI 必须存在、且与服务端执行的是同一件事。进程内直调会让这两者慢慢分家，
>   而分家之后界面上显示的命令就成了一句**看起来精确的假话**。
> · **一个节点崩了不许带走整个队列。** 本项目是批量服务（一次跑一批书），
>   而 OOM / 段错误这类失败**在进程内拦不住**。

> 不是「子进程用不着退出码」。子进程的退出码仍然是编排层判成败的依据（`R-12.3`）。

> ### R-11.3 的范围收窄（2026-08-11 · 骨架 D）：「绝不落盘」→「绝不落**产物**盘」
>
> `Q-8` 的同一条纪律：**只换一句话而不标注，读的人会以为这条规则被偷偷放宽了。**
>
> **收窄的理由是一句话，而且它没有第二种解法**：
> **「子进程被 OOM 杀掉了」这条记录只有父进程写得出来**——
> 子进程写不了自己的死讯，而退出码正是编排层判成败的依据（`R-12.3`）。
> 让子进程自己记，`spawn` 失败与被 kill 这两种情况**盘上零痕迹**，
> 而 SSE 要读的那份日志在子进程起来之前根本不存在。
>
> ⇒ 服务进程写、且**只写**这两处，它们都**不是产物**（不进来源账、不进 `_provenance`、
> `contracts/schema/__init__.py::ARTIFACTS` 里没有它们）：
>
> | 落点 | 形态 | 为什么这样存 |
> |---|---|---|
> | `Output/_service/jobs.jsonl` | **append-only 事件流** | 与成本账同一条理由：**永不需要读-改-写** ⇒ 并发安全、被 kill 不损坏、可 grep。⚠ 原型每次状态变化都 `os.replace` 整份 `<job_id>.json`，并**为此写了一段重试**——`PermissionError: [WinError 5]`，因为服务一边写一边被 SSE 轮询读，**实测在测试里必现** |
> | `Output/_service/logs/<job_id>.log` | 按字节追加 | 中文一个字跨 3 字节，按字节切块读时**只在读的一侧解码**，宁可少读几个字节也不把一个字劈成两半（那个 `�` 不可逆） |
>
> **这条收窄是有守卫的**，不是一句口头放行：`tests/test_layering.py` 的写口白名单
> 为 `novel/orchestrator/jobs.py` 单开一条并写明理由，
> 而 `test_the_service_only_writes_under_service_dir` 断言它**没碰 `_service/` 以外的任何东西**。
>
> ⚠ **改判也是追加**（`reconcile` 写一条 `reconciled`），不是回去改 `started` 那一行——
> 回去改就毁掉了 append-only 的全部意义，而那正是「被 kill 不损坏」这条性质的来源。

> **R-11.9 为什么不照抄逐段 diff**：那个比的是同一章的两轮稿子，段落大体还是那些段落。
> 这里比的是原文与重写，实测配对率**开卷 44~82% / 闭卷只有 8~25%**——
> 闭卷写手没见过原文，句子没有字面关系。而**逐字原话的锚与臂无关**（闭卷覆盖 50~100%），
> 正好补上塌掉的那一半。实测两本 22 章，带原话的拍 **31/31 与 49/49 两侧全部定位成功**，
> 覆盖 70% / 77% 的拍，**稿内锚点逆序 0**。

> 但反过来那一条更要紧：**把没做的事标成有守卫，比留着「待建」坏得多**——
> 前者会让人以为有一道闸在那儿，而闸后面是空的（那正是本文档第四节警告的形状）。
> ⇒ 做完的那半写落点，没做的那半照旧写「待建」并说清在等什么。

### R-14 · 断点续跑 【**新增能力**，原型没有】

一次跑被打断（人为中止 / 进程死 / 机器重启）之后，能从断点继续，**不重复付费**。

| # | 要求 | 谁在查 |
|---|---|---|
| R-14.1 | 已完成的阶段按**产物存在性 + 来源新鲜度**判定，不靠一份单独的进度文件——进度文件会与盘上的实际产物分家 | **`结构`**（`novel/orchestrator/state.py::overview`；配一条 AST 守卫 `test_completeness_never_peeks_at_the_job_records`：那份文件的**代码里**够不到 `_service`） |
| R-14.2 | 逐章类阶段（写作）的续跑粒度是**章**：已落盘的章不重跑 | **`结构`**（`novel/orchestrator/state.py::chapters_done`，**排除 `.INVALID.json`**——`chNN.json` 的存在本身就是「过了落盘闸门」这个语义） |
| R-14.3 | **被打断的跑可以几乎免费续**——已完成的调用命中缓存。这要求缓存键稳定，且**参数不变的「重跑」什么都没跑**这条语义被显式说出来 | **`结构`**（`novel/llm/cache.py::cache_key` 稳定键 + `novel/llm/ledger.py` 的 `calls_made` / `calls_cached` **两个计数器**，B1/B2 已落地） |

| R-14.5 | 中断留下的半成品（写到一半的章 / 空壳响应）**入显式终态并踢出缓存**，不许被当成「已完成」续过去 | **`结构`**（响应侧：`novel/llm/client.py` 的空壳 evict，B2 已落地）+ **待建**（**逐章半成品**那一半要等 stage5 移植——今天 `.INVALID` 不计入已完成已经挡住了一类，写到一半的 `chNN.json` 那一类还没有样本） |
| R-14.6 | 进程被杀时**不保证原子性的地方要列出来**。⚠ 原型里「不做取消」的理由曾写着「落盘非原子，中途 kill 会留下截断的 JSON」，而落盘**早已是原子替换**——结论仍成立（钱已经花了），但它现在只剩一条腿撑着 | **`结构`**（那张表在 `docs/schema/_orchestration.md` §八，**五处**，每处带「崩在中间会留下什么 / 怎么自愈」） |

⚠ **`R-14` 与「不做作业取消」不冲突**：不做取消是因为**调用在途时钱已经花了**；
续跑处理的是**已经被打断之后**怎么办。两件事。

> ### R-14.6 那张表长什么样（2026-08-11 · 骨架 D 建表）
>
> 全文在 `docs/schema/_orchestration.md` §八，这里只记它的**形状与两条结论**：
>
> 五处里 **三处会自愈**（多文件写 / `_rounds/` 归档与新稿之间 / 提升路三步的中间窗口），
> **一处不自愈**——「账本行与产物之间」：**钱花了、产物还没写**。

> 第五处是 D 期新增的，而且**不打算补**：**互斥锁是进程内内存**，

>
> ⚠ 这张表本身就是 `R-14.6` 要的东西。原型那条「不做取消」的理由
> **退役了而没人标注**，只剩一条腿撑着——这张表就是那次标注。

## 三、工程约束 Q-1 ~ Q-12

跨阶段成立。它们不是「最佳实践」，每一条都对应一次已发生的损失。

### Q-1 · 不静默
截断 / 缺章 / 解码失败 / 任何异常一律入**显式终态 + 报警**，绝不悄悄接受、不自动修正。
可疑但不算错的进显式 `warnings[]`，交人工审核。

**记账不是终点，报出来才是。**「落盘前的确定性改写」与「返工/提升的历史」都必须记进产物
（因为改写跑在落盘前，校验器已经不可能再从字段值上看出发生过什么），
而**每一个这样的记账键都必须在校验报告里有一行出口**。三条形式要求：

- **空也要报**，报成 `0 处`，不是不打印这一行——「没改过」与「没在报」必须分得开（`Q-2`）；
- **一行常驻 + 非空才展开**，否则报告变噪声，而噪声会让人不看报告；
- **出口在校验报告，不在 stdout**——stdout 会随会话消失，那不算出口。

> **实测代价**：stage2 的 8 个记账键有 5 个没有任何出口
> （叫法起点被抬了几处、区分词剥掉了什么、人删过哪条秘密、哪几章重生成过、各修了什么），
> stage3 的 3 个**一个都没有**——其中 `gates_skipped` 是「阻断级判据没跑成」这件事的
> **唯一痕迹**。写进文件没人看，与没记过在报告上完全同形。

> ⚠ **反过来的那一面：不是每一次「落盘前写入」都值得记账。**
> 判准是**那个位置本来有没有东西**——有，才叫改写（原值被销毁 ⇒ 记账 + 判据改断言计数）；
> 没有，那叫**初始化**，它的后置条件由代码自己保证，记一份「本来是空的」只会制造恒定的噪声。
> 实测反例：stage4 的「篇幅方式」记了 17 条改写，**17 条全是「本来是 null」**
> （规划节点根本不产这个字段），而那份记账既没有出口、也没有一个 bit 的信息。
> ⇒ **模型越界多写一个字段**这件事该由**响应侧 `extra='forbid'`** 挡，不是由产物侧记账。

> **结构化响应一律 `extra='forbid'`。** 未知字段被静默丢弃正是本条要挡的形态：
> 上游多写了一个字段、或字段名拼错，校验照常通过而那个值消失了。
> 它同时是「模型产出了我们没要的字段」这一类的**唯一守卫**——落盘之后再记账已经晚了一层，
> 而且那时已经花过钱。

### Q-2 · 「不知道」与「没问题」必须可区分
这是本系统最贵的一条。它有四个落点：
- 产物新鲜度**三态**（新 / 陈旧 / **不知道**），指纹缺失记作「不知道」不是「匹配」
- 结论严重度**四级**，其中「查不了」独立成一级，既不是通过也不是失败
- 校验徽章**三态**：「通过 + N 项未验证」渲染成琥珀**而不是绿**
- 作业状态含「不知道」

> **实测代价**：某次 23 章成稿与任何一版上下文都配不上（匹配 1/23），
> 而产出它的那份上游已被覆盖，**配对关系永久丢失**——而界面当时全绿。

### Q-3 · 每一层确定性的部分都必须能 0 成本重算
否则修自己的 bug 要付费。命名体系本身是资产，**唯一落点是 `contracts/invariants.py` 的
`FREE_ENTRIES`**（本节不再抄第二份清单——抄一份就是又一个会分家的落点）。

> **⚠ 这张表 2026-08-11 补过一次，缺口是量出来的不是想出来的。**
> 拿真实抓包（`docs/design_brief/05_samples/enums.json` 的 36 条 `actions`）对了一遍：
> 现役后端真正当 0 成本用的 flag 有 **13 个**，而表里当时只有 **9 个**，交集 8 个。
> ⚠ **漏一个的后果是反的**：`is_paid` 拿这张表当白名单，未知 flag 一律按付费算
> （`Q-10`：不知道要倒向贵的那一边）——于是一个漏登记的 0 成本动作会被画成橙色、
> 弹二次确认，**而它根本不花钱**。表不全 ⇒ 系统在对用户说假话。
>
> 补进来的四个：`--measure-only`（只跑实测**不写盘**，与 `--remeasure` 是两件事）·
> `--migrate`（确定性回取）· `--names-only`（stage4 逐章可用名册）·
> 另有三个**被两层命名取代**、登记进 `SUPERSEDED_FREE_ENTRIES` 并带标注。
>
> ⚠ 其中 `--identity-plan` 是**本条自己的违例实例**：它与 `--identity` 是同一件事，
> 只因为原型里一个脚本干两件事才被迫起了第二个名字。
> **「同一个语义在不同节点上必须叫同一个名字」这句话，原型自己没做到。**

**配套纪律**：重算时只对**本次新引入**的错误入终态——旧违约照报但不挡路，
否则一条不相干的旧问题会把重算这条路永久堵死。

⚠ 原型里这条**三个节点行为不一致**（一个有提升路、一个没有、一个把问题稿双双排除掉，
代码直接叫你重付一次钱）。新骨架**必须一致**。

### Q-4 · 每份产物必须记住自己是从哪份上游来的
`{prompts 指纹, model, code 版本, inputs 指纹, params}`。
**校验器先报来源，再报判定**——对不上时报出来的一堆违规是「拿新尺子量旧布」，
不说破就会被当成一次回归。

⚠ **读上游只有一条路**（那条路记账）。原型里有十几处裸读绕过它，绕过就记不上账。
⚠ **取不到指纹的条目 = 那份上游【已经不在盘上】，要报出来。** 原型的比对函数对这种条目
**静默跳过**——于是一条指向已删文件的边既不报错、也不报「不知道」，
只是安静地当作一条正常的上游边（实测就有一条：0 成本提升路读完问题稿就把它删了）。
⚠ 指纹是**文件级**的：改一个不相干的字段会让整份产物的指纹失配，把一批结论降级成「读数不可用」，
且没有重新挂钩的路。字段级指纹是一次契约改版，值得在新骨架里就做对。

### Q-5 · 先校验后落盘
阻断级错误**不覆盖已有产物**，问题稿单独存一份带 `.INVALID` 标记的文件。
配 0 成本提升路（`--revalidate`）：按**当前**判据重判，合格即提升。

**为什么必须有提升路**：没有它，修一条**判错**的判据要为每一章再付一次费，
而重掷回来的是**另一份稿**，修没修好无从对照。

⚠ **问题稿与被提升的稿【同样要带来源】，并且要记「它是被提升上来的」**（2026-08-10 补）。
原型这条整个漏了：问题稿用裸写绕过了带来源的落盘、提升路又不传来源，
而它的注释还写着「来源信息沿用原稿里那一份」——**实测盘上 1/3 本的计划因此没有任何来源信息**
（用哪个 prompt 产的、哪个模型、照哪份上游、落盘前改写了什么，全部永久丢失），
而**没有一行报告会说出来**。⇒ 这一条同时是 `Q-1`（不静默）与 `Q-4`（来源）的交叉缺口。

### Q-6 · 单一落点
一个枚举 / 词表 / 区间 / 判定，全系统只能有一份定义。
**prompt 里那一份必须是插值来的**，不许手抄。

模板引擎的选型判据只有一条：**占位符缺值时必须抛异常**。
缺值渲染成空串会静默产出一个带窟窿的 prompt，与「显式终态」正相反。

⚠ 已实测的分家：prompt 手抄的写法词表写着「象征/强化感官」而真词表是「意象/感官」、另 8 词一个没提；
另一处漏了整个一档。**模型按 A 算、校验按 B 判，谁也不会出声。**

### Q-7 · 中间层只存决策与引用，内容由确定性代码搬运
**凡是让 LLM 转抄的地方，都会长出一个新的漂移源。** 对原文字节成立，对任何上游产物也成立。

⚠ 已实测：某中间层把上游的事件文本改写成合并散文，106 拍相似度中位 0.84、最低 0.44，
既造事实（「某人身边人」→「某家丫头」）又丢内容（整段具体材料被压没）。

### Q-8 · 退役而不删，且必须带标注
- **不删**是为了区分「没报违规」与「根本没在查」——把修不好的数据删掉，这一次会响亮报错，
  下一次跑就没得报了，一次性告警会退化成静默降级
- **必须标注**是因为一份没有标记的退役描述会继续**以现役身份被引用**。
  已实测：一份外部审阅照着一条被推翻的旧判据得出结论，并据此推了一条错误的处方
- **退役是可执行的事实，不是一句注释**：退役的脚本留在盘上但 `main()` 即显式终态退出

### Q-9 · 判据要报出自己的基线，且探针的名字要等标定完再起
- 词表类判据没有基线命中率，等于不知道自己在说什么
- **告警与度量不要共用同一个分支**：把度量挂在「没问题」那一支上,
  等于规定「一出问题就不许知道现状」——而那恰恰是最需要知道现状的时候
- **抢跑的命名会误导**：一个叫「幻觉探针」的东西真跑出来幻觉 0 例，它抓到的是另外两件事——
  都是真问题，都不在它的名字上。后来读报告的人会按名字去解释数字

### Q-10 · 钱
- 花钱前必须人确认；能 0 成本离线验证的先离线验证
- **贵贱只有一处算**，且取决于「跑什么」与「带什么参数」**两者**
- 免费判定用**白名单**：没逐个核对过分支的参数、认不出的动作，一律按花钱算。
  「不知道」必须倒向贵的那一边
- **不显示预估花费**——猜一个数写在界面上，比不显示更坏

### Q-11 · 缓存
三条语义必须显式：关缓存**同时关读写** · 参数不变的「重跑」什么都没跑 · 被打断的跑可几乎免费续。
**空壳响应必须踢出缓存**，否则「重试」在下一次进程里会退化成「把同一个坏响应读了两遍」，
而它长得与一次真调用一模一样。

### Q-12 · 守卫本身要有守卫
- **关卡的判据必须跟着被它检查的契约一起改版。** 契约改了而关卡没改，关卡不会报错——
  它会继续输出一个看起来正常的结论。已实测：四条确定性检查在新契约下**三条静默失效、
  一条全量误报**（结论恒为「需修订」）。两种故障方向相反、危害相同：**报告不再携带信息**
- **改字段名时，搜旧名的范围必须覆盖所有下游节点，不只是校验器。** 读着已改名字段的消费方
  **不会报错，它只是安静地什么也不做**。已实测三例，其中一例让「必须覆盖的事件」清单
  变成一串空项目符号，而解释「为什么必须列出来」的注释还原样挂在上面
- **修复步骤和关卡一样会静默失效**，而且更隐蔽：关卡至少还会输出一个 verdict

## 四、无守卫清单 B-01 ~ B-22

> **这是新骨架关卡层的施工清单。**
> 下表每一条都问过「哪一段代码在查它」，答案都是「没有」。
> 处置只有三种：**补一条判据** / **把这个自由度整个收走** / **明知不查但要写明**。
>
> ⚠ 补 prompt 之前先确认那条要求**本身是对的**——已有一例是要求错了（`B-12` 那条打架的）。
> ⚠ 收走自由度之后**别把它记成质量改进**：去掉的是一个无守卫、高方差的自由变量。
> **没有守卫 ≠ 已经出事。**

### 4.1 最要紧的五条

| # | 约束 | 现状 | 建议处置 |
|---|---|---|---|
| **B-01** ★ | **发明越界七项里的五项**：新事件 · 新地点 · 新道具 · 新因果 · 新时间跳跃 | **零校验。** 只有「新数字」有探针、「新人物」有部分探针（召回有缺口：用本书没出现过的姓造人、不带称谓后缀的光名字都抓不到）。地名后缀是普通名词、无硬左锚，实测 82 条候选几乎全假 | **已裁决（2026-08-10）：不补，直到有 ground truth。** 三条理由都有实测：① gate1 在抽象层做语义判定时**护栏自己成了发明源**，已整节退役；② **唯一 `full` 的那一项自己就零判别力**——`invented_number` 在 3 本里有 2 本被书级恒等闸门判死（头牌 2/8 vs 源章 2/8；三岁 1/9 vs 源章 **2/9**）；③ 反哺**实测会诱发**自造内容而当轮判定一条都指不出它。<br>⇒ 七项的身份是**给人核对的料**（同 `name_surface_survey`），不是关卡。**「探针报 0 条 ≠ 约束生效」必须写在报告里** |
| **B-02** | **拍的顺序就是落笔的顺序** | 没有。「事件有没有落点」只查有无，不查顺序 | 补判据（拍的落点位置单调）**或**接受不查并写明 |
