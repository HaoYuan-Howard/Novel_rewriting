# To-do list

本文件是项目唯一的活动待办清单，基于 2026-08-15 对设计交接包、现役设计 brief、根目录记录、
当前代码与守卫测试的联合审计。已完成事项不在这里保留；历史原因由 Git 和专项验证记录回答。
产品规格、冻结契约、证据基线以及文档与测试的直接耦合统一见 `docs/BACKEND_CONTRACT.md`。

优先级含义：P0 影响正确性、真实花费或恢复能力；P1 影响质量闭环、诊断可信度或兼容性；
P2 是明确可延期的工程化与体验增强。勾选前必须满足条目中的验收条件，而不是只增加类型、按钮
或占位函数。

## 待产品裁决 · 不应由实现者静默选择

### DEC-01 · stage0 人工审阅与编辑账

- [ ] 审阅范围：全量书、只审自动命中书，还是允许零命中批量放行。
- [ ] 重跑 stage0 时，人工编辑与新自动结果如何三方合并；唯一已确定的底线是不得静默覆盖。
- [ ] `clean_text.txt` 是否进入所有下游来源指纹，以及人工正文编辑是否逐条记账。

建议：默认全量首次审阅；自动重跑产生候选 diff，由人确认合并；下游至少绑定 clean hash，详细编辑项
另存审计账。该选择会改变用户流程与全链 stale 口径，实施前需确认。

### DEC-02 · 无可靠守卫的语义如何处置

以下能力目前不能被“加一条看起来合理的检查”草率关闭。每项要在“建立 ground truth 的守卫、
收走生成自由度、明确交人工、明确不可验证”中选一项：

- [ ] 写作拍严格按计划顺序落笔。
- [ ] prompt 不泄漏内部 beat / character / rule / node 标识。
- [ ] 计划不发明人物、事件和设定，重头稀缺，结尾钩子不提前泄底。
- [ ] 逐章抽取的施受关系、区间、硬数字、矛盾与非转抄质量。
- [ ] 全书规则/秘密收录标准及相关枚举的语义正确性。
- [ ] 文风画像的可迁移性、覆盖位置、区分度与素材分区。
- [ ] 写作不说破潜台词、遵守视角，开卷臂不过度照抄。
- [ ] 修剪不改变人物、地点、因果、时间与结尾立意。
- [ ] 开卷写手是否必须获得“现场 / 回忆 / 转述”的完整释义。
- [ ] 身份描述泄底、改写式泄底与设定块字面探针的判别力。

### DEC-03 · “部分遮蔽”是否升级为完整遮蔽

- [ ] 当前产品明确常驻提示“部分遮蔽”，这是诚实状态；若产品要求完整遮蔽，需要先定义所有泄漏面
  和消费方，而不是只扩一个字段列表。

建议：在有完整威胁模型和反例集之前维持“部分遮蔽”命名，不宣传为安全边界。

## 条目生命周期

1. 开工前补足可复现输入、预期最终状态和受影响的守卫。
2. 改动同时覆盖真实消费者、失败路径、文档与测试，不以“能构造 schema”为完成。
3. 验收通过即删除条目；不要在活动清单里保留已完成施工史。
