# 未完成需求

本文件只记录项目尚未完成、尚未验证或尚待裁决的事项。条目通过验收后直接删除；
实现过程与完成记录留在 Git 历史，不在这里归档。

后端开发当前视为关闭。标有“需重开后端”的条目是已知缺口或前端阻塞项，不代表可以
自行扩大后端范围；实施前必须先取得明确裁决。

## 文档边界

- 本文件回答“还欠什么、怎样才算完成、被什么阻塞”。
- 产品流程、屏幕和视觉规则以 `docs/design_brief/` 为准，本文件不复述。
- 已实现的产物/API 形状以 `docs/schema/` 和代码为准。
- 前端当前结构与联调事实以 `web/DELIVERY.md` 为准。
- 既有后端的编号与判据追踪冻结在 `docs/BACKEND_CONTRACT.md`，不再作为任务清单。
- 可迁移经验只写入 `docs/LESSONS.md`。

若代码、schema、样本和文档冲突，先确认冲突属于实现事实还是产品语义。实现事实可据仓库
自行核实；会改变页面、API、数据契约或用户流程的语义冲突必须先裁决。

## 当前交付目标

把 `web/` 从 mock 版接到真实服务，并让所有可见入口诚实反映后端能力：

1. 可用功能走真实数据和真实写入链路；
2. 未提供的能力显示明确的“尚未实现/当前不可用”，不伪装成空数据、成功或普通 404；
3. 前端不复制后端的枚举、费用、写盘、新鲜度和判定逻辑；
4. mock、证据基线与真实响应严格分层。

项目完成不能只以编译通过为准；至少要在真实服务、真实书目录和真实浏览器路径上验收。

## P0：真实前端联调

### FE-01 · 对齐真实 API 可用面

**现状**

`web/src/types/api.ts` 与 `web/src/api/endpoints.ts` 声明了完整界面所需的读写方法，
通用异步作业启动与 `approvals` 状态机已经接入真实服务；当前仍缺以下调用：

- 读取：`reading/:ordinal`、`stage2/global`、`stage4/:ordinal`、
  `stage5/:ordinal`、`review/:ordinal`、`inbox`、`stage6`、`stage7`；
- 人工写回：章节改稿、文案定稿、人名定稿。

**要求**

先形成“前端 Api 方法 → HTTP 路由 → 服务端实现 → 页面入口”的逐项矩阵。每一项只能落在
“真实可用”或“明确不可用”之一，不能继续由 mock 掩盖。

**验收**

- `VITE_USE_MOCK=false` 时，正常导航不会因路由不存在而收到意外 404；
- 每个 `Api` 方法都有真实实现，或经产品裁决从真实模式移除并在界面说明；
- 404 只表示资源不存在，不拿它表达“能力尚未实现”。

**阻塞**：需重开后端 API/view 层，或裁决收窄前端能力面。

### FE-02 · 清除原型作业名和旧 check kind

**现状**

`web/src/` 仍使用 `n4_plan`、`n9_rename`、`stage5_review`、`n0_extras`
等旧名字；真实后端使用节点 id，并把 stage5 的 check kind 统一为 `stage5`。

**要求**

- 作业名、支持的 flags、`paid`、`writes_disk` 全部消费 `/api/enums`；
- check kind 与服务端八个 stage 逐值一致；
- 页面、类型、mock 适配层和动作按钮一起迁移，不保留第二套现役命名表。

**验收**

- 除显式命名的历史 fixture 外，`web/src/` 搜不到上述四个旧名字；
- 任意服务端新增/删除 action 不要求修改前端常量表；
- 未识别动作显示“未标注”，不得默认成免费或只读。

### FE-03 · 删除前端的判定与动作分类副本

**现状**

`web/src/constants/actions.ts` 仍用 `WRITES_FLAGS` / `WRITES_KINDS` 兜底；
`web/DELIVERY.md` 还登记了锚点覆盖率、逐拍预算比例、闸门 DAG 和
`freshness=missing` 的前端推断。

**要求**

- 费用、写盘、通过、严重度、新鲜度与闸门状态只照服务端结构化字段渲染；
- 服务端没有给结论时显示中性读数或“未知”，不在前端补阈值；
- 历史 mock 缺字段时只允许在 mock 边界适配，不得污染真实数据路径。

**验收**

- 真实模式不依赖 `WRITES_FLAGS` / `WRITES_KINDS`；
- 屏幕与组件中没有业务阈值、文案正则或作业名集合；
- 缺字段不会被折成“通过”“免费”“只读”或“新鲜”。

**阻塞**：若现有服务端响应缺少必需字段，需重开后端契约，或裁决改成中性展示。

### FE-04 · 完成真实读屏与 S-13 校验展示

**要求**

- 原文↔骨架、全局设定、计划↔上下文、成稿↔材料、验收/修订、待人工、
  开篇文案、人名与成书页面全部从真实 API 取数；
- S-13/校验面板按 `rules[]` 渲染，不从 `oks/unver/info` 文案反推结构；
- 字符数、切片、锚点与对齐关系由服务端视图给出，前端不重复计算；
- 加载、未运行、错误、正常四态都用真实响应走通。

**验收**

- 每一屏至少用两本真实书完成浏览器 smoke test；
- 长文本、空数组、`null`、amber、stale 和 unknown 均有覆盖；
- 页面没有直接读取 `src/mocks/`，也没有自行 `fetch`。

**阻塞**：FE-01。

### FE-05 · 接通真实写操作

**要求**

- 所有写按钮先调用服务端 preview，确认框显示服务端返回的完整命令与费用；
- 确认后调用真实作业/人工写回接口，真实模式不得写 localStorage 充当成功；
- 作业状态与日志使用服务端记录；失败、重启后的 unknown、冲突和显式终态分别显示；
- 没有真实端点的按钮必须禁用并解释原因。

**验收**

- 至少各走通一次：免费只读、免费写盘、付费确认、人工定稿、失败作业；
- preview 与执行使用同一份服务端计划，前端不拼 argv；
- 页面刷新后状态来自服务端，不依赖浏览器本地存储恢复。

**阻塞**：FE-01；付费 smoke test 还需要用户逐次确认。

### FE-06 · 隔离证据样本、mock 与新响应

**要求**

- `docs/design_brief/05_samples/` 与 `design_handoff_novel_refactor_console/mocks/`
  是证据基线，不得被新后端输出覆盖；
- 当前后端的新响应另建有版本含义的 fixture 目录；
- mock 与 real 继续共同满足同一个 `Api` 接口，但 mock 的兼容转换只能留在 mock 边界。

**验收**

- `npm run seams` 能证明证据基线未改、屏幕不直读 fixture；
- 关闭 mock 后构建产物与网络请求中不出现样本正文；
- 两份 check fixture 按新 `rules[]` 形状重建，并与旧证据分开保存。

### FE-07 · 前端交付门

每次删除一个 FE 条目前，必须同时通过：

```powershell
cd web
npm run typecheck
npm run seams
npm run build
```

并完成一次 `VITE_USE_MOCK=false` 的真实服务浏览器验收。验收记录至少包含失败路径，
不能只截图正常态。

## 需重开后端才能完成的缺口

以下内容仍未完成，但后端范围当前关闭。它们保留在这里是为了避免被误读成已支持。

### BE-01 · stage2 生成与写回

`novel/stages/stage2/extract.py` 的以下路径仍落 `RunModeNotImplemented`：

- 全书抽取、逐章抽取与定向重生成；
- `--purge-role`；
- `--migrate`；
- `--drop`。

完成时必须一次接齐：`ask_json` 响应模型、落盘前归一及其 provenance 账、
`present_names → present_char_ids`、verbatim 回取三笔账，并先确定
`human_adjudicated` 的子字段契约。只放行其中一半不算完成。

### BE-02 · 已登记但未接线的人工修订

- stage3：`--apply-edit`、`--repair-surface-habits`；
- stage4：`--apply-edit`；
- stage6：`--apply-edit`。

完成标准是与生成稿共用校验、落盘、轮次归档和 human provenance 路径；不能另造一条
“人工稿免检”写口。

### BE-03 · HTTP 服务仍缺失的真实消费路径

FE-01 点名的读屏与人工写回路由尚不存在。通用 `POST /api/jobs` 和 approvals 已完成，
后续若重开其余后端路径：

- 服务进程仍只写 `_service/`，产物写入继续经 CLI 子进程；
- 新变更路由自动经过现有 CSRF 中间件；
- 每个端点必须有成功、上游未运行、产物损坏和未实现的行为测试；
- 视图层只组装展示数据，不复制判据。

### BE-04 · 队列、待人工与断点续跑的半成品

- 待人工六类聚合没有生产者；
- 队列只有一次性计划，没有可取消的“尚未开始项”；
- 逐章写到一半的中断样本与恢复行为尚未建立；

这些能力必须以真实持久状态和失败样本验收，不能只增加 schema 或按钮。

### BE-05 · 共享基础设施缺口

- `_provenance.code` 不能稳定区分同一短 SHA 下不同 prompt/脏树；
- `LlmProvenance.to_human_edit()` 没有覆盖 `FreeProvenance`；
- 冻结后端契约仍有 4 个 `结构` 落点只写裸符号，路径存在性守卫无法检查；
- `PARTIAL_MASK_FIELDS` 尚无真实屏蔽消费方，接线前不得宣称完整遮蔽。

### BE-06 · 已知诊断与元数据错误

- stage4 `--identity` 的 `writes` 文案指向错误文件名；
- stage6 `hook_para_sep` 对单段文案给出不成立的诊断理由；
- stage5 的秘密词法两侧对中文数字处理不一致；
- stage5 rejected 归档和 stage7 `name_map_edit.json` 尚无真实端到端样本。

修复时要给出能复现旧错误的样本，不能只改文案或让当前样本变绿。

## 尚未完成的验证

### VAL-01 · 真正的 LLM 调用

stage4、stage5、stage6、stage7 只验证过 dry-run/合成路径，没有完成真实传输 smoke test；
stage2 受 BE-01 阻塞。首次调用会花真钱，必须逐次取得用户确认。

验收需记录模型、prompt 指纹、缓存命中、落盘产物、判据结果与失败重试；不得把真实密钥、
正文或完整响应提交进仓库。

### VAL-02 · HARD 判据反例

stage4、stage6、stage7 仍有 36 条 HARD 判据没有各自的会红样本。每条必须用判据可消费的
原始 dict 构造最小反例，并配一条“新增 HARD 却没登记反例就失败”的守卫。

### VAL-03 · 真链路回归样本

仍需补：

- stage5 `run_write` / `run_revise` 的真实响应降级路径；
- `.rejected.json` 归档；
- stage7 人工映射编辑后的完整重放；
- 真实服务上的付费确认、失败和重启后 unknown。

### VAL-04 · 重试参数与并发容量验证

逐章并发的默认值与硬上限已由 2026-08-13 用户裁决为 32，不再是未决调参项；Stage2
和 Stage5 的 20/40 章合成回归已验证峰值。真实 429 分布与重试/退避参数仍缺观测数据，
取得后应以调用日志和失败率验证容量并重新标定重试策略，不得静默突破 32 的产品上限。

### VAL-05 · 干净环境可复现性

部分语料测试依赖被 gitignore 排除的 `Test_data/`、`outputs/` 与同级原型仓；干净 clone/worktree
不能复现全量结果，且 fixture 数量可能静默缩小。应把可提交的最小合成 fixture 纳入仓库，
把需要本机版权语料的检查标成显式 integration suite，并在缺资产时报告“未检查”及预期数量。

## 无守卫但尚未裁决的语义

下表不是“补一个检查就结束”的清单。每项必须在三种处置中选一项：
建立有 ground truth 的守卫、收走自由度、或明确归人判断/不可验证。

| 编号 | 未决语义 |
|---|---|
| UG-01 | 写作拍必须按计划顺序落笔 |
| UG-02 | 发出的 prompt 不得泄漏内部 beat/character/rule/node 标识 |
| UG-03 | 计划不得发明人物/事件/设定，重头应稀缺，结尾钩子不得提前泄底 |
| UG-04 | 逐章抽取的施受关系、区间、硬数字、矛盾与非转抄要求 |
| UG-05 | 全书抽取的规则/秘密收录标准及五个枚举取值 |
| UG-06 | 文风画像的可迁移性、覆盖位置、区分度与素材分区 |
| UG-07 | 写作不说破潜台词、遵守视角、开卷臂不过度照抄 |
| UG-08 | 修剪不得改变人物、地点、因果、时间与结尾立意 |
| UG-09 | 开卷 system 对“现场/回忆/转述”三个标签没有解释 |
| UG-10 | 身份描述泄底、改写式泄底与设定块字面闸门判别力不足 |
| UG-11 | 计划轻重告警只有读数，没有处置回环 |
| UG-12 | 定向重生成被回归护栏驳回后没有下一条恢复路径 |
