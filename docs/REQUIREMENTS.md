# 小说重构系统 — 需求规格

**立于 2026-08-10（重写版）。** 用于正式开发：先按它定契约，再搭骨架，再移植。

---

## 这份文档怎么读

### 它是自足的

**全文 0 处外部引用。** 不引 `CONTRACTS.md`、不引 `PROTOTYPE_FINDINGS.md`、不引任何 F 编号、
不引任何已归档的交接件。需要的事实一律**就地写出来**，包括实测数字。

理由：这份文档要活得比它的来源久。一条写着「详见某文档某节」的需求，在那份文档被归档、
改版或删除之后，就变成了一条**读起来完整、实际上空心**的需求——而没有任何东西会为此报错。

代价是它会重复一些别处也有的话。这是有意的。

### 核心机制：每条需求带「谁在查」

需求表的最后一列是 **「谁在查」**，取值只有五种：

| 取值 | 含义 |
|---|---|
| **`HARD`** | 有确定性代码在查，违反即阻断（不落盘 / 非零退出 / 显式终态） |
| **`INFO`** | 有确定性代码在查，违反只报不拦 |
| **`闸门`** | 落盘之前跑的校验，不通过就不覆盖现役产物 |
| **`人`** | 按设计就由人判，没有也不该有确定性判据 |
| **`无守卫 → B-xx`** | **这条要求只写在 prompt 或文档里，没有任何代码在查它** |

第五种是这份文档存在的主要理由。

> **一条只写在 prompt 里的约束，它的遵守率是没人在测的。**
> 而它读起来与有守卫的那些**一模一样**——同样出现在【硬约束】段里、同样被别处当成
> 「结构上不可能」引用。要分辨「在守」与「只是在写」，唯一的办法是去问**哪一段代码在查它**。
>
> 已实测的代价：写作节点的三条硬约束（只并相邻拍 / 只并同层拍 / 按写作顺序排）
> 在盘上**各违反一次，全链没有一层出声**。

反过来的同一个病也要防：**一条只写在关卡里、产地从没被告知过的要求**。
两者的共同点是**约束与守卫不在同一个地方**，而后者更亏——模型本可以第一次就做对，
现在要为同一件事付第二次费。已实测：`章首漏抓` 是阻断级判据，而抽取节点的 prompt
不但没说「第一拍要从章首起」，还明写「两条之间允许有空隙」；三本书 5 处漏抓**全在章首**。

⇒ **验收本文档的方法是双向的**：
① 每条 `无守卫` 都要有处置（补判据 / 收走自由度 / 明知不查但写明）；
② 每条现役守卫都要能追到本文档里的一条需求（见最后一节的反向覆盖率）。

### 编号

- **`R-1` ~ `R-12`** — 功能需求，按处理阶段编排（**1:1 重建**：形态可以变，能力与守卫不许缩水）
- **`R-13` ~ `R-14`** — **相对原型新增的两项能力**（批量队列 · 断点续跑），用户裁决
- **`Q-1` ~ `Q-12`** — 工程约束，跨阶段成立
- **`B-01` ~ `B-22`** — 无守卫清单 = **关卡层的施工清单**

**`B-01` 与 `B-03` 需要裁决才能往下定契约**，见「待裁决」一节。

## 一、系统是什么

把一本中文网络小说的原作，经 7 个阶段处理成一本**新书**：情节骨架保留，文字全部重写，
人名全部替换，最终交付一个 `book.txt`。

**部署形态**：单人、本机、桌面浏览器。服务只绑 `127.0.0.1`。无登录、无多用户、无权限。

**成本模型**：每个阶段的核心是一次或多次 LLM 调用，**花真钱**。
确定性部分（分章、锚点回取、替换、组装、全部校验器）不花钱。
一次全链约 40~50 次调用；一本 8 章的小书跑完在数十分钟量级。

**最高风险不是「出不了书」，是「错误的剧情被静默接受」。**
LLM 的错误不会崩溃：它会造一个读起来毫无破绽的假事实、会在第 1 章说出第 14 章才揭晓的秘密、
会把一段该保留的关键台词整段丢掉而成稿依然通顺。
系统的全部设计张力都在这里——**这决定了本文档里绝大多数的 `Q-` 条目**。

### 处理链

```
stage1  摄入 + 分章 + 非正文剔除              0 成本，无 LLM
stage2  全书级抽取（人物/关系/规则/秘密/弧线）  1 次调用
        逐章抽取（事件拍 + 必须保真的原文点）    分批调用
stage3  文风画像（描述 + 代码实测的形态档位）    1~2 次调用
stage4  重构计划（只存决策，一个字内容都不经它） 1 次调用
        写作上下文（确定性组装，写作的唯一输入） 0 成本
stage5  逐章写作，两条臂：闭卷重构 / 开卷改写    逐章 1 次调用
        全书验收（判成品）+ 修订式反哺           0 成本 / 逐章调用
stage6  开篇文案：一次调用产三候选，人定稿       1 次调用
stage7  人名替换：一次调用产新人物表（只产决策）  1 次调用
        替换与成书组装                          0 成本
```

**章的唯一键一律是阅读序整数 `chapter_ordinal`。输出章号恒等于源章号**——
不合并、不重排、不删、不拆分，四条是同一个恒等式的分解。

## 二、功能需求 R-1 ~ R-12

### R-1 · 摄入与分章（stage1）

把一个原始 txt 变成结构化的章表，并剔除非正文。**这一层不调 LLM。**

| # | 要求 | 谁在查 |
|---|---|---|
| R-1.1 | 解码：BOM 优先探测，无 BOM 时试 `utf-8` → `gb18030`。**解码失败入显式终态，绝不用替换字符** | `HARD` |
| R-1.2 | 归一化**只做两件事**：去 BOM、换行统一为 `\n`。**不做 NFC/NFKC、不 strip 行尾** | `HARD` |
| R-1.3 | 记录原文 sha1；校验时对不上即阻断（有人换过原文，而下游全部产物仍是照旧那份跑的） | `HARD` |
| R-1.4 | 章号连续性：断号 / 重号 / 是否严格递增，逐项记账 | `HARD` |
| R-1.5 | **章数必须等于章表长度**（两行式番外最容易在这里造出一个被跳过的空章） | `HARD` |
| R-1.6 | 正文占比 < 0.60 判失败——**红在花钱之前** | `HARD` |
| R-1.7 | 非正文剔除：`番外 / 后记 / 尾声 / 作者有话说` 四类。正文 = `[0, 第一个非正文标记)` | `HARD`（切点与记账） |
| R-1.8 | 剔除的**正确性**——「这一段到底是不是番外」 | **`人`**，见 `B-20` |
| R-1.9 | 可疑但不算错的情况进显式 `warnings[]`，**不静默、不自动修正、不硬报错** | `INFO` |
| R-1.10 | 目录寻址只有一把尺子：文件名结尾有 `_<数字>` 就用它当 id，否则用书名本身当键；写盘前断言目录名能被同一把尺子解析回来且是不动点 | `HARD` |
| R-1.11 | 同目录不同正文 → 显式终态（除非显式强制覆盖） | `HARD` |

**剔除判据已按 161 本语料标定**：命中 27 本 / 34 条标记 / 0 假阳，切点全落在 75.9%~99.3%。
判据细节（它们各自都是踩出来的，重写要连着搬）：

- 逐行 strip 后剥掉前导 `【 [ ( （` 与 `\d{1,3}[.、．:：]?`、尾部 `】 ] ) ） 。 : ：`，得到 `core`
- `core` 以「番外」开头 → 命中（`len(core) <= 30`）；「番外」在中间或结尾 → 命中（`len(core) <= 12`）
- `后记`/`尾声` 要求 `core` **全等**，`作者有话说` 要求前缀相等。
  **不能用包含**：语料里有「节目的尾声」（5 字）、「前厅的宴席似乎已经接近尾声」、
  「孩子出生后记在你的名下」——它们**比真标记还短**，长度上限救不了，全等才救得了
- 两条长度上限是假阳的唯一防线（实测真标记开头分支最长 17 码点、中/尾分支最长 6，
  而含「番外」的正文句最短 77）。**这些数字必须按码点数**：「番外」一个词就是 6 字节，
  拿字节数当字数会把上限放大三倍
- **切点要往回退一行**：标记行之前（跳过空行）紧邻的若是一个章节数字行，那个数字属于番外
  （实测 5 本这样写）。不退的后果不是报错，是多出一个被当空白跳过的空章，而章数仍把它算进去

> **番外体在盘上不留任何副本**（用户裁决：彻底抛弃，不是「纳入别处」）。
> 因此剔除记账的摘要是**唯一**能核对「切对了没有」的东西——剔除是破坏性的，一次假阳会静默吃掉半本书。

### R-2 · 全书级抽取（stage2 · 一次调用）

抽出跨章成立的东西：人物、关系、世界规则、秘密、剧情弧线、设定。**纯描述，不做规约。**

| # | 要求 | 谁在查 |
|---|---|---|
| R-2.1 | 人物正典名**全书唯一** | `HARD` |
| R-2.2 | 人物的叫法（称谓表）逐条**必须在原文里原样搜得到** | `HARD` |
| R-2.3 | 称谓**整条不许是代词**。有据的叫法若全都含代词，下游必然取到「我妈」这种相对说话人的说法，而它不触发任何终态 | `HARD` |
| R-2.4 | 「谁在这么叫」的取值域闭合为 `<人物id> / 叙述者 / 公众`。**指称群体一律记「公众」**——「苏府下人」这类群体名解析不出人，而这个字段的用途是派发键 | `HARD` |
| R-2.5 | 每条叫法带「从第几章起可用」，且**不早于该叫法在原文里首次出现的章**（单边判定：早于字面首现一定错；晚于合法） | `HARD` |
| R-2.6 | 人物的静态身份描述**非空、不含结局词、不含模棱语、不得与正典名同字** | `HARD`（词表） |
| R-2.7 | 结局单独存一个字段，与静态身份分开——**它是故意造出来接住结局的**，删了结局会混回身份描述 | 只统计 |
| R-2.8 | 关系带「从第几章成立 / 到第几章失效」 | `HARD`（范围） |
| R-2.9 | 秘密带「埋点章」与「读者第几章知情」两套章号——**它们不是一回事** | `HARD` |
| R-2.10 | 五个枚举：`人名区分度` · `规则类型` · `称谓场合` · `弧线变化类型`（开放枚举）· `叙述人称` | **无守卫 → `B-08`** |
| R-2.11 | 抽取判据本身（只收结构性规则 / 规则描述必须连「怎么运作」一起写 / 秘密的四类收录判据 / 冲突阶段名要能定位） | **无守卫 → `B-08`** |
| R-2.12 | 身份描述里不许藏结局或未揭示的秘密 | **无守卫 → `B-14`** |

> **R-2.6 的词表只抓「结局」，抓不到中段才揭示的事实。** 实测基线：
> 某本书上词表命中 **0/17**，而人读真违规 **6/17**（「…后成为某人的下属」差一个字避开了词表里的「后被」；
> 「勾结外族叛国」是一条第 6 章才揭示的秘密，一个结局词都没用上）。另一本命中 2/40。
> ⇒ 这条判据**不是恒为 0，只是判别力低**。它命中时照报失败是对的，但
> **「没报违规」在这一维上不等于「没问题」**（`B-14`）。
> 处置不能是加词（那是个案补丁），也不能是按章收窄身份描述（会掏空写作节点对角色的认知）。

### R-3 · 逐章抽取（stage2 · 分批调用）

逐章抽出「发生了什么」：事件拍、以及必须逐字保真的原文「点」。

| # | 要求 | 谁在查 |
|---|---|---|
| R-3.1 | 拍的编号确定性归一为 `b<章号>_<序>`，**不许 LLM 自拟**（自拟会跨批撞名） | `HARD` |
| R-3.2 | 每一拍带它在原文里的区间，且**区间可定位**；游标单调 | `HARD` |
| R-3.3 | **原文以「点」不以「段」下发**：离散原子（要害台词 / 硬数字 / 物件 / 因果前提）可逐字下发；**连续文本段一律不下发** | `HARD`（长度与跨段） |
| R-3.4 | 一条跨段落的「要害台词」下发前**必须按段落边界确定性拆成独立的点**。实测一章 4 条跨段原话被写作节点**一条不剩地全丢** | `HARD` |
| R-3.5 | 原文字节**只能由确定性代码按锚点回取**，不许 LLM 转抄 | `HARD` |
| R-3.6 | 保真类型是闭合枚举，**兜底分支不许静默通过**——把写歪的类型兜底成「原样写入，一个字都不能改」，会把一段叙述文变成逐字要求 | `HARD` |
| R-3.7 | 在场人物一律用人物 id；解析不了的按**形状**分流（保留形必须解析，自由文本放行），不逼模型造假 id | `HARD` |
| R-3.8 | 章首章尾必须被第一/最后一拍覆盖 | `HARD` |
| R-3.8b | **且抽取 prompt 必须明说这一条**——三本书 5 处漏抓全在章首、0 在章尾，而 prompt 明写着「两条之间允许有空隙」 | `HARD`（prompt 侧待补，见 `Q-6`） |
| R-3.9 | 切分坍缩 / 拍过粗 | `HARD` |
| R-3.10 | 主谓宾明确不许省略施受关系 · 不为首尾相接拉伸区间 · 硬数字必须原样进事件文本 · 原文自相矛盾时如实记录矛盾 · 不许照抄例子里的名字 · 摘要不照抄原文措辞 | **无守卫 → `B-07`** |
| R-3.11 | 定向重生成（只重跑某几章，下游引用面零扰动）**必须配「不读缓存」**——它的 prompt 与整跑时该章那一批逐字相同，缓存必然命中，于是一个字都没重新生成而它照样打印「已重生成」 | `HARD` |
| R-3.12 | 定向重生成被回归护栏驳回之后**没有下一条路** | **无守卫 → `B-18`** |

> **R-3.3 的判据出处**：离散原子无法被模仿成文风，只能被放进去或不放进去；
> 连续文本段一律不下发——写作节点必然沿着它的句序和节奏走，那正是重写要避免的。

> **⚠ 定向重生成的成功率不是 1**：实测 9 次 → **7 次修好 · 1 次无变化 · 1 次净负**
> （一次重生成后章首仍未覆盖；另一次覆盖率 98%→90% 且在别处新添一处锚点失败）。
> 报「定向重生成能修好它」时要带上这个基数。

### R-4 · 文风画像（stage3）

量出原作的文风，转成能发给写作节点的指令。

| # | 要求 | 谁在查 |
|---|---|---|
| R-4.1 | **形态数字由代码算，不是 LLM 产**：字数 / 段数 / 句数 / 平均段长 / 段间分隔字数 / 平均句长 / 对白比 / 引号体 | `HARD` |
| R-4.2 | 正文与开篇文案段**分开测、互不污染** | `HARD` |
| R-4.3 | 数字换算成**档位词**下发，**实测数字本身不下发** | `HARD` |
| R-4.4 | 描述里**不许出现数字**——数字的落点是实测块，写进描述就是两处不同步 | `HARD` |
| R-4.5 | 描述**必须可迁移**：写生成机制不写本书内容，因此禁止出现专名 | `HARD` |
| R-4.5b | 专名扫描面**排除书名与 id**——它们是确定性搬来的元数据，不是模型写的描述。实测一本书名含一个人物专名，于是该判据在书名上恒红，而书名改不了也不该改 | `HARD` |
| R-4.6 | 无开篇文案段时该字段为空并**显式报警，不编造** | `HARD` |
| R-4.7 | 声音八维 / 文案写法七项 / 表层习惯的**内容质量** | **无守卫 → `B-09`** |
| R-4.8 | 「必须覆盖四类位置」「每一维要写出区分度」「不得凭印象写全程统一」「素材分区不得混用」「不要用套话填格」 | **无守卫 → `B-09`** |

> **本节点的真实调用数恒 ≥1，不可能靠缓存白跑**：表层习惯引原句 **5/5 本全犯**，
> 而带反馈重抽那一次不读缓存。重跑路径恒为「首抽命中缓存 → 返回同一份违规稿 → 必然重抽 → 重抽不吃缓存」。
> 报预算按「1~2 次」。

### R-5 · 重构计划（stage4 · 一次调用）

**只存决策，一个字内容都不经它。**

| # | 要求 | 谁在查 |
|---|---|---|
| R-5.1 | 输出章号 1..N 连续 | `HARD` |
| R-5.2 | **一章对一章**：源章列表长度恒为 1 · 源章序非递减 · 源章全覆盖 · 无源章被两个输出章共用 · **源章号 == 输出章号**（前四条的合取式，做成会报错的检查而不是一句注释） | `HARD` ×5 |
| R-5.3 | 篇幅方式恒为「保持」；逐章预算之和落在源字数的 ±10%，**无豁免** | `HARD` |
| R-5.4 | 逐章三个目标（章目标 / 开头钩子 / 结尾钩子）**不含风格套话词** | `HARD` |
| R-5.5 | **拍的分组与顺序由代码切，不由 LLM 产**：只吸收 <80 字的碎拍，并进同层的、较小的那一侧邻居；够大的拍一条不动 | `HARD`（后置条件 ×3） |
| R-5.6 | 三条后置条件：章内展平后与源序一致 · 每一拍是源序上一段连续区间 · 一拍内叙述层恒定 | `HARD` |
| R-5.7 | **LLM 在这一层真正产出的只剩三样**：全书重构策略 · 逐章三个目标 · **逐拍预算** | `HARD`（正整数） |
| R-5.8 | 不发明人物/事件/设定 · 重头要稀缺（一章一到两拍）· 结尾钩子不提前泄底 | **无守卫 → `B-06`** |
| R-5.9 | 「分配要有轻重」「一拍 80~150 字」两条 warn **量出来了，然后没有下文** | **无守卫 → `B-17`** |

> **R-5.5 为什么收走这个自由度**：从前 prompt 写着三条硬约束（只并相邻 / 只并同层 / 按写作顺序排），
> 而代码里**一条对应的门都没有**。实测盘上三条**全被违反过**。
> 收走之后它们成为分组函数的后置条件——红了只有两种可能：产物是旧的，或分组函数坏了。
>
> ⚠ 两点配套：① 收走之前先量代价（纯 1:1 会顶破篇幅上界，所以只吸收碎拍）；
> ② **别把它记成质量改进**——去掉的是一个无守卫、高方差的自由变量，
> 而并拍不伤成稿早已实测过。**没有守卫 ≠ 已经出事。**

> **`BEAT_MIN_CHARS=80` 这个阈值只有分布支持，没有独立判断校准。**
> 它来自「写作节点一拍的自然产出 80~150 字」的观测，不是拿成稿质量标定出来的。
> 「80 比 60 或 100 更好」没有证据。

> **逐拍预算是非平凡的**：两本书实测，拍级 `预算/源字数` 中位 0.97 / 0.95，
> 区间 0.64~1.85 / 0.69~1.57，**恰好 1.00 的拍 0 个**——模型确实在拍上分配轻重，不是照抄源字数。
> 章级两本给出**相反**的读数（一本 8/8 全是 1.00，另一本 14 章各不同），
> ⇒ 现在唯一能说的是「没有证据支持任何一边」。

**这是写作的唯一输入。** 它由代码按引用组装，不经任何 LLM。

|---|---|---|

| R-6.3 | **逐章剧透闸门**：一条秘密下发的充要条件是「读者已在本章或之前知情」**或**「本章是埋点章」；后者带一个「读者尚不知情」标志位，写作节点据它分成「可以正面写」与「只埋不点破」两组 | `HARD` |
| R-6.4 | **跨叙述层不压平**：在场人物取并集会把只在回忆里出场的人放进现世街头 | `HARD` |
| R-6.5 | 设定块也要逐章投影——它曾是唯一一个书级直发、无任何闸门的事实块 | `HARD` |
| R-6.6 | 剧透屏蔽要**按信息盘点通道，不按字段名盘点**：同一批事实会从身份描述 / 关系生效章 / 世界规则描述 / 冲突阶段摘要 / 弧线多条旁路漏出 | 部分 `HARD` |
| R-6.7 | 设定块的剧透闸门是**字面子串包含**，只挡转抄式 | **无守卫 → `B-16`** |
| R-6.8 | 「不许发明」清单七项里的**新地点 · 新道具 · 新因果 · 新时间跳跃**（另加新事件） | **无守卫 → `B-01`** ★ |

> **R-6.7 的实测基线**：设定块的剧透闸门**命中 0/8，包括一条已知的真泄漏**。
> 某本书的「世界观」写着「主角穿越到…系统绑定宿主，发布攻略任务」，
> 而一条秘密的内容是「许言是穿越者，绑定系统，任务是完成剧情攻略男主们」——
> 说的是同一件事、**措辞完全不重叠**。**写第 1 章的写作节点照样读得到第 14 章才该揭示的事。**

> **R-6.8 的实测原因**：「新地点」查不了是有原因的——地名后缀（府/家/宫/城/街/山）都是普通名词，
> 没有数字那样的硬左锚，实测 23 章报 82 条候选、几乎 100% 假阳。
> **别把「探针报 0 条」读成「约束生效了」。**

### R-8 · 全书验收与反哺（stage5 第二相）

**判成品，不判计划。** 整本写完之后才算得出来。

| # | 要求 | 谁在查 |
|---|---|---|
| R-8.1 | 严重度四级：`阻断 / 提示 / 度量 / 查不了`。**「度量」与「提示」必须分开**——度量无条件产出，不许挂在「没问题」那一支上 | `HARD` |
| R-8.2 | 每条结论带**根因第一嫌疑层**；「可反哺」**蕴含根因在写作层**——根因不在写手身上的条目重写一百遍也修不好 | `HARD` |
| R-8.3 | 收敛键 = `(章, 判据, 证据键)`。只按判据去重会把「换了个位置」读成「已修复」 | `HARD` |
| R-8.4 | 成稿指纹没变时**不许前进未消轮次计数**——0 成本重跑一次验收不是「写手又试了一次」 | `HARD` |
| R-8.5 | 连续 2 轮未消 → 判「根因不在写手」，反哺主动跳过 | `HARD` |
| R-8.6 | **付费自救的第二道准入**：可反哺之外还要「满足路径唯一」——目标字串被上游钉死，或动作就是「删掉指出来的那个东西」，写手编不出第三种答案。密度 / 比率 / 档位类**一律不进**，因为最省力的满足路径是删内容或编内容 | `HARD`（分不干净当场炸） |
| R-8.7 | 「这条我不修」要**理由必填**，且不给不存在的结论发豁免；豁免**不删结论**，只是不再进反哺、不再占待办，并**单独计数** | `HARD` |
| R-8.8 | 待人工清单聚合六类，**只读盘、不重判**：被闸门拦下的问题稿 / 自救被驳回 / 连续两轮未消 / 不进付费自救 / 阻断且重写修不掉 / 两个人定稿闸门。**「查不了」不进**——那是判据的边界不是待办 | `HARD` |
| R-8.9 | 词表类判据**必须报出它的基线命中率** | `HARD`（部分） |
| R-8.10 | 改写式泄底 | **无守卫 → `B-15`** |

> **R-8.6 的依据与代价**：某章为满足「对白变少了」这条（引语 7→11 句）**凭空编了一句台词**，
> 源章 0 次且语义讲不通；而第二轮全部 4 条判定**没有一条指向它**，报告还记它「消掉 2 条」。
> 收窄后的实测代价：盘上 5 本可反哺条目 **36 → 9（转人工 27 条，75%）**，
> 其中一本是 **10 → 0**。⚠ 这是裁决的后果不是 bug；转人工那些**照常列在报告与界面上等人改**。

> **R-8.9 的出处**：一张「揭示标记」词表（其实/原来/一直/根本…）实测在 **21/22 章**命中，
> 与那一章有没有点破什么无关——于是它的「通过」分支是**一盏保证会亮的绿灯**。
> 没有基线数字的词表判据，等于不知道自己在说什么。有判别力的往往只有它的**反面**
> （一个标记都没有＝反常）。

> **另一条已可判死的**：秘密的字面探针 **4 本 12 条 secret，0 命中，连各自的揭示章都不命中**
> （四个题材）。「改写式泄底确定性层抓不到」不再是推论（`B-15`）。

> **判据的判别力是（判据 × 书）的属性，不是判据的属性。** 恒等基线在每本书上判死的是**不同**的集合；
> 三本书的干净集**交集只剩一条**。别把某本书上「这条判据有用」外推成判据的属性。

### R-10 · 人名替换与成书（stage7）

把成品里的**人物真名**换掉，好让成品表达原创；关系、身份、职位、称谓体系一个字不变。
**一次调用产新人物表（只产决策），替换与组装全部是确定性代码，人定稿。**

| # | 要求 | 谁在查 |
|---|---|---|
| R-10.1 | **改名只能待在链尾**：全链底座的判据是「人名必须在原文里有据」，把新名写回上游会被静默撤销。本节点**只读上游、只产自己的产物、绝不回写** | `HARD` |
| R-10.2 | 替换是**单次 alternation 扫描**，`A→B`+`B→C` 的级联在结构上不可表示 | `HARD` |
| R-10.3 | **三道防线**（中文没有词边界，这是本节点全部的风险）：① 保留项进 alternation 当恒等条目 ② 称呼最短 2 字 ③ 多主称呼一律否决 | `HARD` ×3 |
| R-10.3b | 但**有一类书里多主是情节本身**（顶名 / 替身 / 女扮男装）：人在补充映射里明写的按人的裁决执行，另落一条 info **照样报出它还碰到了谁**。这条否决防的是**静默**误伤，不是「多主一律不能换」 | `HARD` + `INFO` |
| R-10.4 | 姓氏族群的判据**只有「字面同姓且 ≥2 人」**。关系边那条已删：一本书的兄弟在关系里**根本没有边**，而谓词词表会把夫妻同姓并成一族 | `HARD` |
| R-10.5 | 亲属词与姓氏同形（`孙`/`公`/`子`/`女`/`母`）时，用**本书的姓氏表**判，不硬编码字表——否则会让原作的姓氏活着进入「原创」成品 | `HARD` |
| R-10.6 | 残留探针的取值面 = 「原文有据的姓」**∪** 「姓氏映射的键」。少了后者有盲区：正典名是自造标签的姓、与亲属字同形的姓都会被过滤判掉 | `HARD` |
| R-10.6b | ⚠ **修探针，不修「原文有据」那一侧**——同一份数据在下发面该严、在检测器该宽，两处的正确方向相反 | `HARD` |
| R-10.7 | 恒等基线：占位符双射往返，验替换器与组装器**逐字节守恒** | `HARD` |
| R-10.8 | 成书 = `文案 \n\n 1 \n\n 第1章正文 \n\n 2 \n\n …`，LF、无「第N章」、无任何审阅元信息 | `HARD` |
| R-10.9 | 成书是纯文本、带不了来源账，所以账记在它的 sha1 + 「判了哪几份稿」上 | `HARD` |
| R-10.10 | **替换覆盖率验不了**——只能替换人物表里有的称呼，**人物表漏掉的角色这一层结构上够不着** | **无守卫 → `B-21`** |
| R-10.11 | **新名好不好、读起来串不串味没有确定性判据** | **`人`**，见 `B-22` |
| R-10.12 | 新名贴合时代与性别气质 · 保住名字之间的结构关系（排行字、兄弟姐妹只差一字） | **无守卫 → `B-12`** |

> **R-10.10 的实测**：某本成稿里有一个人物（原文 2 次），而上游人物表**完全没有这个人**。
> 只按人物表替换，她改了名而她的家人原样留着。**除残留探针外全链没有第二处能发现它。**
> 别把「残留 0 条」读成「人名都换干净了」。

> **残留探针的覆盖率阈值只有分布支持，且它会反向**：比率 =（总数−残留）/总数，
> 当漏网形就是该姓的**主用法**时，分母里装的主要就是分子，比率自我压低——
> 实测两个姓分别是 40% / 60%（都落在「基本是普通词」那一侧）而**两个都是真漏网**。
> **两个信号打架时以结构信号为准**（它不受这个反馈回路影响，实测 6/6 全真）。

> **一族已知同形的残留**：`X家` / `X府` / 职务式称呼，**四本同形**（`陆家`×3 · 30 处 ·
> `刘家`×6 + 手帕上绣的「柳」字 · `沈总`/`周秘书`）。根因是人物表的称谓收的是「人的叫法」，
> 不收「门第」形，也常漏收职务式称呼。补充映射后覆盖率回到 100%。

### R-11 · 人工验收界面

**给人眼核对用的工具，不是自动化看板。** 主体动作永远是「把两份东西并排放在一起，让人自己看」。

| # | 要求 | 谁在查 |
|---|---|---|
| R-11.1 | 只绑 `127.0.0.1`。四条各自独立成立的理由：会在本机执行进程 · 那些进程花真钱 · 会往盘上写文件 · 传输的是不外流的版权正文 | `HARD` |
| R-11.2 | localhost 也要防 CSRF：变更类路由要求自定义头 + 校验来源。**一个花钱的端点开在本机上，浏览器里任何页面都够得着它** | `HARD` |
| R-11.3 | **服务进程只读，绝不落盘**，一切写操作走子进程。原因不是洁癖：来源账是**进程级**的且键不含书名，同一进程里读过 A 书再写 B 书的产物，会落下一条**看不出来的假匹配** | `HARD`（测试钉死） |
| R-11.4 | **界面不重算任何已经在校验器/闸门里的判据**，只呈现或链接。造第二个判官就是造第二个落点 | `HARD` |
| R-11.5 | 六个核心对照视图：原文↔骨架 · 计划↔写作上下文（逐拍）· 成稿↔材料（含原文↔重构稿按锚点切块）· 结论↔可编辑成稿 · 三候选文案 · 新旧人名表 | — |
| R-11.6 | 产物新鲜度**三态**（新 / 陈旧 / **不知道**）；校验徽章**三态**（通过 / 通过但有查不了的 / 失败） | `HARD` |
| R-11.7 | 付费与 0 成本动作在界面上分色，且**贵贱只有一处算**（服务端），前端一行判贵贱的代码都没有 | `HARD` |
| R-11.8 | 付费入口一律经二次确认，并把**将要执行的那条命令**摊开显示（展示与执行共用同一个构造函数） | `HARD` |
| R-11.9 | 原文↔重构稿的分界线由**必须逐字写入的原话**定：同一串字节在两侧各定位一次，**两边都锚到才切**。没有锚的拍并进相邻块，**不给它编一条分界线**，并常驻显示锚点覆盖率 | `HARD` |
| R-11.10 | 一本书同时只跑一个作业（第二个请求 409）。唯一例外：写作的两条臂可并发 | `HARD` |
| R-11.11 | 作业记录 = 这次跑用的是哪条命令、哪版代码。**服务重启后 `运行中` 一律改判 `不知道`**，不是「成功」 | `HARD` |
| R-11.12 | **不做作业取消**——调用在途时钱已经花了，kill 掉省不回来 | — |
| R-11.13 | 剧透开关只关四个字段，**已知旁路仍在**，界面上常驻这句标注 | `INFO`（标注） |

> **R-11.9 为什么不照抄逐段 diff**：那个比的是同一章的两轮稿子，段落大体还是那些段落。
> 这里比的是原文与重写，实测配对率**开卷 44~82% / 闭卷只有 8~25%**——
> 闭卷写手没见过原文，句子没有字面关系。而**逐字原话的锚与臂无关**（闭卷覆盖 50~100%），
> 正好补上塌掉的那一半。实测两本 22 章，带原话的拍 **31/31 与 49/49 两侧全部定位成功**，
> 覆盖 70% / 77% 的拍，**稿内锚点逆序 0**。

### R-13 · 批量队列 【**新增能力**，原型没有】

> **`R-13` 与 `R-14` 是本次正式开发相对原型的两项新增**（用户裁决）。
> 其余 `R-1` ~ `R-12` 是 1:1 重建——**形态可以变，能力与守卫不许缩水**。

一次排入多本书，按顺序自动跑到指定阶段，人只在需要裁决的地方介入。

| # | 要求 | 谁在查 |
|---|---|---|
| R-13.1 | 队列以「书 × 目标阶段」为单位，可排入、可取消**尚未开始**的项 | 待建 |
| R-13.2 | **一本书同时只跑一个作业**这条不变（唯一例外仍是写作的两条臂）；队列只决定顺序，不放宽互斥 | 待建 |
| R-13.3 | **花钱的项必须一次性预先确认**，不能因为「排进队列了」就变成静默扣费。确认时摊开的仍是**将要执行的那些命令** | 待建（`Q-10`） |
| R-13.4 | 任一项失败 → **停在那里，不跳过、不继续往下扣费**。失败项与其后未跑的项分开计数 | 待建（`Q-1`） |

⚠ **批量的风险与单本不同**：单本跑错，人当场看得见；批量跑错，是**一批产物同时坏掉且没人在看**。
所以 R-13.4 的「停在那里」不是保守，是这条能力成立的前提。

### R-14 · 断点续跑 【**新增能力**，原型没有】

一次跑被打断（人为中止 / 进程死 / 机器重启）之后，能从断点继续，**不重复付费**。

| # | 要求 | 谁在查 |
|---|---|---|
| R-14.1 | 已完成的阶段按**产物存在性 + 来源新鲜度**判定，不靠一份单独的进度文件——进度文件会与盘上的实际产物分家 | 待建（`Q-4`） |
| R-14.2 | 逐章类阶段（写作）的续跑粒度是**章**：已落盘的章不重跑 | 待建 |
| R-14.3 | **被打断的跑可以几乎免费续**——已完成的调用命中缓存。这要求缓存键稳定，且**参数不变的「重跑」什么都没跑**这条语义被显式说出来 | 待建（`Q-11`） |
| R-14.4 | 续跑前必须**重新判定新鲜度**：上游在中断期间变过，就不是「续」而是「重来」，要说出来 | 待建（`Q-2`/`Q-4`） |
| R-14.5 | 中断留下的半成品（写到一半的章 / 空壳响应）**入显式终态并踢出缓存**，不许被当成「已完成」续过去 | 待建（`Q-11`、`R-12.2`） |

⚠ **`R-14` 与「不做作业取消」不冲突**：不做取消是因为**调用在途时钱已经花了**；
续跑处理的是**已经被打断之后**怎么办。两件事。

## 三、工程约束 Q-1 ~ Q-12

跨阶段成立。它们不是「最佳实践」，每一条都对应一次已发生的损失。

### Q-1 · 不静默
截断 / 缺章 / 解码失败 / 任何异常一律入**显式终态 + 报警**，绝不悄悄接受、不自动修正。
可疑但不算错的进显式 `warnings[]`，交人工审核。

### Q-2 · 「不知道」与「没问题」必须可区分
这是本系统最贵的一条。它有四个落点：
- 产物新鲜度**三态**（新 / 陈旧 / **不知道**），指纹缺失记作「不知道」不是「匹配」
- 结论严重度**四级**，其中「查不了」独立成一级，既不是通过也不是失败
- 校验徽章**三态**：「通过 + N 项未验证」渲染成琥珀**而不是绿**
- 作业状态含「不知道」

> **实测代价**：某次 23 章成稿与任何一版上下文都配不上（匹配 1/23），
> 而产出它的那份上游已被覆盖，**配对关系永久丢失**——而界面当时全绿。

### Q-3 · 每一层确定性的部分都必须能 0 成本重算
否则修自己的 bug 要付费。命名体系本身是资产：
`--check-only` / `--revalidate` / `--recheck` / `--remeasure` / `--prompt-only` /
`--context-only` / `--dry-run` / `--identity` / `--names-only` / `--apply-edit`。

**配套纪律**：重算时只对**本次新引入**的错误入终态——旧违约照报但不挡路，
否则一条不相干的旧问题会把重算这条路永久堵死。

⚠ 原型里这条**三个节点行为不一致**（一个有提升路、一个没有、一个把问题稿双双排除掉，
代码直接叫你重付一次钱）。新骨架**必须一致**。

### Q-4 · 每份产物必须记住自己是从哪份上游来的
`{prompts 指纹, model, code 版本, inputs 指纹, params}`。
**校验器先报来源，再报判定**——对不上时报出来的一堆违规是「拿新尺子量旧布」，
不说破就会被当成一次回归。

⚠ **读上游只有一条路**（那条路记账）。原型里有十几处裸读绕过它，绕过就记不上账。
⚠ 指纹是**文件级**的：改一个不相干的字段会让整份产物的指纹失配，把一批结论降级成「读数不可用」，
且没有重新挂钩的路。字段级指纹是一次契约改版，值得在新骨架里就做对。

### Q-5 · 先校验后落盘
阻断级错误**不覆盖已有产物**，问题稿单独存一份带 `.INVALID` 标记的文件。
配 0 成本提升路（`--revalidate`）：按**当前**判据重判，合格即提升。

**为什么必须有提升路**：没有它，修一条**判错**的判据要为每一章再付一次费，
而重掷回来的是**另一份稿**，修没修好无从对照。

### Q-6 · 单一落点
一个枚举 / 词表 / 区间 / 判定，全系统只能有一份定义。
**prompt 里那一份必须是插值来的**，不许手抄。

模板引擎的选型判据只有一条：**占位符缺值时必须抛异常**。
缺值渲染成空串会静默产出一个带窟窿的 prompt，与「显式终态」正相反。

⚠ 已实测的分家：prompt 手抄的写法词表写着「象征/强化感官」而真词表是「意象/感官」、另 8 词一个没提；
另一处漏了整个一档。**模型按 A 算、校验按 B 判，谁也不会出声。**

### Q-7 · 中间层只存决策与引用，内容由确定性代码搬运
**凡是让 LLM 转抄的地方，都会长出一个新的漂移源。** 对原文字节成立，对任何上游产物也成立。

⚠ 已实测：某中间层把上游的事件文本改写成合并散文，106 拍相似度中位 0.84、最低 0.44，
既造事实（「某人身边人」→「某家丫头」）又丢内容（整段具体材料被压没）。

### Q-8 · 退役而不删，且必须带标注
- **不删**是为了区分「没报违规」与「根本没在查」——把修不好的数据删掉，这一次会响亮报错，
  下一次跑就没得报了，一次性告警会退化成静默降级
- **必须标注**是因为一份没有标记的退役描述会继续**以现役身份被引用**。
  已实测：一份外部审阅照着一条被推翻的旧判据得出结论，并据此推了一条错误的处方
- **退役是可执行的事实，不是一句注释**：退役的脚本留在盘上但 `main()` 即显式终态退出

### Q-9 · 判据要报出自己的基线，且探针的名字要等标定完再起
- 词表类判据没有基线命中率，等于不知道自己在说什么
- **告警与度量不要共用同一个分支**：把度量挂在「没问题」那一支上,
  等于规定「一出问题就不许知道现状」——而那恰恰是最需要知道现状的时候
- **抢跑的命名会误导**：一个叫「幻觉探针」的东西真跑出来幻觉 0 例，它抓到的是另外两件事——
  都是真问题，都不在它的名字上。后来读报告的人会按名字去解释数字

### Q-10 · 钱
- 花钱前必须人确认；能 0 成本离线验证的先离线验证
- **贵贱只有一处算**，且取决于「跑什么」与「带什么参数」**两者**
- 免费判定用**白名单**：没逐个核对过分支的参数、认不出的动作，一律按花钱算。
  「不知道」必须倒向贵的那一边
- **不显示预估花费**——猜一个数写在界面上，比不显示更坏

### Q-11 · 缓存
三条语义必须显式：关缓存**同时关读写** · 参数不变的「重跑」什么都没跑 · 被打断的跑可几乎免费续。
**空壳响应必须踢出缓存**，否则「重试」在下一次进程里会退化成「把同一个坏响应读了两遍」，
而它长得与一次真调用一模一样。

### Q-12 · 守卫本身要有守卫
- **关卡的判据必须跟着被它检查的契约一起改版。** 契约改了而关卡没改，关卡不会报错——
  它会继续输出一个看起来正常的结论。已实测：四条确定性检查在新契约下**三条静默失效、
  一条全量误报**（结论恒为「需修订」）。两种故障方向相反、危害相同：**报告不再携带信息**
- **改字段名时，搜旧名的范围必须覆盖所有下游节点，不只是校验器。** 读着已改名字段的消费方
  **不会报错，它只是安静地什么也不做**。已实测三例，其中一例让「必须覆盖的事件」清单
  变成一串空项目符号，而解释「为什么必须列出来」的注释还原样挂在上面
- **修复步骤和关卡一样会静默失效**，而且更隐蔽：关卡至少还会输出一个 verdict

## 六、反向覆盖率

> **验收本文档的第二个方向**：每一条现役守卫都要能追到本文档里的一条需求。
> 追不到的守卫有两种可能——需求漏写了，或者那条守卫本身该退役。
> **上一版做这个检查时抓出了 5 处需求漏写。**

新骨架落地时按这个清单逐条对：

| 守卫所在 | 应对应的需求 |
|---|---|
| 分章校验器 | `R-1.1` ~ `R-1.11` |
| 全书抽取的落盘闸门 | `R-2.1` ~ `R-2.9` |
| 逐章抽取的离线校验器 | `R-3.1` ~ `R-3.9`、`R-3.11` |

| 计划的落盘闸门 | `R-5.1` ~ `R-5.7` |
| 上下文组装的四条不变量 | `R-6.1` ~ `R-6.6` |
| 写作的落盘闸门 | `R-7.1`、`R-7.3` ~ `R-7.8` |
| 验收判据表 | `R-8.1` ~ `R-8.9` |
| 文案的落盘闸门 | `R-9.1` ~ `R-9.5` |

⚠ `R-13` / `R-14` 是新增能力，**原型里没有任何守卫可供反查**。
它们的「谁在查」一律是 `待建`——这一列不许在实现之后还留着 `待建`，
否则新增的两项能力会长成本文档第四节警告的那个形状：**只写在需求里，没人在查**。

**没有守卫的，一律指向 `B-01` ~ `B-22`。** 一条需求既没有守卫、也不在 B 清单里，
就是这份文档的漏洞。
