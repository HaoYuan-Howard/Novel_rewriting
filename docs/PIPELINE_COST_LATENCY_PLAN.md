## 3. 新工作流与职责

目标主路：

`Stage0/1 → characters → global → Global C → Blueprint E → Blueprint C → 免费 Stage2 汇合 → Stage4A → A C → Stage4B → B C → Context → Stage5～7`

- 人物节点只新增 Executor，不新增独立 Commander。Global 接受后才生成 Blueprint，暂不开放
  两个付费生成分支或预审重叠；Blueprint 内仍逐章并发。
- Global C 覆盖人物注册与必要全局事实；Blueprint C 首次覆盖全部章节原文、事实完整性、因果、
  状态和相关 Global 一致性。必要原文阅读不能由摘要或上游接受代替。
- 两位 C 分别拥有持续工作单元及基础预算。Stage2 汇合沿用现有免费关闭入口，不新增模型或作业节点。
- Stage4A 继续盲规划，B 只绑定证据不改 A；A/B 两种审阅职责分离。Stage6 双 judge 保持互盲及 UNVER，
  最终采用仍是 typed 决定。Stage3 继续退役，章不合并、不拆分、不重排。

### 3.1 审阅义务、问题和修复归属

从各 producer 的现役 schema 枚举稳定审阅单元，分别保存 unit ID、主体/证据/依赖身份、契约、
原 actor、决定和理由。覆盖声明绑定冻结范围；“本轮完整覆盖且未列为问题的项接受”必须是模型
或人的显式 typed 声明，不能由漏填推导通过。

Global 的事实义务与 Blueprint 的一致性义务分别建模：读取已接受 Global 作参考，不等于重新
裁决同一事实。新决定与有效继承的并集必须完整覆盖当前义务，无冲突；没有待审项时免费收口。

问题必须记录准确主体、证据、修复条件和真实 owner，Stage2 owner 闭集为人物、Global、Blueprint
三个 producer。Blueprint 错了不把正确 Global 改 FAIL；指向上游的问题经已有权限路径派修，
只重开受影响接受。不能因新增 owner 自动授予 Stage4 跨阶段写权限。

修改问题主体只令其待复审，不能自动关问题；删除有问题的事实必须保留删除确认义务。定向编辑
模板只开放问题及真实依赖闭包，不能因为原审阅全 PASS 就放开所有 blocking 项。

模型端可使用本轮数字序号引用单元，由可信组装器注入正式 ID、SHA 和 token；完整原生 schema
不得随全部单元枚举无谓膨胀。审阅材料按引用表去重，完整详情与精简传输来自同一冻结工作包。

### 3.2 UNVER 与隔离处置

语义判断与生成处置是两条独立事实。隔离只适用于现役允许隔离、且能够从下游完整排除的组，
不使 UNVER 变成 PASS，不覆盖 pending/FAIL，不得删除必需情节事实来取得开闸。

用完整组成员、内容、证据和适用契约绑定隔离决定；同组当前 UNVER 可复用有效组授权，任一成员
或证据变化撤销处置。新接口统一表达组隔离，不要求通过修改事实取得处置入口；API 显示原授权来源。

## 4. 计算身份、采用与恢复

### 4.1 同一依赖投影服务请求、失效和影响范围

分别建立 A 全局策略、A 单章、B 单章及两类审阅的类型化业务依赖。移除 A/B 单章请求中的无关
整书包装身份；请求仍绑定实际 prompt/schema、模型/effort、输出和恢复协议。持久审计继续记录真实代码。

依赖覆盖实际策略、局部 alias、完整候选集合、邻章摘要、证据和边界义务；关系变化由代码算依赖闭包，
范围与原因一并留账。无法证明局部范围时保持未知或扩大到安全范围，不由 Commander 任意指定一章。

区分业务依赖、模型请求、审阅义务、修复事务、提交 intent 和 execution epoch。外层任务工作包
与内层编辑输入不能共用含糊的 workpack 字段；分别对原任务账及 producer 证明，以 exact request 连结。
原始 response 与可信组装后的 payload 各保留自身摘要，不混比。

### 4.2 B 的执行与整书提交

执行顺序为机械基线、精确历史采用、仅执行缺失/变化单元、完整聚合。允许不同运行提供各章来源，
允许全部章节机械生成或合法采用；同单元多个来源优先已有明确采用 lineage，其余只有唯一或可证
等价时采用，冲突不按时间或文件名猜选。

聚合使用独立 intent 和逐章来源清单，不再要求存在本轮模型 acceptance 作为 anchor。保留完整 A/B
原字节绑定、整书 HARD、当前 schema 和两相提交。机械生成、历史采用、缓存与新调用分开记账。

历史采用仅来自新工作流内的合格来源；旧归档不进采用池。跨代码采用须有登记政策并通过当前 validator，
不能泛化忽略 code 变化。源 owner、checkpoint、原回答、session、attempt、ledger 和采用证明均需闭合。

### 4.3 producer 决定恢复类型，Supervisor 执行转移

| 生产状态 | 唯一允许的行为 |
|---|---|
| 已保存回答或决定，提交未完 | 重验原请求与证据，零模型补提交 |
| aggregate prepared | 优先按同一 intent 补尾，不先启动新审阅或生成 |
| 相同请求的部分成功 | 保留成功单元，只续缺失工作，使用原预算 |
| 已完成且依赖确实变化 | producer 给出新依赖重建证明，排空旧执行，必要时新 producer/epoch，再重取 next/token |
| 文件/来源/执行证据矛盾或未知 | 保留 unknown，禁止当作新请求机会 |

修订反馈由同一 producer 从冻结候选/失败材料重演，不能由编排猜测旧项是否仍阻塞。连续会话的
恢复以 work_unit/turn/attempt 精确对证，允许真实多 turn 与网络重试，不照搬“会话必须恰有四个事件”。

### 4.4 生成、编辑、采用和聚合共用合法后继证明

正式 typed 编辑回执与产物同时保存，但还必须闭合审计、修后接受、动作消费和退休。恢复读到回执
后应补完缺失尾部，不能提前返回造成永久漏账。同意图重复执行不新增修订或费用。

每次合法编辑都追加从原提交到新主体的后继证明；后续上游变化时，重建校验应能走完整 lineage。
不能继续只把当前正式文件与最初模型提交比较，也不能取消原字节校验来接受不明修改。

main 静态审计发现两个组合风险，实施时必须以新契约补反例；本轮尚未运行复现测试：

- formal 编辑已写、typed-edit 审计未写时崩溃，main 的已落地快路提前返回而未补该审计。
- Blueprint 模型生成后合法编辑，再因称名输入变化重建；main 的旧 journal 比对可能将合法后继误判漂移。

## 5. 人物、必要知识、Blueprint 与对白

- 人物注册独占 ID、姓名、别名、称名归属、生效时点及可举证静态身份；知识引用冻结人物版本。
  漏人或误合并经人物 producer 修正；知识失败只补知识，称名投影不变则 Blueprint 不因规则修改重抽。
- 删除整个 arc 及 response、edit、审阅义务、Context、Stage6、UI 中的对应消费；必要结局事件和状态
  由事实承载，不换名称继续保存文学分析。
- Global 提出源文案事实证据和连续开篇正文范围，既有审阅确认；歧义进入 typed 裁决，不缺省为第 1 章。
- 分开审阅真相、规划约束与写作可见知识。现实时间、读者披露与人物获知分别关联事实；埋点只向写手
  提供允许表现的内容，不交未来答案。必要绑定缺失时明确未闭合，不靠字符串相似度补关系。
- Blueprint 保持一次拍→事实抽取及证据候选回取，精简重复说明、人物材料和反馈；不截正文、不限制
  事实数量、不把当前 v3.2 已有能力再计收益。
- 材料增加有证据的 source_fact_refs，与 B 机械归属同批；多事实分落不同场景仍保留歧义。
- 对白义务改为说话者、对象、语义、作用和必保事实，原句仅后台证据。贯通 Hinge、Context、写作、
  原句 HARD、反馈及重合度统计；剧情必要字面单列，语义保真仍由受托或人工核验。
- 合并 TODO-31 中与本次消费链重叠的冗余字段收紧，避免发布后立即再次破坏形状。

## 6. 基础四次与人工追加预算

工作单元账仍是唯一内容额度来源；成本只认既有 ledger。增加同一工作单元的不可变 BudgetGrant，
不清 turns、不改历史 ordinal、不换 unit_id，也不另开全书预算账。

目标计算为：基础额度 4；有效上限为 4 加所有有效追加；已用为真实预占/消费轮次；余量由同一账计算。
原调用即使因工程缺陷失败也保留费用与失败事实。网络 attempts 与内容调用继续分账。

默认设计：单次可明确追加 1～4 次，默认 1 次，只给指定角色及工作单元。每份授权都有有限次数，
不自动重复；累计不另设不可解释的隐藏重置周期，每次追加均须新的人工授权并显示累计支出和次数。

追加流程：

1. 后端预览准确工作单元、当前主体/拒因、基础/累计额度、待恢复成果及拟追加次数，返回 opaque token。
2. 只允许人类发起；同书锁、原 owner 停止证明和锁内账/主体 CAS 一并验证。活动 owner、未闭合执行、
   unknown 或可先免费恢复的成果不得被追加额度绕过。
3. 持久化 actor、reason、授权次数、原账/主体/契约绑定及幂等意图。同一请求重放不重复加额；主体漂移拒绝。
4. 追加本身不启动模型、不替代付费与正文外发授权、不解除无进展或语义阻塞。下一动作仍由 operator 产生。

同批升级 WorkUnit schema 中固定四次的 ordinal/committed 范围、reserve、driver 上限、preview、API、
运行页和验收指标。基础额度耗尽且无 grant 的第五次仍必须拒绝。

原配置续跑独立于预算按钮提供：优先原完整 profiles，经当前 capability 与预览确认；原模型不可用明确
停止，不回退默认配置。正常 paused resume 仍使用冻结 RunContract；结束后的新运行不能把旧授权/UI
草稿当作当前授权，也不能因创建新 parent 重新领取同一工作单元的基础额度。

## 7. CLI、API 与前端

- NODES 登记人物节点及其依赖、预算和恢复。公开枚举仍由后端唯一发布。
- 为 Stage4 登记确定性 --reaggregate 以及 A/B 的 --close-review，接入 operator、CLI、queue 和 Supervisor；
  零模型预览和实际执行都不触发 driver/probe/wire。
- 公共审阅/追加/执行只搬 opaque token 和业务决定；内部保留各身份域的精确证据，不让 UI 构建 hash。
- 扩展现有工作单元投影，分别展示生成和审阅总量、待处理、新生成、机械处理、采用、继承、失败/未知
  及原因，并展示基础额度、人工追加、累计使用与剩余。
- 恢复详情读取失败只使对应投影 unknown，不能阻断 pause/stop/drain；最终整书交付仍独立核验。
- 服务只写 _service，产物通过 CLI/ArtifactStore；所有接口与重启后的状态共享同一判定，不新增旁路缓存。
