# Stage6 开篇文案质量 A/B（2026-08-15）

## 结论

改版达到落地阈值：三本书的最佳实验候选匿名主编均分 8.78，当前定稿 4.88，平均提升
+3.90/10；最佳实验候选 3/3 获胜。

因此生产 Stage6 已采用本轮验证过的最小完整设计：

- 仍用一次生成调用产三候选；
- 给生成器原作文案、完整故事真相与逐章结构地图；
- 给生成器正文 `voice`、`surface_habits` 与开篇源章风格；
- 剧透不再判错，只看它是否增强阅读欲；
- 三策略改为 `source_architecture` / `payoff_preview` / `scene_punchline`；
- 语义审判改为实质矛盾检查 + 六维吸引力评分与匿名排序；
- 当前校准 `clear` 可直接作为自动依据；缺审、过期或 `UNVER` 仍不洗绿，但后续
  2026-08-16 裁决允许人以 actor / reason / 当前文本完整 SHA-256 绑定的
  `human_verification` 收口。当前或历史校准 `FAIL` 仍不可绕过，只能改字形成新主体。

没有改成“三次独立生成调用”；当前三候选仍在一次 API 请求中生成。

随后又补测了“单份直出”是否足以替代“一次请求生成三份再择优”。单份只在 1/3 本书中
胜过三候选最佳，均分 6.60，对三候选最佳 8.75，落后 2.15 分。因此保留三候选：它的
价值不是弥补输入缺失，而是给同一次创作提供机制搜索和抗采样失手能力。

## 授权与数据面

用户在本次测试前明确授权将相应材料发送至 DeepSeek API。每本发送的数据为：

- 原作文案；
- 当前重写开篇正文；
- `global_grounding` 中的完整人物、正典与弧线；
- `writer_context` 的全书逐章事件地图；
- `style_grounding` 的文案风格、正文 voice、surface habits、开篇逐章风格和 measurable；
- 当前定稿，仅在匿名比较阶段发送。

第一轮共完成 6 次 API 调用：3 次生成、3 次匿名主编评审。探针脚本为
`tools/probe_stage6_quality.py`；原始响应保存在本地
`outputs/stage6_quality_probe_20260815/`。

单份直出补测使用同一授权数据面，又完成 6 次 API 调用：3 次单份生成、3 次五方匿名
评审。补测脚本为 `tools/probe_stage6_single_quality.py`；响应保存在
`outputs/stage6_single_probe_20260815/`。

## 实验变量

实验组相对当前生产设计只改变质量相关信息与指令：

1. 原作文案从“只供校验、模型不可见”改为创作金标准；要求学钩子结构，不照抄措辞；
2. 从“开篇正文 + secret 摘要”改为“开篇正文 + 完整故事真相 + 全书逐章地图”；
3. 从抽象书级 voice 改为 voice + surface habits + 开篇逐章风格；
4. 撤销结局/高潮禁令；
5. 明确允许时间压缩、倒叙、重写台词和合成场面；
6. 只禁止改变身份、关系、关键因果、故事结果或新增改变理解的设定；
7. 强制最后一句落在具体欲望、危险、反转、笑点或行动，避免空泛反问。

匿名评审维度：

- `read_on_desire`
- `body_voice_match`
- `concrete_scene_and_specificity`
- `curiosity_and_payoff_promise`
- `hook_craft`
- `synopsis_penalty`
- `material_contradictions`

综合分按生产实现的固定权重回算：阅读欲 30% + 正文声线 20% + 具体场面 15% +
期待承诺 20% + 文案技法 15% − 摘要感 10%。

## 逐书结果

| 书 | 当前定稿 | 最佳实验 | 提升 | 匿名排序 |
|---|---:|---:|---:|---|
| 常春杜若 | 2.40 | 9.00 `scene_punchline` | +6.60 | scene → source → payoff → current |
| 收养三只反派幼崽后 | 7.10 | 8.70 `scene_punchline` | +1.60 | scene → source → current → payoff |
| 我教夫人斗渣夫 | 5.15 | 8.65 `scene_punchline` | +3.50 | scene → source → payoff → current |
| **平均** | **4.88** | **8.78** | **+3.90** | 实验最佳 3/3 获胜 |

`收养三只反派幼崽后` 的 `payoff_preview` 虽有 7.55 的原始质量分，却被排在当前定稿之后：
它虚构了会改变故事理解的“地下室血迹 / 陪坐牢”结果。这个反例直接决定了生产校验器的
边界：放开剧透与文案体裁自由，但必须保留实质矛盾硬闸。

## 单份直出补测

单份生成器拿到与三候选生成器相同的完整创作包，并被要求在内部比较
`source_architecture`、`payoff_preview`、`scene_punchline` 后只交付最强一条。它并不是
“信息缩水版”。评审仍按同一六维评分公式回算。

| 书 | 单份直出 | 三候选最佳 | 差值 | 五方匿名排序 |
|---|---:|---:|---:|---|
| 常春杜若 | 3.60 | 9.30 `scene_punchline` | -5.70 | scene → payoff → source → single → current |
| 我教夫人斗渣夫 | 8.80 | 8.45 `source_architecture` | +0.35 | single → source → scene → payoff → current |
| 收养三只反派幼崽后 | 7.40 | 8.50 `scene_punchline` | -1.10 | scene → current → single → payoff → source |
| **平均** | **6.60** | **8.75** | **-2.15** | 单份仅 1/3 获胜 |

三条单份直出都没有实质事实矛盾，所以失败原因不是校验器误杀，也不是剧透闸门，而是
创作搜索的方差：模型在只交一份时，有时会自行选中明显较弱的结构；显式产出三种机制后，
至少一条强候选的稳定性更高。这个样本量适合决定当前实现，不足以证明“三”是永远最优的
候选数；以后若要进一步缩短流程，应测试“模型内部生成多份、外部只返回语义评审选中的一份”，
而不是直接改成一次单份直出。

## 生产验收

对应实现测试覆盖：

- 新/旧 approach 的写入与只读兼容；
- 三策略各一次、候选文本不重复；
- 原作文案、全书真相、故事地图、surface habits 与开篇逐章风格真实进入 user prompt；
- 匿名标签覆盖、排序覆盖、矛盾证据逐字回查；
- 干净候选必须排在矛盾/uncertain 候选之前；
- 质量总分由代码固定计算；
- 缺审、旧审、过期、未覆盖与 uncertain 不洗绿；
- 单条坏候选不废掉整组三候选；全部坏或定稿坏才命中 HARD；
- `stage6.approve` 与 Stage7 付费改名/成书只接受两种可审计依据：当前校准 `clear`，
  或 actor / reason / 当前文本完整 SHA-256 绑定的 `human_verification`；当前或历史
  校准 `FAIL` 不能被普通批准绕过。
