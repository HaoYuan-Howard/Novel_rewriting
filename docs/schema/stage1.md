> ## ⚠ 三条贯穿本层的事实
>
> **① 承重的只有 `main_text.json` 与 `hook_copy.json` 的【字节形态】。**
> 下游每一份产物记的来源指纹都是对它们算的（实测三份 `_provenance.inputs`：
> stage2 ← `main_text.json`；stage3 ← `main_text.json` + `hook_copy.json`；
> **`partition_report.json` 一次都没作为 input 出现过**）。
> 改动这两份（哪怕只是重排一个键）会让全部下游产物被整批报成「陈旧」——**那是一次假回归**。
>
> **`partition_report.json` 不承重**：没有下游消费方，增字段、删字段、重排键都不会造成任何失配。
> 「逐字节等价」这条移植验收**只覆盖前两份**，不覆盖它。
> 〔此前本文写的是「新增信息一律只进 `partition_report`」——那条规矩反过来正好说明它不承重。〕
>
> **② 这两份产物在前端是【只读】的，stage1 切完就钉死。**（2026-08-10 裁决）
> 分章算法是确定性的：切错了就是算法错了，**去改算法、重跑**，不在界面上手改数据。
> ⇒ 载体不需要给它们任何编辑入口、不需要 `origin=human` 那套回写路径、
> 也不需要「人改过的版本 vs 机器产的版本」这层并存关系。
> ⇒ 一旦改了算法重跑，`main_text` / `hook_copy` 的字节变了，下游**本来就该**整批判陈旧——
> 那是真回归，不是假回归。
>
> **③ 本层所有字段的「prompt 消费方」一律是【无】——stage1 不进任何 prompt。**
> 这是判定结果，不是留空。只有 `main_text.text` 与 `hook_copy.text` 经下游读取后**间接**影响 prompt；
> `partition_report` 本身只被确定性代码读，**不再有人读**（S-03 屏已砍，见 §三开头）。

## 一、`main_text.json`

顶层是**数组**。**长度恒 ≥ 2**（`R-1.13`：只有一章的书入显式终态）。全语料 2~39 章。
**前端只读**（事实 ②）。

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `[].section_id` | `str` | 是 | 形如 `sec_0001`，长度恒 8 | **三源** |
| `[].chapter_ordinal` | `int` | 是 | ≥1，**连续无缺号无重号** | **三源** |
| `[].source_chapter_label` | `str` | 是 | **非空**。原文标号的字符串形式 | **三源** |
| `[].text` | `str` | 是 | 章正文 | **三源** |

### `source_chapter_label` 收窄成必填 `str`（2026-08-10 裁决）

原型代码写的是 `str(chapter_no) if chapter_no is not None else None`，类型上可空。
**收窄，并配一条后置条件**——否则「不可能为 `None`」只是一句注释。

- **结构论证**：`main_chapter` 段的 `chapter_no` 恒由 `CHAPTER_RE` 匹配出的数字行解析得到；
  解析不出数字的行根本不会被认成章节标记。这条路上没有产生 `None` 的分支。
- **实测**：全语料 163 本共 **2559 个 `main_chapter` 段，`chapter_no` 为 `None` 的 0 个**。
- **后置条件**：写盘前逐段断言 `chapter_no is not None`。
- ⚠ **`None` 确实存在，只是不在这个字段上**：163 个 `hook_copy` 段的 `chapter_no` 全是 `None`
  （163/163）。但 hook 段不进 `main_text.json`。**这两件事常被混着读**，
  「盘上见过 `None`」于是被当成「这个字段可空」的证据——不是。

> ⚠ 顺带把另一件常被混读的事分开：**重号是常态，`null` 是零样本。**
> 语料里第一本书的前 5 章标号实测就是 `[1, 2, 3, 4, 4]`——有重号，但没有 `null`。

### 两个 ordinal 的区别（本层最容易读错的地方）

| | 含义 | 全语料实况 |
|---|---|---|
| `source_chapter_label` | **原文标号，原样保留** | **28/163 本有重号**（单本最多 16 个重号）· **12/163 本有缺号** |
| `chapter_ordinal` | **修正后的阅读序** | 恒连续、无重复。**下游一律 key 在它上面** |

> **`R-1.4`（断号/重号/严格递增逐项记账）的记账落点就是 `source_chapter_label` 本身。**
> 「原样保留 + 另给一个修正序」这一对字段共存，就是记账；
> 派生出来的三个汇总（`chapter_no_gaps` / `_duplicates` / `_strictly_increasing`）
> 已从 `partition_report` 删除，**改由校验器现算**——它们是同一份信息的第二副本，
> 而 `main_text` 只读钉死，现算与落盘永远同值。

## 二、`hook_copy.json`

开篇文案段——第一个正文章标记之前那段无标题内容。

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| （顶层） | `obj` | 是 | **不可为 `null`**，见下 | **裁决** |
| `section_id` | `str` | 是 | 恒 `sec_0001` | **三源** |
| `text` | `str` | 是 | 非空。全语料长度 57 ~ 414 | **三源** |

### ⚠ 文案段为空 = 显式终态，不是一个合法分支（2026-08-10 裁决）

原型代码写的是 `hook_copy = {...} if hook else None`，于是类型上顶层可空。
**这条分支作废**：认不出文案段时 **stage1 直接入显式终态，不写任何产物、后续 stage 一步都不跑**。

理由不是「163 本都非空所以大概不会空」——那是拿样本当结论。理由是**下游三层都要它**：

| 层 | 怎么用 | 空了会怎样 |
|---|---|---|
| stage3 | `_provenance.inputs` 记着 `stage1/hook_copy.json`；产出 `hook_style` 七项（`HOOK_KEYS`）+ `hook_copy_text` | 文案写法七项无源可量 |
| stage6 | 三候选文案参照原作文案段的写法与收尾形态（`R-9.4`） | 参照物没有 |
| stage7 | 成书 = `文案 \n\n 1 \n\n 第1章正文 …`（`R-10.8`） | 成书第一段是空的 |

⇒ **让它带着一个 `null` 往下跑，等于把一次本该在 0 成本层红掉的失败，推迟到花钱之后。**

> #### 连带：`R-4.6` 的分支在本裁决下不可达
> `REQUIREMENTS.md` `R-4.6`（`HARD`）写着「无开篇文案段时该字段为空并**显式报警，不编造**」。
> 那是在「hook 可以为空」的前提下写的。现在 stage1 就把这种书挡在门外了，
> stage3 不可能遇到无文案段的输入。已同步改成「由 stage1 阻断，本层不可能遇到」。

> #### ⚠ 此前本文写着「下游抽取从不消费它，只给人看」——**那是错的**
> 实测 `stage3_style.json` 的 `_provenance.inputs` 里就有 `stage1/hook_copy.json`，
> 产物里还有 `hook_style`（七项）与 `hook_copy_text`。
> 这处错误值得记一笔：它正是「盘上产物这一源能纠正文档」的实例——
> 按错的那句读，本节的顶层 `null` 会被当成一个无关紧要的边角分支放过去。

## 三、`partition_report.json`

**9 个字段。** 演化：原型 24 −13（§3.5 的删除清单）= 11 → +2（§3.6 对照屏）= 13
→ **加 stage0 后搬走 5**（`dropped[]` + 四个摄入记账字段）= 8 → **+1**（新增 `input_sha1`，§3.1）= **9**。
〔此前这里写的是「再搬走 4」，少算了 `dropped[]`、也没算新增的 `input_sha1`——
两个错互相抵消，总数 9 是对的而推导是错的。**数值要复算，包括自己刚写下的那个。**〕

两个消费方：

| 谁 | 读什么 | 干什么 |
|---|---|---|
| **校验器** | 全部 | `R-1.3` / `R-1.5` / `R-1.12` / `R-1.13` / `R-1.14` 的判据 |
| **S-03 原文↔切分对照屏** | `hook_span` · `chapter_spans` · `input_sha1` | 在 `clean_text` 上把「文案 / 各章」标出来。<br>**被剔除段的高亮来自 `stage0/removal_report.json` 的 `removed[].span`**，画在原始 txt 上 |

**报告的字段本身仍然不上屏**——上屏的是它记的那些**区间**。
`warnings[]` 的落点是 S-13 校验报告的 `stage1` 那一份（`info` 级结论），不是 S-03。

键的插入顺序按下表固定。**这不再是为了逐字节验收**（那条验收只覆盖前两份，见事实 ①），
而是为了两次跑出来的产物能直接 `diff`。

### 3.1 两个指纹

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `source_sha1` | `str` | 是 | **原始 txt** 的 sha1，从 stage0 透传。只用于追溯，本层不判它 | **三源** |
| `input_sha1` | `str` | 是 | **本层输入**（`stage0/clean_text.txt`）的 sha1。**[HARD]** 对不上即阻断 | **设计** |

**这两个是 `R-0.6` 的下半段。** 加了 stage0 之后，本层的输入不再是原始 txt——
只记一个指纹，「有人换过原始小说」和「有人改过 stage0 的剔除结果」就分不开了，
而这两件事的处置完全相反（前者从头重跑，后者**是人有意为之、必须保住**）。

> #### 搬去 stage0 的四个摄入记账字段
>
> `original_filename` / `original_path` / `source_encoding` / `text_norm` 现在记在
> `stage0/removal_report.json` 里。**谁读原始 txt，谁记它的元数据**——
> 本层的输入恒 utf-8 / `\n`，没有编码可记、没有归一化口径可记。
>
> ⚠ `source_encoding` 的取值面那条警告跟着搬到 `stage0.md`：全语料 163 本只有 `utf-8`，
> 而候选集是 `utf-8-sig` / `utf-32` / `utf-16` / `utf-8` / `gb18030` **五个，另外四个零样本**。
> **样本再多也补不出没发生过的分支**——这句话本身没变，只是换了一层说。

### 3.2 规模与分章

| 字段 | 类型 | 必填 | 取值面 / 范围（全语料 163 本） | 证据 |
|---|---|---|---|---|
| `total_code_points` | `int` | 是 | 8088 ~ 41224。**[HARD]** 与复算的原文长度交叉核对 | **三源** |
| `body_code_points` | `int` | 是 | `[0, body_limit)` = 文案 + 正文，即保留下来的部分 | **三源** |
| `num_chapters` | `int` | 是 | **≥ 2**（`R-1.13`）。全语料 2 ~ 39。**[HARD]** 必须等于 `main_text` 的长度 | **三源** |
| `has_end_marker` | `bool` | 是 | `True`×46 · `False`×117。**[HARD]** `R-1.14` 的第三段只在它为 `True` 时非空 | **盘·码** |

**`body_ratio` 已删**，而且**判它的那条判据也搬去了 stage0**（`R-0.9`）。
本层不再剔除，切点只由完结标记决定 ⇒ `body_ratio` 恒 ≈1.0（差的就是那一行 `（全文完）`）。
把 `< 0.60` 留在这里就是**一盏保证会亮的绿灯**：报告照常输出，只是不再携带信息。
⚠ `total_code_points` / `body_code_points` **仍然留着**——它们不是为了算这个比值，
是 `R-1.3` 的交叉核对（复算的输入长度对不对）和 `R-1.14` 的三段记账要用。

> #### ⚠ `num_chapters` **必须由分章那一趟独立数出来，不许写成 `len(sections)`**
>
> 这是它没被一起删掉的**唯一**理由。`R-1.5`（`HARD`：章数必须等于章表长度）防的是
> 「两行式番外造出一个被跳过的空章」——**认出 9 章、只写进去 8 条**。
> 若 `num_chapters` 取自 `len(main_text)`，这条判据就成了恒等式，**永远不可能红**，
> 而它要抓的那个 bug 会原封不动地活下来。
> ⇒ 载体阶段要配一条后置条件把这件事钉住：产地一侧的计数来源与写盘来源**必须是两条路**。

> #### `num_chapters < 2` → 显式终态（`R-1.13`，2026-08-10 裁决）
>
> 只有一章的「书」不接受重构。**不带字数阈值**——原型那条是「≤1 章且 >3000 字才告警」，
> 而语料里最短的书也有 8088 字，那个阈值从来没起过作用；留着它只会让判据看起来标定过。
>
> **影响面实测：163 本里正好 10 本**（10670 / 11608 / 12357 / 14924 / 15516 /
> 15648 / 15785 / 18912 / 24862 / 28223 字），全部拒收。
> 核过原文：它们确实只有一个 `1` 标记、之后再没有数字行——**真·未分章，不是漏切**。
> ⇒ 这也是本层告警量骤降的原因：原型全语料 11 条告警里，**10 条是这一类**。
> 一条报了 10 次的告警，报的其实是一件该拒收的事。

### 3.3 非正文剔除 —— **已整节搬到 stage0**

`dropped[]` 及其 8 个子字段现在是 `stage0/removal_report.json` 的 `removed[]`。
判据标定的那组数（**命中 27/163 本、34 条真标记、0 假阳**）、
`core` 长度的四段带状结构、34 条真样本的形态清单——全部跟着搬，见 `stage0.md` §2.2。

**本层剩下的只有一条断言**（`R-1.7`）：

```
在 stage0 已批准的 clean_text 里，如果还认出任何非正文标记 → 显式终态
```

**它不切任何东西。** 判据与词表仍与 `R-0.1` 同源（`contracts/invariants.py` 只有一份），
但角色完全变了：

| | 搬之前（stage1 剔除） | 搬之后（stage1 断言） |
|---|---|---|
| 命中时做什么 | **切掉标记行之后的全部内容** | **报错，不写任何产物** |
| 判据错报一次的代价 | 静默吃掉半本书 | 一个假警，回 stage0 看一眼 |
| 正确性谁来验 | 没人（`R-1.8`「验不了」） | 不需要验——它不产生任何不可逆的后果 |

> #### ⚠ 别把这条断言当成盲区的解药
>
> 它是**同一套判据的重放**，所以它只能抓「判据本来就认得、但 stage0 没删」这一类
> （例如人在审阅时误删了一条 machine 记录）。
> **判据本来就不认得的（盲区①：番外用纯数字章节标记写），它同样抓不到。**
> 那一类只有 `R-0.3a` 的人工闸门能挡。
>
> 也正因为如此，这条断言**几乎必然是零命中的**——它和 `R-1.14` 一样，
> 属于「新加的、从没响过的判据」。合成样本要跟上（见 §六）。

### 3.4 可信度层

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `warnings` | `obj[]` | 是 | **动态**。每条带 `kind`（`STAGE1_WARNINGS` 之一）与人读的一句话 | **三源** |

**落点已定**：`warnings` 转成 **S-13 校验报告里 `stage1` 那一份的 `info` 级结论**。
S-03 屏已砍，这是它唯一的出口——`R-1.9`（不静默、不自动修正、不硬报错）靠这条路兑现。
写进文件没人看才是真的静默。

⚠ **认告警一律用 `kind`，不许用措辞前缀。** 措辞不再承重（逐字节等价不覆盖本份产物），
随时可改；拿字符串开头去认告警的代码会在第一次改文案时静默失效。
`kind` 的闭合枚举在 `contracts/invariants.py::STAGE1_WARNINGS`。

### 从 6 类砍到 1 类

⚠ **此前本节写的是「砍到 4 类」并把 `early_cut` / `drop_ratio` / `long_marker` 列在这里**——

### 3.5 删掉的 13 个字段（2026-08-10 裁决）

留下来的判准只有一条：**这条信息能不能 0 成本重新算出来。**
stage1 全程不调 LLM、算法确定性、`main_text` / `hook_copy` 只读钉死（事实 ②）——
所以凡是能从这两份产物、目录名或原文现算的，落盘就只是抄第二份，
而两份同源数据只会带来一种新问题：它们哪天不一致了，你不知道该信谁。

| 删掉的字段 | 为什么能删 |
|---|---|
| `platform` | **用户裁决：不需要这个字段。** 全语料 `'FQ'`×43 / `null`×120，没有第二个平台值，无人消费 |
| `source_id` | = 目录名。`R-1.10` 保证目录名能被同一把尺子解析回来**且是不动点** |
| `title` | 同上。前端书名取自 `dirname`（实测 `novels.json` 就是这么来的），不是取自本报告 |
| `num_sections` | = `len(main_text) + 1`（文案段恒存在，见 §二） |
| `body_ratio` | = `body_code_points / total_code_points` |
| `chapter_nos` | = `[int(s.source_chapter_label) for s in main_text]` |
| `chapter_no_gaps` | 由上式现算 |
| `chapter_no_duplicates` | 由上式现算 |
| `chapter_nos_strictly_increasing` | 由上式现算 |
| `hook_copy_present` | **死字段**：文案段为空已是显式终态（§二），它恒为 `True` |
| `hook_copy_code_points` | = `len(hook_copy.text)` |
| `dropped_code_points` | = `sum(dropped[].code_points)` |
| `notes` | 逐字固定的 3 条静态说明。**它是常量不是数据**，而唯一的读者（人）已经不读这份文件了。<br>常量的落点是代码，不是每本书的产物里抄一遍 |

**这解决了「`notes[]` 算不算 schema 的一部分」那条待决**：算常量，不落盘。
此前挡着不敢删的理由是「会破坏逐字节等价」，而那条验收本来就不覆盖这份产物。

#### `notes[3]` 逐条的下落

删一份「说明文字」之前得先确认它说的事在别处还成立。三条各自查过：

| 原文（逐字） | 它说的事现在记在哪 |
|---|---|
| `N1 is read-only; typo unification (e.g. 徐喻朗/徐瑜朗) is deferred to N2 entity resolution.` | 前半（只读）→ 事实 ②。**后半（错别字/异体人名不在本层统一，留给 stage2 实体消解）此前在全仓只有这一处记载**，已补进 `REQUIREMENTS.md` `R-1` 节 |
| `chapter_no is the raw source label … downstream nodes should key off chapter_ordinal, not chapter_no.` | §一「两个 ordinal 的区别」，讲得比它细 |
| `正文 = [0, 第一个非正文标记)。番外/后记/尾声/作者有话说 的正文体不落盘…` | `R-1.7` + §3.3 |

⇒ 三条里有 **1 条半**是重复的、**半条**是唯一记载。那半条已经搬走，剩下的可以删。
**这就是「静态文案」该怎么删**——不是因为它是常量所以无所谓，是因为逐条确认过它没有独占的信息。

⚠ **反向提醒**：以后想往 stage1 加一条信息时，先问「它能不能现算」。
能现算就别加——本节这 13 个字段全是当初「顺手记一下」记进去的。

### 3.6 为对照屏加回的两个字段（2026-08-10）

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `hook_span` | `[int,int]` | 是 | 文案段在归一化原文上的码点半开区间。恒 `[0, x)` | **新增** |
| `chapter_spans` | `[[int,int], …]` | 是 | 逐章，**长度恒 == `num_chapters`**，顺序即 `chapter_ordinal` | **新增** |

**为什么不能加进 `main_text.json`。** 那是最自然的位置——span 是章的属性。
但改 `main_text` 的字节形态会让**全部下游产物被整批判成陈旧**（事实 ①），那是一次假回归。
`partition_report` 不承重，加字段没有任何代价。**「新增信息一律只进 `partition_report`」
这条老规矩，第一次真正派上用场就是这里。**

**为什么它们不算「能现算所以该删」。** 重跑分章确实能算出同样的 span——
但那样一来，对照屏画的就是**分割器自己和自己对账**，看不出任何问题。
拿**落盘时记下的** span 去比**此刻盘上的**原文，才是一次真的核对：
原文被换过、被截断、编码变了，都会在屏上直接错位。⇒ 它们属于「有消费方且不可替代」那一类。

**依赖：源 txt 必须还在 `original_path`。** 三种降级，**必须能区分**：

| 情况 | 屏上说什么 |
|---|---|
| 文件在、`source_sha1` 对得上 | 正常对照 |
| 文件不在了 | 「原文不在原处，**无法对照**」——是「不知道」，不是「没问题」 |
| 文件在但 sha1 对不上 | 「文本变过，span 已失效」——`R-1.3`（本层输入）与 `R-0.14`（原始 txt）在这里现形 |

⚠ **这不违反「番外体在盘上不留副本」那条裁决。** 对照读的是 `Novel_data` 里的**源文件**，
不是在 `Output/` 里再存一份。番外体从来就在源文件里——裁决说的是产物目录不留副本。

### 一条**改写掉**的不变量 → `R-1.14`（三源冲突，2026-08-10 实测并裁决）

`CONTRACTS.md` §1.5.2 写着：

> `dropped[]` 的校验 = **与 `body_code_points` 之和 == `total_code_points`**

**它在 42/163 本上不成立。** 缺口恒为 **1~7 码点**，全部落在有完结标记的书上：

| 缺口 | 本数 | 那几个码点是什么 |
|---|---|---|
| 6 | 15 | `（全文完）\n` |
| 5 | 14 | 同类 |
| 4 | 2 | `（完）\n` |
| 3 / 7 / 1 | 15 / 3 / 1 | 同类变体 |

按 `(不成立?, 有完结标记?)` 分组：`(True, True)` **42** · `(False, True)` 4 · `(False, False)` 117。
⇒ **只有「切点来自完结标记、且其后没有非正文标记」时才不成立**——
那一行 `（全文完）` 既不在正文里（`body_limit` 停在它之前），也没进 `dropped`（它不是非正文标记）。

**三件事同时成立**：契约这么写了 · 实现不满足 · **`check_partition` 根本没在查**
（它只查 `len(text) == total_code_points`）。

**处置是改契约，不是改数据**：按契约去修，就得把「（全文完）」硬塞进正文或塞进 `dropped`——
两个都是假的。**「一条判据开始报错时，先问是数据错了还是判据把合法情况排除在外了」——
判据错的信号就是：按它去修数据会让产物变得更差。**

正确的表述是**三段**而不是两段：

```
total_code_points = body_code_points + tail
tail := clean_text[body_limit:]          # 加 stage0 之后没有 dropped 了，第二段恒为空
```

**裁决：补成真判据 `R-1.14`，而且比原契约更强。**「三段」只是把缺口记下来，
真正能查的是**第三段里到底是什么**：

```
R-1.14：tail == '' 或 tail.strip() 匹配 END_RE
```

跑过了——**163/163 成立，0 本违反**。分布：

```
121 本  ''              14 本  '(全文完)'      9 本  '(完)'       7 本  '（全文完）\n'
  6 本  '全文完'          2 本  '（完）\n'      2 本  '(正文完)\n\n'  1 本  '(全文完)\n\n'  1 本  '完'
```

它查的正是**「正文里有没有漏进第三种东西」**——切点之后、第一个番外标记之前，
只允许有一个完结标记行，别的一律算违规。顺带**接管了「完结标记之后还有内容」
那条从没触发过的 warning**，把它从 `INFO` 升成 `HARD`。

顺序决定结果，两个边界形态各有真样本，也各有一份合成样本（§六）：

| 形态 | `tail` | `dropped` | 全语料 | 合成样本 |
|---|---|---|---|---|
| 完结标记在前、番外在后 | `'(全文完)\n\n'` | 非空 | **3 本** | `end_marker_then_fanwai` |
| 番外在前、完结标记落在番外体里 | `''` | 非空 | **4 本** | `end_marker_inside_fanwai` |
| 只有完结标记 | `'（全文完）\n'` | 空 | **42 本** | `end_marker_tail` |

⇒ **`has_end_marker` 因此留在 §3.2**：第三段只在它为 `True` 时非空，它是这条判据的前件。

### 验不了的那条 —— 以及它现役的闸门

**剔除的正确性验不了**（`R-1.8` / `B-20`）：「这一段到底是不是番外」没有结构不变量可查，
而正文体已按契约丢弃、盘上不留副本。所以每本都要打印一条
`[????] 剔除的正确性：本层验不了`——**「没报违规」与「根本没在查」必须能区分**。

**判据查不了，闸门是人**：S-03 原文↔切分对照屏（§3.6）。这不是「退而求其次」，
它是这条需求现役的**唯一**闸门。此前 S-03 只剩章表时，人能看出漏章、
**看不出「第 7 章其实是番外」**——那个缺口已由对照屏补上。

#### 判据的盲区（2026-08-10 实测，说清楚闸门在挡什么）

先说判据在这批语料上的表现。扫了一遍**留在正文里、仍含四类关键词的行**：

| | 结果 |
|---|---|
| 命中 | **6 本 / 163，共 7 行** |
| 逐行核对 | **7 行全部是正常叙述，0 条真漏切** |
| 样本 | 「前厅的宴席似乎已经接近尾声。」·「节目的尾声。」·「拍摄到了尾声，还剩一组落日照片没有拍。」 |

⚠ 其中 **4 行长度 ≤30 且含「尾声」**。`后记`/`尾声` 如果用「包含」而不是**全等**匹配，
这 4 本每一本都会被从中间砍掉——**这组数据是全等匹配那个设计的实测辩护**。

**但「扫不出来」不等于「没有」。** 三个盲区，逐个查过能不能用模式匹配补掉：

#### 盲区 ①：番外用纯数字章节标记写（`9` 换行、内容是番外）

**它和正常章节长得一模一样。** 找过两个可能的结构信号：

| 信号 | 实测 | 结论 |
|---|---|---|
| **完结标记之后还有内容** | 有完结标记的 **46/163** 本；这类内容一律落在 `body_limit` 之外 | ✅ **已经用上了**。番外若在完结标记之后，要么被切掉、要么被 `R-1.14` 拦下 |
| **章号回退重启**（正文 1..N 后又从小号开始） | 全语料只有 **3 本**有回退，回退幅度分布 `{1:1, 2:1, 4:1, 11:1}` | ❌ **0/3 精确率，不能用** |

回退那 3 本逐本看过内容，**没有一本是番外**：

```
小三争夺战    [1,2,3,1,7,8,…,12,1,1,1,…]  回退后是正常剧情（那个反复出现的「1」是误判成章号的固定标记）
任他明月      [1,2,3,4,5,4,5,6,…]         回退后是正常剧情（标号写错了一个）
女a她也不想的 [1,2,3,4,5,5,1]             回退后是正常剧情（末章标号写成了 1）
```

⚠ 最后那本尤其值得记：回退 4、发生在全书 **86%** 处——**「幅度大 + 位置靠后」正是我预设的强信号，
而它是假的**。按这个信号去切，会砍掉一本书的最后一章正文。
⇒ **模式匹配在这个盲区上没有余量可捡**，唯一的结构信号（完结标记）早就在用了。

#### 盲区 ②：标题用四类之外的词——**这个可以靠加枚举补**

`NONBODY_KINDS` **是开放表，遇到新写法就加**。但加之前必须过
`tools/probe_nonbody_word.py` 那道假阳闸门（流程见 `R-1.7`）——
剔除是破坏性的，而词表只会单向增长，**加错了没有任何东西会提醒你**。

已经跑过的候选词：

| 词 | 正文里含它 | `core` 全等 | 判定 |
|---|---|---|---|
| `外传` | **26 行** | **0** | ✅ 安全。⚠ 那 26 行是「不外传的秘药」「**门外传**来脚步声」——**用包含匹配会毁掉 26 处** |

| `小剧场` | 1（「日本小剧场里进货」） | 0 | ✅ 安全 |
| **`正文完`** | 1 | **1**（`(正文完。)`） | ❌ **不要加**：它已经是**完结标记**（`END_MARKER_WORDS`），走的是另一条路 |

⇒ 结论：**加枚举是可行的，而且大多数候选词零风险**——因为 `后记`/`尾声` 那条
「必须全等匹配」的设计已经把假阳挡在外面了。真正的风险只有两种，闸门各查一遍：
词在正文里以整行出现（直接误切）· 词与完结标记撞车（两条路记同一段）。

#### 盲区 ③：新上传的书是未知分布

163 本的干净**不能外推**，这条补不掉。

## 六、合成样本

**18 份**，落在 `tests/fixtures_ingest.py`，由 `tests/test_ingest_fixtures.py` 消费。
〔文件名是 `ingest` 不是 `stage1`：加 stage0 之后这批样本**横跨两层**——
`COVERS` 里的 4 组是 `stage0/解码`×2 · `stage0/编码候选`×4 · `stage0/剔除与可疑项`×7 · `stage1/分章`×5。〕
**每一份都拿原型的分割器实跑核对过**，声明的分支与实际走的分支逐条一致。

**不提交 `.txt` 文件，从源文本确定性生成。** 样本要覆盖 UTF-16 / UTF-32 / GB18030 / 带 BOM
这些形态，把它们当二进制提交进仓，编辑器、`core.autocrlf`、任何一次「顺手格式化」
都可能悄悄改坏它们——而**样本被改坏时测试会照常变绿**（它验的是解码结果，不是文件字节）。

| 分组 | 样本 | 守的分支 |
|---|---|---|
| 显式终态 | `no_hook` · `single_chapter`（stage1）· `decode_bom_lies` · `decode_nul`（**stage0**） | `R-1.12` · `R-1.13` · `R-0.11`×2 |
| 可疑项 | `early_cut` · `drop_ratio_only` · `long_marker_silent_band` · `long_marker_not_cut` · `noisy_duplicate` | 四类 `kind` + 带状结构两侧 |
| 闭合枚举 | `kind_author_note` | 四类 `kind` 里唯一零样本的那支 |
| `R-1.14` | `end_marker_tail` · `end_marker_then_fanwai` · `end_marker_inside_fanwai` | 第三段的三种形态（全部 PASS） |
| `R-1.14` 反例 | **`r114_violation`** | **唯一会让新判据变红的样本**，见下 |
| 编码 | `enc_utf8_sig` · `enc_utf16` · `enc_utf32` · `enc_gb18030` | 五个候选里的四个零样本 |

> #### ⚠ 新判据自己也可能是一条零样本分支
>
> `R-1.14` 在全语料 163 本上 **163/163 通过**。而「163/163 通过」与「根本没在查」
> **在报告上长得一模一样**——这正是本项目反复踩过的那个坑。
> 它接管的那条 warning（完结标记之后还有内容）在语料上同样是 0 命中，
> ⇒ **这个形态只可能靠合成样本触发**。
>
> `r114_violation`：完结标记之后、番外之前夹一段散文。实跑确认
> `tail = '（全文完）\n\n这段既不是正文也不是番外，它就不该在这儿。\n\n'` → 判 FAIL。
> 对照屏上它渲染成一个 **`hole` 段——`hole` 非空就是这条判据的可视形态**。
>
> 测试 `test_every_hard_judge_this_layer_added_has_a_violating_sample` 盯着这件事：
> **本层每新加一条 HARD 判据，就必须有一份会让它红的样本。**
> 「见过它通过」不是证据，「见过它红一次」才是。

测试分两半：

- **上半今天就跑**（已绿）：样本自洽、覆盖率不许退化、带状结构三个阈值的关系、
  `marker_of_length` 精确到码点。这一半**不需要 stage1 的实现**——它验的是样本集这份资产本身。
- **下半 `skip`**，等 stage1 落地自动转成真断言。⚠ 是 `skip` 不是空断言：
  **「跳过」与「通过」必须能区分**，`pytest -rs` 会把「还没接」打出来。

⚠ **覆盖率不是 `len(CASES)`。** `COVERS` 那张表才是机器可读的覆盖声明，
并且有三条测试盯着它：每个 `warnings` id 都要有样本、每个 `kind` 要么有合成样本
要么有真实语料样本、每个编码候选都要有样本。**哪天某一类没样本了，测试会红，
而不是悄悄退回零样本。**
