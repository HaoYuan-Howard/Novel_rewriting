# stage1 产物 schema

摄入 + 分章 + 非正文剔除。**这一层不调 LLM。** 对应需求 `R-1.1` ~ `R-1.11`。

读法（证据列的取值、为什么三源合并）见 `_README.md`。**载体留空，等骨架。**

> **样本面：全语料 163 本**（不是盘上那 3 本）。
> 2026-08-10 把分章的纯函数在全语料上跑了一遍，**不落盘**——
> `build_sections` / `build_report` 是纯的，拿样本不需要写文件，
> 而盘上那 3 本已有完整 stage1→stage7 产物，为几个样本去覆盖它们不划算。
> 于是此前「盘上零样本」的两块（`dropped[]` / `warnings[]`）都有真数据了。

三份产物：

```
stage1/main_text.json         [ {section_id, chapter_ordinal, source_chapter_label, text} ]
stage1/hook_copy.json         {section_id, text} | null
stage1/partition_report.json  {…24 个字段…}
```

> ## ⚠ 两条贯穿本层的事实
>
> **① `main_text.json` 与 `hook_copy.json` 的【字节形态】是承重的。**
> 下游每一份产物记的来源指纹都是对它们算的；改动它们（哪怕只是重排一个键）
> 会让全部下游产物的指纹失配，被整批报成「陈旧」——**那是一次假回归**。
> 新增信息一律只进 `partition_report.json`。
>
> **② 本层所有字段的「prompt 消费方」一律是【无】——stage1 不进任何 prompt。**
> 这是判定结果，不是留空。只有 `main_text.text` 的正文经下游抽取后**间接**影响 prompt；
> `partition_report` 本身只被确定性代码与人读。

## 一、`main_text.json`

顶层是**数组**。全语料每本 1~39 章。

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `[].section_id` | `str` | 是 | 形如 `sec_0001`，长度恒 8 | **三源** |
| `[].chapter_ordinal` | `int` | 是 | ≥1，**连续无缺号无重号** | **三源** |
| `[].source_chapter_label` | `str \| null` | 是 | 原文标号的字符串形式 | **三源** |
| `[].text` | `str` | 是 | 章正文 | **三源** |

**`source_chapter_label` 的 `null` 在结构上不可达**：代码写的是
`str(chapter_no) if chapter_no is not None else None`，而 `main_chapter` 段的 `chapter_no`
恒由章节标记行解析得到、不可能是 `None`。
⇒ 类型上可空、结构上不可能——**载体阶段要决定**：跟着代码写成可空，还是收窄成必填。
收窄是对的，但要配一条后置条件，否则「不可能」只是一句注释。

### 两个 ordinal 的区别（本层最容易读错的地方）

| | 含义 | 全语料实况 |
|---|---|---|
| `source_chapter_label` | **原文标号，原样保留** | **28/163 本有重号**（单本最多 16 个重号）· **12/163 本有缺号** |
| `chapter_ordinal` | **修正后的阅读序** | 恒连续、无重复。**下游一律 key 在它上面** |

## 二、`hook_copy.json`

开篇文案段——第一个正文章标记之前那段无标题内容。**下游抽取从不消费它，只给人看。**

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| （顶层） | `obj \| null` | — | **整份可以是 `null`**（这本书没有文案段） | **仅代码** |
| `section_id` | `str` | 是 | 恒 `sec_0001` | **三源** |
| `text` | `str` | 是 | 长度 57 ~ 414 | **三源** |

> ⚠ **顶层 `null` 在全语料 163 本上仍是零样本**（`hook_copy_present` = `True`×163 / `False`×0）。
> 它只在代码里成立：`hook_copy = {...} if hook else None`，
> 而 `hook` 存在的条件是「第一个章节标记行之前有非空内容」——几乎每本都有。
> ⇒ **别把「163 本都非空」读成「不可能为空」**：证据来源仍是**仅代码**，
> 载体不能把它定成必然非空。

## 三、`partition_report.json`

24 个字段。**键的插入顺序是承重的**——移植验收用逐字节比对，重排不会报错，
只会让那条验收从此永远失败。下表按代码里的写入顺序排。

> ### ⚠ `CONTRACTS.md` 只覆盖了其中 **15/24**
>
> 另外 9 个（`title` 在 §1.5 内 0 次，`platform` / `num_sections` /
> `chapter_nos_strictly_increasing` / `has_end_marker` / `hook_copy_present` /
> `hook_copy_code_points` / `dropped_code_points` / `notes` **全文 0 次**）
> **只活在代码和盘上**。
> 这不是「契约写漏了几个字段」——**它本来就不是完整 schema，它是「有消费方或有判据的字段」表**。
> 拿它当 schema 用会直接丢掉 9 个字段。

### 3.1 身份与摄入记账

| 字段 | 类型 | 必填 | 取值面 / 范围（全语料 163 本） | 证据 |
|---|---|---|---|---|
| `source_id` | `str` | 是 | 文件名尾部的 `_<数字>`；**没有这个尾巴时退化成书名本身**（13/163 本） | **三源** |
| `title` | `str` | 是 | 剥掉平台前缀与 id 之后的书名 | **盘·码** |
| `platform` | `str \| null` | 是 | **`'FQ'`×43 · `null`×120**。全语料只出现过**一个**平台值 | **盘·码** |
| `original_filename` | `str` | 是 | | **三源** |
| `original_path` | `str` | 是 | 绝对路径。**文件被移走时是「不知道」，不是「不匹配」** | **三源** |
| `source_sha1` | `str` | 是 | 归一化后正文的 sha1（40 位十六进制）。**[HARD]** 对不上即阻断 | **三源** |
| `source_encoding` | `str` | 是 | **`utf-8`×163**。取值面见下方警告 | **三源** |
| `text_norm` | `str` | 是 | 归一化口径的版次，恒 `v1:bom+crlf`。**[INFO]** 与当前代码不同则 sha1 不可比 | **三源** |

> #### ⚠⚠ 这三个字段的取值面，**观察给不出**
>
> | 字段 | 盘上 3 本 | 全语料 163 本 | 真正的取值面从哪来 |
> |---|---|---|---|
> | `platform` | 3/3 `'FQ'` | **120 本 `null`**，有值的只有 `'FQ'` 一种 | 代码：任意字母前缀，或无 |
> | `source_id` | 3/3 19 位数字串 | **13 本退化成书名** | 代码 |
> | `source_encoding` | `utf-8` | **仍然只有 `utf-8`** | **只能从代码来**：候选集是 `utf-8-sig` / `utf-32` / `utf-16` / `utf-8` / `gb18030` 五个，另外四个**全语料零样本** |
>
> 只按盘上 3 本定 → `platform: str` 必填非空 → **在 74% 的语料上崩掉**。
> 扩到 163 本修好了 `platform` 和 `source_id`，但**修不好 `source_encoding`**——
> 这批语料恰好全是 UTF-8。**样本再多也补不出没发生过的分支。**

### 3.3 非正文剔除的记账

**命中 27/163 本，共 34 条**（这与判据标定时记的「命中 27 本 / 34 条真标记 / 0 假阳」逐数对上）。

番外体**在盘上不留任何副本**（用户裁决：彻底抛弃，不是「纳入别处」），
所以 `dropped[]` 是**唯一**能核对「切对了没有」的东西——剔除是破坏性的，一次假阳会静默吃掉半本书。

| 字段 | 类型 | 必填 | 取值面 / 范围（34 条真样本） | 证据 |
|---|---|---|---|---|
| `dropped` | `obj[]` | 是 | 27/163 本非空，单本最多 4 条 | **三源** |
| `dropped[].kind` | `str` | 是 | 闭合枚举 4 类；实际命中 **`番外`×31 · `后记`×2 · `尾声`×1** | **三源** |
| `dropped[].marker_line` | `str` | 是 | 标记行原文（strip 后），长度 **2 ~ 18** | **三源** |
| `dropped[].line_no` | `int` | 是 | 541 ~ 2143（1 起） | **三源** |
| `dropped[].span` | `[int,int]` | 是 | 码点半开区间，恒 `span[0] < span[1]`（34/34） | **三源** |
| `dropped[].code_points` | `int` | 是 | 94 ~ 3290 | **三源** |
| `dropped[].head_preview` | `str` | 是 | **恒 80**（上限就是 80，34/34 都顶满） | **三源** |
| `dropped[].tail_preview` | `str` | 是 | **恒 40**（同上） | **三源** |
| `dropped_code_points` | `int` | 是 | `sum(dropped[].code_points)` | **盘·码** |

> ⚠ **`作者有话说` 这一类在全语料 163 本上零样本**。枚举有 4 个值，实际只见过 3 个。
> 别把它当成「这一支已验证」。

> ⚠ **`marker_line` 长度 2~18 与「真标记最长 17」不冲突**：
> 17 说的是 `core`（剥掉前导括号/数字与尾部标点之后），`marker_line` 是**整行原文**。
> 两个量纲，别混着用——告警线（`core > 20`）判的是前者。

`番外-宋温瑶` · `【番外：两年后】` · `【后记】` · `19.后记` · `【尾声】`

### 3.4 可信度层与静态说明

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `warnings` | `str[]` | 是 | **动态**。全语料 **11/163 本命中，共 11 条**，单本最多 1 条 | **三源** |
| `notes` | `str[]` | 是 | **静态**：恒 3 条，逐字固定。与 `warnings` 性质完全不同 | **盘·码** |

`warnings` 有 6 类触发条件。**全语料跑下来只有 2 类真的触发过**：

| 触发 | 阈值 | 全语料命中 |
|---|---|---|
| 只认出 ≤1 章却很长 | `3000` 码点 | **10** |
| 同一个章号重复 N+ 次 | `3` | **1** |
| 切点太靠前 | `body_ratio < 0.60` | **0** |
| 丢弃占比过大 | `> 0.35` | **0** |
| 标记行过长 | `core > 20` 码点 | **0** |
| 完结标记之后还有内容 | — | **0** |

> ⚠ **后四类在 163 本上一次都没触发过——这是「没有失败样本」，不是「已验证」。**
> 而其中「切点太靠前」与「丢弃占比过大」恰恰是**这一层最要紧的两道防线**
> （剔除是破坏性的，一次假阳会静默吃掉半本书）。
> 它们从没响过，可能是因为判据好，也可能是因为**它们根本挡不住真出问题的那种形态**——
> 这两件事在当前证据下**分不开**。

⚠ **`warnings` 的文案本身是承重的**（移植验收逐字节比对）。措辞不能改。
要改就得先决定「逐字节等价」这条验收换成什么。

### ⚠⚠ 一条**必须改写**的不变量（三源冲突，2026-08-10 实测）

`CONTRACTS.md` §1.5.2 写着：

> `dropped[]` 的校验 = **与 `body_code_points` 之和 == `total_code_points`**

**它在 42/163 本上不成立。** 缺口恒为 **1~7 码点**，全部落在有完结标记的书上：

| 缺口 | 本数 | 那几个码点是什么 |
|---|---|---|
| 6 | 15 | `（全文完）\n` |
| 5 | 14 | 同类 |
| 4 | 2 | `（完）\n` |
| 3 / 7 / 1 | 15 / 3 / 1 | 同类变体 |

按 `(不成立?, 有完结标记?)` 分组：`(True, True)` **42** · `(False, True)` 4 · `(False, False)` 117。
⇒ **只有「切点来自完结标记、且其后没有非正文标记」时才不成立**——
那一行 `（全文完）` 既不在正文里（`body_limit` 停在它之前），也没进 `dropped`（它不是非正文标记）。

**三件事同时成立**：契约这么写了 · 实现不满足 · **`check_partition` 根本没在查**
（它只查 `len(text) == total_code_points`）。

**处置是改契约，不是改数据**：按契约去修，就得把「（全文完）」硬塞进正文或塞进 `dropped`——
两个都是假的。**「一条判据开始报错时，先问是数据错了还是判据把合法情况排除在外了」——
判据错的信号就是：按它去修数据会让产物变得更差。**

正确的表述是**三段**而不是两段：

```
total_code_points = body_code_points + dropped_code_points + 完结标记行及其后未被剔除覆盖的部分
```

⇒ **待裁决**：这条要不要补成一个真判据（连同它的第三段），还是登记为「不查」并写明理由。
补的话记得先在 163 本上跑一遍——现在的写法会红 42 本。

### 验不了的那条

**剔除的正确性验不了**（`R-1.8` / `B-20`）：「这一段到底是不是番外」没有结构不变量可查，
而正文体已按契约丢弃、盘上不留副本。所以每本都要打印一条
`[????] 剔除的正确性：本层验不了`——**「没报违规」与「根本没在查」必须能区分**。
