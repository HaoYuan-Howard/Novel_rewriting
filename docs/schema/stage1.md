# stage1 产物 schema

分章。**这一层不调 LLM，也不切任何非正文**。对应需求 `R-1.3` ~ `R-1.14`。

**输入是 `stage0/clean_text.txt`**——一份已经删掉番外、且**经人批准**的文本，
恒 utf-8 / `\n`，没有编码可猜、没有归一化口径可记（那些都在 `stage0.md`）。
判据与词表**只有一份**（`contracts/invariants.py`），本层与 stage0 同源。

读法（证据列的取值）见 `_README.md`。
**载体 = Pydantic v2**（已定），但本文只定内容、不写模型——模型在骨架阶段照本文写。

> **样本面：全语料 163 本**（不是盘上那 3 本）。
> `build_sections` / `build_report` 是纯函数，取样**不落盘**——
> 拿样本不需要写文件，全语料扫一遍是 0 成本的。

三份产物：

```
stage1/main_text.json         [ {section_id, chapter_ordinal, source_chapter_label, text} ]
stage1/hook_copy.json         {section_id, text}          ← 恒非 null，见 §二
stage1/partition_report.json  {…9 个字段…}                ← 见 §三
```

---

> ## ⚠ 三条贯穿本层的事实
>
> **① 承重的只有 `main_text.json` 与 `hook_copy.json` 的当前规范 JSON。**
> 下游每一份产物记的来源指纹都是对它们算的（`_provenance.inputs`：
> stage2 ← `main_text.json`；stage3 ← `main_text.json` + `hook_copy.json`；
> **`partition_report.json` 一次都没作为 input 出现过**）。
> 新流水线统一通过 `ArtifactStore.write()` 生成规范字节，不再保留原型的 CRLF/无末尾换行格式。
>
> **`partition_report.json` 不承重**：没有下游消费方，增字段、删字段、重排键都不会造成任何失配。
> 「逐字节等价」这条移植验收**只覆盖前两份**，不覆盖它。
>
> **② 这两份产物在前端是【只读】的，stage1 切完就钉死。**
> 分章算法是确定性的：切错了就是算法错了，**去改算法、重跑**，不在界面上手改数据。
> ⇒ 载体不需要给它们任何编辑入口、不需要 `origin=human` 那套回写路径、
> 也不需要「人改过的版本 vs 机器产的版本」这层并存关系。
> ⇒ 一旦改了算法重跑，字节变了，下游**本来就该**整批判陈旧——那是真回归，不是假回归。
>
> **③ 本层所有字段的「prompt 消费方」一律是【无】——stage1 不进任何 prompt。**
> 这是判定结果，不是留空。只有 `main_text.text` 与 `hook_copy.text` 经下游读取后**间接**影响 prompt；
> `partition_report` 本身只被确定性代码读。

## 一、`main_text.json`

顶层是**数组**。**长度恒 ≥ 2**（`R-1.13`：只有一章的书入显式终态）。全语料 2~39 章。
**前端只读**（事实 ②）。

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `[].section_id` | `str` | 是 | 形如 `sec_0001`，长度恒 8 | **三源** |
| `[].chapter_ordinal` | `int` | 是 | ≥1，**连续无缺号无重号** | **三源** |
| `[].source_chapter_label` | `str` | 是 | **非空**。原文标号的字符串形式 | **三源** |
| `[].text` | `str` | 是 | 章正文 | **三源** |

### `source_chapter_label` 是必填 `str`，不可空

原型代码写的是 `str(chapter_no) if chapter_no is not None else None`，类型上可空；
本 schema **收窄，并配一条后置条件**——否则「不可能为 `None`」只是一句注释。

- **结构论证**：`main_chapter` 段的 `chapter_no` 恒由 `CHAPTER_RE` 匹配出的数字行解析得到；
  解析不出数字的行根本不会被认成章节标记。这条路上没有产生 `None` 的分支。
- **实测**：全语料 163 本共 **2559 个 `main_chapter` 段，`chapter_no` 为 `None` 的 0 个**。
- **后置条件**：写盘前逐段断言 `chapter_no is not None`。

> ⚠ **两件常被混读的事，分开写**：
> ① **`None` 确实存在，只是不在这个字段上**——163 个 `hook_copy` 段的 `chapter_no` 全是 `None`
> （163/163），但 hook 段不进 `main_text.json`。「盘上见过 `None`」不是「这个字段可空」的证据。
> ② **重号是常态，`null` 是零样本**——语料里第一本书的前 5 章标号实测就是 `[1, 2, 3, 4, 4]`。

### 两个 ordinal 的区别（本层最容易读错的地方）

| | 含义 | 全语料实况 |
|---|---|---|
| `source_chapter_label` | **原文标号，原样保留** | **28/163 本有重号**（单本最多 16 个重号）· **12/163 本有缺号** |
| `chapter_ordinal` | **修正后的阅读序** | 恒连续、无重复。**下游一律 key 在它上面** |

> **`R-1.4`（断号/重号/严格递增逐项记账）的记账落点就是 `source_chapter_label` 本身。**
> 「原样保留 + 另给一个修正序」这一对字段共存，就是记账；
> 派生出来的三个汇总（`chapter_no_gaps` / `_duplicates` / `_strictly_increasing`）
> **由校验器现算，不落盘**——`main_text` 只读钉死，现算与落盘永远同值。

## 二、`hook_copy.json`

开篇文案段——第一个正文章标记之前那段无标题内容。

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| （顶层） | `obj` | 是 | **不可为 `null`**，见下 | **三源** |
| `section_id` | `Literal['sec_0001']` | 是 | 恒 `sec_0001`（2026-08-21 从正则串收紧为 Literal——正则只保证形状，不保证这个常量事实） | **三源** |
| `text` | `str` | 是 | 非空。全语料长度 57 ~ 414 | **三源** |

### ⚠ 文案段为空 = 显式终态，不是一个合法分支

认不出文案段时 **stage1 直接入显式终态，不写任何产物、后续 stage 一步都不跑**（`R-1.12`）。

理由不是「163 本都非空所以大概不会空」——那是拿样本当结论。理由是**下游三层都要它**：

| 层 | 怎么用 | 空了会怎样 |
|---|---|---|
| stage3 | `_provenance.inputs` 记着 `stage1/hook_copy.json`；产出 `hook_style` 七项（`HOOK_KEYS`）+ `hook_copy_text` | 文案写法七项无源可量 |
| stage6 | 三候选文案参照原作文案段的写法与收尾形态（`R-9.4`） | 参照物没有 |
| stage7 | 成书 = `文案 \n\n 1 \n\n 第1章正文 …`（`R-10.8`） | 成书第一段是空的 |

⇒ **让它带着一个 `null` 往下跑，等于把一次本该在 0 成本层红掉的失败，推迟到花钱之后。**

⚠ 连带：`R-4.6`（stage3「无开篇文案段时该字段为空并显式报警」）的分支在此前提下**不可达**，
已改成「由 stage1 阻断，本层不可能遇到」。

## 三、`partition_report.json`

**9 个字段。** 两个消费方：

| 谁 | 读什么 | 干什么 |
|---|---|---|
| **校验器** | 全部 | `R-1.3` / `R-1.5` / `R-1.12` / `R-1.13` / `R-1.14` 的判据 |
| **S-03 原文↔切分对照屏** | `hook_span` · `chapter_spans` · `input_sha1` | 在 `clean_text` 上把「文案 / 各章」标出来。<br>**被剔除段的高亮来自 `stage0/removal_report.json` 的 `removed[].span`**，画在原始 txt 上 |

**报告的字段本身不上屏**——上屏的是它记的那些**区间**。
`warnings[]` 的落点是 S-13 校验报告的 `stage1` 那一份（`info` 级结论）。

键的插入顺序按下表固定。**这不是为了逐字节验收**（那条验收只覆盖前两份，见事实 ①），
而是为了两次跑出来的产物能直接 `diff`。

### 3.1 两个指纹

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `normalized_source_sha1` | `str` | 是 | **原始 txt** 的 sha1，从 stage0 透传。只用于追溯，本层不判它 | **三源** |
| `input_sha1` | `str` | 是 | **本层输入**（`stage0/clean_text.txt`）的 sha1。**[HARD]** 对不上即阻断 | **盘·码** |

**这两个是 `R-0.6` 的下半段。** 只记一个，「有人换过原始小说」和「有人改过 stage0 的剔除结果」
就分不开了，而这两件事的处置完全相反（前者从头重跑，后者**是人有意为之、必须保住**）。

⚠ 摄入元数据（`original_filename` / `original_path` / `source_encoding` / `text_norm`）
记在 `stage0/removal_report.json`，不在这里——**谁读原始 txt，谁记它的元数据**。

### 3.2 规模与分章

| 字段 | 类型 | 必填 | 取值面 / 范围（全语料 163 本） | 证据 |
|---|---|---|---|---|
| `total_code_points` | `int` | 是 | 8088 ~ 41224。**[HARD]** 与复算的原文长度交叉核对 | **三源** |
| `body_code_points` | `int` | 是 | `[0, body_limit)` = 文案 + 正文，即保留下来的部分 | **三源** |
| `detected_chapter_marker_count` | `int` | 是 | **≥ 2**（`R-1.13`）。全语料 2 ~ 39。**[HARD]** 必须等于 `main_text` 的长度 | **三源** |
| `has_end_marker` | `bool` | 是 | `True`×46 · `False`×117。**[HARD]** `R-1.14` 的第三段只在它为 `True` 时非空 | **盘·码** |

**`body_ratio` 不落盘，判它的那条判据也不在本层**（`R-0.9` 在 stage0）。
本层不剔除，切点只由完结标记决定 ⇒ `body_ratio` 恒 ≈1.0（差的就是那一行 `（全文完）`），
留在这里就是**一盏保证会亮的绿灯**：报告照常输出，只是不再携带信息。
⚠ `total_code_points` / `body_code_points` **仍然留着**——它们不是为了算这个比值，
是 `R-1.3` 的交叉核对和 `R-1.14` 的三段记账要用。

> #### ⚠ `detected_chapter_marker_count` **必须由分章那一趟独立数出来，不许写成 `len(sections)`**
>
> 这是它存在的**唯一**理由。`R-1.5`（`HARD`：章数必须等于章表长度）防的是
> 「两行式番外造出一个被跳过的空章」——**认出 9 章、只写进去 8 条**。
> 若 `detected_chapter_marker_count` 取自 `len(main_text)`，这条判据就成了恒等式，**永远不可能红**，
> 而它要抓的那个 bug 会原封不动地活下来。
> ⇒ 载体阶段要配一条后置条件：产地一侧的计数来源与写盘来源**必须是两条路**。

> #### `detected_chapter_marker_count < 2` → 显式终态（`R-1.13`）
>
> 只有一章的「书」不接受重构。**不带字数阈值**——原型那条是「≤1 章且 >3000 字才告警」，
> 而语料里最短的书也有 8088 字，那个阈值从来没起过作用；留着它只会让判据看起来标定过。
>
> **影响面实测：163 本里正好 10 本**（10670 / 11608 / 12357 / 14924 / 15516 /
> 15648 / 15785 / 18912 / 24862 / 28223 字），全部拒收。
> 核过原文：它们确实只有一个 `1` 标记、之后再没有数字行——**真·未分章，不是漏切**。

### 3.3 非正文剔除 —— 本层只剩一条断言

剔除与记账都在 stage0（`removed[]`，见 `stage0.md` §2.2）。本层剩下的是：

```
在 stage0 已批准的 clean_text 里，如果还认出任何非正文标记 → 显式终态（R-1.7）
```

**它不切任何东西**，命中时只报错、不写产物 ⇒ 判据错报一次的代价是「一个假警，回 stage0 看一眼」，
不再是「静默吃掉半本书」。

⚠ 它是**同一套判据的重放**，只能抓「判据本来就认得、但 stage0 没删」这一类。
判据本来就不认得的（盲区①，见 §五「三个盲区」）它同样抓不到。
⚠ 也正因如此，这条断言**几乎必然是零命中的**——合成样本要跟上。

### 3.4 可信度层

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `warnings` | `obj[]` | 是 | **动态**。每条带 `kind`（`STAGE1_WARNINGS` 之一）与人读的一句话 | **三源** |

**落点**：`warnings` 转成 **S-13 校验报告里 `stage1` 那一份的 `info` 级结论**。
`R-1.9`（不静默、不自动修正、不硬报错）靠这条路兑现——**写进文件没人看才是真的静默。**

⚠ **认告警一律用 `kind`，不许用措辞前缀。** 措辞不承重（逐字节等价不覆盖本份产物），
随时可改；拿字符串开头去认告警的代码会在第一次改文案时静默失效。
`kind` 的闭合枚举在 `contracts/invariants.py::STAGE1_WARNINGS`。

**本层只有一类告警**：

| `kind` | 触发 | 阈值 | 全语料命中 |
|---|---|---|---|
| `noisy_duplicate` | 同一章号重复 N+ 次 | `3` | **1**（真实：`小三争夺战`，章号 1 出现 17 次） |

⚠ **「只剩一类」不等于这一层变安全了。** `early_cut` / `drop_ratio` / `long_marker` 三类
随剔除记在 `STAGE0_WARNINGS`（见 `stage0.md` §2.3）；「只认出 ≤1 章却很长」升成了 `R-1.13` 显式终态；
「完结标记之后还有内容」升成了 `R-1.14` 的 HARD 判据。
⚠ 但**本层现在没有零样本的告警分支**：`noisy_duplicate` 有真实语料样本。

### 3.5 对照屏用的两个区间

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `hook_span` | `[int,int]` | 是 | 文案段在归一化原文上的码点半开区间。恒 `[0, x)`，且 `x <= body_code_points` | **盘·码** |
| `chapter_spans` | `[[int,int], …]` | 是 | 逐章，**长度恒 == `detected_chapter_marker_count`**，顺序即 `chapter_ordinal`；**有序、两两不重叠、每条 `end <= body_code_points`**（2026-08-21 收紧为载体后置条件） | **盘·码** |

**为什么不加进 `main_text.json`。** 那是最自然的位置——span 是章的属性。
但 span 是分章过程的诊断与审计结果，不是下游正文消费契约；因此放在
`partition_report`，避免正文载体重复携带下游不读的字段。

**为什么它们不属于「能现算所以该删」。** 重跑分章确实能算出同样的 span——
但那样一来，对照屏画的就是**分割器自己和自己对账**，看不出任何问题。
拿**落盘时记下的** span 去比**此刻盘上的**原文，才是一次真的核对：
原文被换过、被截断、编码变了，都会在屏上直接错位。

**依赖：源 txt 必须还在 `original_path`。** 三种降级，**必须能区分**：

| 情况 | 屏上说什么 |
|---|---|
| 文件在、`normalized_source_sha1` 对得上 | 正常对照 |
| 文件不在了 | 「原文不在原处，**无法对照**」——是「不知道」，不是「没问题」 |
| 文件在但 sha1 对不上 | 「文本变过，span 已失效」——`R-1.3`（本层输入）与 `R-0.14`（原始 txt）在这里现形 |

⚠ **这不违反「番外体在盘上不留副本」。** 对照读的是 `Novel_data` 里的**源文件**，
不是在 `Output/` 里再存一份。番外体从来就在源文件里。

## 四、判据清单

当前注册表共 **9 条**：**8 hard、1 info**。落点是 `contracts/judges/stage1.py`；
条数与分布由 `tests/test_coverage.py` 对着注册表现算，改判据必须同步改这一行。

| 判据 | 级别 | 作用 |
|---|---|---|
| `s1_input_hash` | HARD | 分章输入与 stage0 批准的 clean_text 完全相同 |
| `s1_chapter_count` | HARD | 独立章节计数与章表、区间表一致 |
| `s1_chapter_labels` | HARD | 修正序连续，原始章号的缺号重号可追溯 |
| `s1_min_chapters` | HARD | 正文章数不少于两章 |
| `s1_hook` | HARD | 第一个正文章之前有非空开篇文案 |
| `s1_tail` | HARD | 正文切点之后为空或只有一条完结标记 |
| `s1_decomposition` | HARD | 源文本覆盖不变量：hook+章标记行+章正文+tail 完整分解输入，无未记账字节、无重复覆盖、标记行符合章标记文法 |
| `s1_nonbody_residual` | HARD | 批准文本里没有可识别的非正文残留（**断言，不切**） |
| `s1_warnings` | info | 可疑分章逐项显式报出 |

⚠ 本层**没有 unver 判据**，但这不等于本层什么都验得了：验不了的那一条在 §五末尾
（分章切点的语义正确性），它由人工闸门兜底，不由一条判据表达。

### `R-1.14` —— 尾段判据

记账不是两段而是**三段**：

```
total_code_points = body_code_points + tail
tail := clean_text[body_limit:]
R-1.14：tail == '' 或 tail.strip() 匹配 END_RE
```

**全语料 163/163 成立，0 本违反。** 分布：


### 验不了的那条 —— 以及它现役的闸门

**剔除的正确性验不了**（`R-1.8` / `B-20`）：「这一段到底是不是番外」没有结构不变量可查，
而正文体已按契约丢弃、盘上不留副本。所以每本都要打印一条
`[????] 剔除的正确性：本层验不了`——**「没报违规」与「根本没在查」必须能区分**。

**判据查不了，闸门是人**：stage0 的审阅闸门（`R-0.3a`）+ S-03 原文↔切分对照屏（§3.5）。
这不是「退而求其次」，它是这条需求现役的**唯一**闸门。

#### 判据在这批语料上的表现

扫了一遍**留在正文里、仍含四类关键词的行**：**命中 6 本 / 163，共 7 行，逐行核对全部是正常叙述、
0 条真漏切**（「前厅的宴席似乎已经接近尾声。」·「节目的尾声。」·
「拍摄到了尾声，还剩一组落日照片没有拍。」）。

⚠ 其中 **4 行长度 ≤30 且含「尾声」**。`后记`/`尾声` 如果用「包含」而不是**全等**匹配，
这 4 本每一本都会被从中间砍掉——**这组数据是全等匹配那个设计的实测辩护**。

#### 三个盲区（「扫不出来」不等于「没有」）

**① 番外用纯数字章节标记写**（`9` 换行、内容是番外）——**它和正常章节长得一模一样**。
两个可能的结构信号都查过：

| 信号 | 实测 | 结论 |
|---|---|---|
| **完结标记之后还有内容** | 有完结标记的 46/163 本；这类内容一律落在 `body_limit` 之外 | ✅ **已经用上了**（`R-1.14`） |
| **章号回退重启**（正文 1..N 后又从小号开始） | 全语料只有 **3 本**有回退，逐本核过内容**没有一本是番外**（回退后都是正常剧情） | ❌ **0/3 精确率，不能用** |

⚠ 其中一本回退幅度 4、发生在全书 **86%** 处——**「幅度大 + 位置靠后」这个看起来很强的信号是假的**。
按它去切，会砍掉一本书的最后一章正文。⇒ **模式匹配在这个盲区上没有余量可捡。**

**② 标题用四类之外的词** —— 这个可以靠加枚举补。
`NONBODY_KINDS` **是开放表，遇到新写法就加**，但加之前必须过
`tools/probe_nonbody_word.py` 那道假阳闸门（流程见 `R-1.7`）——
剔除是破坏性的，而词表只会单向增长，**加错了没有任何东西会提醒你**。

| 候选词 | 正文里含它 | `core` 全等 | 判定 |
|---|---|---|---|
| `外传` | **26 行** | **0** | ✅ 安全。⚠ 那 26 行是「不外传的秘药」「**门外传**来脚步声」——**用包含匹配会毁掉 26 处** |
| `特别篇` · `HE线` · `其他视角` · `番外篇` · `幕间` · `终章` · `后日谈` · `结语` | 0 | 0 | ✅ 安全 |
| `小剧场` | 1（「日本小剧场里进货」） | 0 | ✅ 安全 |
| **`正文完`** | 1 | **1**（`(正文完。)`） | ❌ **不要加**：它已经是**完结标记**（`END_MARKER_WORDS`），走的是另一条路 |

⇒ 真正的风险只有两种，闸门各查一遍：词在正文里以整行出现（直接误切）· 词与完结标记撞车（两条路记同一段）。

**③ 新上传的书是未知分布** —— 163 本的干净**不能外推**，这条补不掉。

⇒ ① 和 ③ 只有人对着原文才看得出来，**对照屏挡的就是它们**；
② 可以靠加词逐步收窄，但它永远滞后于下一本书的新写法——**对照屏仍然是兜底**。
