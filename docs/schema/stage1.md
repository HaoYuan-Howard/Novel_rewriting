# stage1 产物 schema

摄入 + 分章 + 非正文剔除。**这一层不调 LLM。** 对应需求 `R-1.1` ~ `R-1.11`。

读法（证据列的取值、为什么三源合并）见 `_README.md`。**载体留空，等骨架。**

三份产物：

```
stage1/main_text.json         [ {section_id, chapter_ordinal, source_chapter_label, text} ]
stage1/hook_copy.json         {section_id, text} | null
stage1/partition_report.json  {…24 个字段…}
```

> ## ⚠ 两条贯穿本层的事实
>
> **① `main_text.json` 与 `hook_copy.json` 的【字节形态】是承重的。**
> 下游每一份产物记的来源指纹都是对它们算的；改动它们（哪怕只是重排一个键）
> 会让全部下游产物的指纹失配，被整批报成「陈旧」——**那是一次假回归**。
> 新增信息一律只进 `partition_report.json`。
>
> **② 本层所有字段的「prompt 消费方」一律是【无】——stage1 不进任何 prompt。**
> 这是判定结果，不是留空。只有 `main_text.text` 的正文经下游抽取后**间接**影响 prompt；
> `partition_report` 本身只被确定性代码与人读。
> 不写明这一条，下一次零消费审计会把整层当成「没审」。

## 一、`main_text.json`

顶层是**数组**（不是对象）。盘上 3 本共 31 项，每本 8~14 章。

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `[].section_id` | `str` | 是 | 形如 `sec_0001`，盘上长度恒 8 | **三源** |
| `[].chapter_ordinal` | `int` | 是 | ≥1，**连续无缺号无重号**。盘上 1~14 | **三源** |
| `[].source_chapter_label` | `str \| null` | 是 | 原文标号的字符串形式。盘上 31/31 非空，长度 1~2 | **三源** |
| `[].text` | `str` | 是 | 章正文。盘上长度 408~1963 | **三源** |

**`source_chapter_label` 的 `null` 在结构上不可达**：代码写的是
`str(chapter_no) if chapter_no is not None else None`，而 `main_chapter` 段的 `chapter_no`
恒由章节标记行解析得到、不可能是 `None`。
⇒ 类型上可空、结构上不可能——**载体阶段要决定：跟着代码写成可空，还是收窄成必填**。
收窄是对的，但要配一条后置条件，否则「不可能」只是一句注释。

### 两个 ordinal 的区别（这是 stage1 最容易读错的地方）

| | 含义 | 性质 |
|---|---|---|
| `source_chapter_label` | **原文标号，原样保留** | 含缺号、含重号。盘上就有一本 `chapter_no` 重复过（`8` 出现两次） |
| `chapter_ordinal` | **修正后的阅读序** | 恒连续、无重复。**下游一律 key 在它上面** |

## 二、`hook_copy.json`

开篇文案段——第一个正文章标记之前那段无标题内容。**下游抽取从不消费它，只给人看。**

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| （顶层） | `obj \| null` | — | **整份可以是 `null`**（这本书没有文案段）。盘上 3/3 非空 | **契·码** |
| `section_id` | `str` | 是 | 盘上恒 `sec_0001` | **三源** |
| `text` | `str` | 是 | 盘上长度 155~349 | **三源** |

**顶层 `null` 是盘上零样本**：三本书都有文案段。代码里 `hook_copy = {...} if hook else None`，
所以 `null` 是合法态。⇒ 载体不能把它定成必然非空。

## 三、`partition_report.json`

24 个字段。**键的插入顺序是承重的**——移植验收用的是逐字节比对，重排不会报错，
只会让那条验收从此永远失败。下表按代码里的写入顺序排。

> ### ⚠ `CONTRACTS.md` 只覆盖了其中 **15/24**
>
> 另外 9 个（`title` 在 §1.5 内 0 次、`platform` / `num_sections` /
> `chapter_nos_strictly_increasing` / `has_end_marker` / `hook_copy_present` /
> `hook_copy_code_points` / `dropped_code_points` / `notes` **全文 0 次**）
> **只活在代码和盘上**。
> 这不是契约文档写漏了字段那么简单——**它本来就不是完整 schema，它是「有消费方或有判据的字段」表**。
> 拿它当 schema 用，会直接丢掉 9 个字段。

### 3.1 身份与摄入记账

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `source_id` | `str` | 是 | 文件名尾部的 `_<数字>`；**没有这个尾巴时退化成书名本身**。盘上 3/3 是 19 位数字串 | **三源** |
| `title` | `str` | 是 | 剥掉平台前缀与 id 之后的书名 | **盘·码** |
| `platform` | `str \| null` | 是 | 文件名的字母前缀（如 `FQ`）。盘上 3/3 是 `'FQ'` | **盘·码** |
| `original_filename` | `str` | 是 | | **三源** |
| `original_path` | `str` | 是 | 绝对路径。**文件被移走时是「不知道」，不是「不匹配」** | **三源** |
| `source_sha1` | `str` | 是 | 归一化后正文的 sha1（40 位十六进制）。**[HARD]** 校验时对不上即阻断 | **三源** |
| `source_encoding` | `str` | 是 | 实际解码用的编码。盘上 3/3 是 `utf-8`；可能值还有 `utf-8-sig` / `utf-16` / `utf-32` / `gb18030` | **三源** |
| `text_norm` | `str` | 是 | 归一化口径的版次，当前恒 `v1:bom+crlf`。**[INFO]** 与当前代码不同则 sha1 不可比 | **三源** |

> #### ⚠⚠ `platform` 与 `source_id` 的取值面，盘上这 3 本严重不具代表性
>
> 拿全语料 163 本跑同一把尺子：
>
> | 字段 | 盘上 3 本 | **全语料 163 本** |
> |---|---|---|
> | `platform` | 3/3 都是 `'FQ'` | **120 本是 `null`**（无平台前缀） |
> | `source_id` | 3/3 是 19 位数字串 | **13 本退化成书名**（无 `_<数字>` 尾巴） |
>
> 只按盘上定 schema → `platform: str` 必填非空 → **在 74% 的语料上崩掉**。
> 这是「机械反推单独用不够」最干净的一个实例。
>
> `source_encoding` 同理：盘上只见过 `utf-8`，而代码的候选集是
> `utf-8-sig / utf-32 / utf-16 / utf-8 / gb18030` 五个。**取值面从代码来，不从盘上来。**

### 3.2 规模与分章

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `total_code_points` | `int` | 是 | 归一化全文的**码点**数。**[HARD]** 与复算的原文长度交叉核对 | **三源** |
| `body_code_points` | `int` | 是 | `[0, body_limit)` = 文案 + 正文，即保留下来的部分 | **三源** |
| `body_ratio` | `float` | 是 | `body_code_points / total`，保留 4 位。**[HARD] < 0.60 判 FAIL**——红在花钱之前 | **三源** |
| `num_sections` | `int` | 是 | 段总数（文案段 + 正文章）。盘上 9~15 | **盘·码** |
| `num_chapters` | `int` | 是 | **[HARD] 必须等于 `main_text` 的长度**（两行式番外最容易在这里造出一个被跳过的空章） | **三源** |
| `chapter_nos` | `int[]` | 是 | 正文章的原文标号，**按出现顺序、原样保留** | **三源** |
| `chapter_no_gaps` | `int[]` | 是 | 观察到的编号范围内缺掉的号。盘上 3/3 为空 | **三源** |
| `chapter_no_duplicates` | `int[]` | 是 | 重复出现的号。盘上有 1 本命中（`[8]`） | **三源** |
| `chapter_nos_strictly_increasing` | `bool` | 是 | 盘上 `True` / `False` 都见过 | **盘·码** |
| `has_end_marker` | `bool` | 是 | 有没有 `全文完 / 正文完 / (完)` 那一行。盘上两种都见过 | **盘·码** |
| `hook_copy_present` | `bool` | 是 | 盘上 3/3 为 `True` | **盘·码** |
| `hook_copy_code_points` | `int` | 是 | 没有文案段时为 `0`。盘上 155~349 | **盘·码** |

### 3.3 非正文剔除的记账 —— **盘上零样本**

**三本书都没有番外，所以下面整块在盘上一条真实数据都没有。**
类型与取值面**从代码读出来的，不是量出来的**。

而这块恰恰最要紧：番外体**在盘上不留任何副本**（用户裁决：彻底抛弃，不是「纳入别处」），
所以 `dropped[]` 是**唯一**能核对「切对了没有」的东西——剔除是破坏性的，一次假阳会静默吃掉半本书。

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `dropped` | `obj[]` | 是 | 盘上 3/3 长度 0。**全语料 163 本里 27 本会命中** | **三源** |
| `dropped[].kind` | `str` | 是 | 闭合枚举：`番外` / `后记` / `尾声` / `作者有话说` | **契·码** |
| `dropped[].marker_line` | `str` | 是 | 标记行原文（strip 后），供人逐条核对 | **契·码** |
| `dropped[].line_no` | `int` | 是 | 1 起的行号 | **契·码** |
| `dropped[].span` | `[int, int]` | 是 | 对归一化全文的**码点**半开区间 | **契·码** |
| `dropped[].code_points` | `int` | 是 | 这一段的码点数 | **契·码** |
| `dropped[].head_preview` | `str` | 是 | 首 80 字（空白折叠后） | **契·码** |
| `dropped[].tail_preview` | `str` | 是 | 末 40 字（取自末 120 字，空白折叠后） | **契·码** |
| `dropped_code_points` | `int` | 是 | `sum(dropped[].code_points)`。**与 `body_code_points` 之和必须 == `total_code_points`** | **盘·码** |

> **「27 本会命中」这个数不是估的**：分章判据在全 161 本语料上标定过——
> 命中 27 本 / 34 条真标记 / **0 假阳**，切点全落在 75.9%~99.3%。
> 本轮移植验收重跑了 163 本，命中数仍是 **27**。
> ⇒ 想给这一块拿到真样本，跑一次全语料 `stage1` 即可，**0 成本**。

### 3.4 可信度层与静态说明

| 字段 | 类型 | 必填 | 取值面 / 范围 | 证据 |
|---|---|---|---|---|
| `warnings` | `str[]` | 是 | **动态**：分章成功了、但结果可疑到该有人瞄一眼。盘上 3/3 为空，**全语料 11 本命中** | **三源** |
| `notes` | `str[]` | 是 | **静态**：恒 3 条，逐字固定。与 `warnings` 性质完全不同 | **盘·码** |

`warnings` 现有 5 类触发条件（都来自 161 本实扫里真实出现过的形态）：

| 触发 | 阈值 | 说的是什么 |
|---|---|---|
| 同一个章号重复 N+ 次 | `3` | 某个反复出现的固定行被误判成章节号，不是普通缺章/重章 |
| 只认出 ≤1 章却很长 | `3000` 码点 | 多半有一种标记写法没被覆盖 |
| 切点太靠前 | `body_ratio < 0.60` | **实测真标记都在 76% 之后**，落到 60% 以下几乎一定是切错了 |
| 丢弃占比过大 | `> 0.35` | 番外通常远短于正文 |
| 标记行过长 | `core > 20` 码点 | 实测真标记上限 17。照样切，但要人确认一眼 |
| 完结标记之后还有内容 | — | 既不进正文也不是可识别的非正文标记 → **真的丢了** |

⚠ **`warnings` 的文案本身是承重的**（移植验收逐字节比对）。措辞不能改。
如果要改，得先决定「逐字节等价」这条验收换成什么。

## 四、跨产物的不变量（`[HARD]`，对应需求 R-1）

| 不变量 | 对应需求 |
|---|---|
| `num_chapters == len(main_text)` | `R-1.5` |
| `body_code_points + dropped_code_points == total_code_points` | `R-1.7` |
| `body_ratio >= 0.60`，否则判 FAIL | `R-1.6` |
| `source_sha1` 与盘上原文复算值一致（文件已移走 → **记「不知道」，不是「匹配」**） | `R-1.3` |
| `chapter_ordinal` 在 `main_text` 内从 1 起连续、无重复 | `R-1.4` |
| `dropped[].kind` ∈ 四类闭合枚举 | `R-1.7` |
| 目录名能被同一把尺子解析回来且是不动点 | `R-1.10` |
| `total_code_points` 与复算的原文长度一致 | `R-1.3` |

**剔除的正确性验不了**（`R-1.8` / `B-20`）：「这一段到底是不是番外」没有结构不变量可查，
而正文体已按契约丢弃、盘上不留副本。所以每本都要打印一条
`[????] 剔除的正确性：本层验不了`——**「没报违规」与「根本没在查」必须能区分**。
