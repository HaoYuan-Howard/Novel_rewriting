# 身份引用文本协议

`identity-text-v1` 把姓名构词、登记名称和具体身份提及分开。姓、名、化名部件只用于
构词与候选召回；“明白”的“白”或“若非”的“若”不构成机械姓名泄漏证据。

现有 semantic unit 在可改写的自然语言字段中输出：

- `[[name:char_id|登记称谓]]`：绑定该身份的名称表达，可包含已登记家族构词。
- `[[text|普通文字]]`：明确的普通义片段，可以与姓名同形。

片段不嵌套，不包含协议分隔符；模型不生成字符偏移。compiler 解析标记、检查引用，
计算纯文本 Unicode 字符坐标，并按已授权显示面投影。原始证据、源引文、事实句柄与
释放登记不标记、不改写。没有足够登记信息的称谓由 source names owner 用正式证据补充，
不能按姓、相似性或常见称呼模板猜补。

材料中的释放许可按人物身份核对，同形称谓不互授权限。compiler 将本人未释放的
登记个人姓名面编成 `(char_id, literal)` 绑定；显式引用可按本人的显示面投影，
已释放面保留，家族构词没有本人许可时拒绝。`unmarked_unique` 是必填的确定性
证明，统计全部登记称谓的 owner；旧未标记源材料只允许凭此证明投影完整称谓。
相邻的独立身份片段不重新拼成第三个姓名，固定模板与正式字段分段保留来源。

Design wire v11、Preserve v6/policy11、Hook Design v4 使用同一协议。
正文协议 v12、renderer v13，正文／Hook validator 分别为 v4／v5。章 IR 与 HookContext
携带验证候选；候选全集不送写手，避免暴露尚未释放的名称。给写手的身份目录只含
当前章或 Hook 的授权身份名称。

Stage5 正式正文是去除标记的纯文本。接受回执同时保存 `name_mentions` 与
`non_name_spans`，均由 compiler 从回答计算并绑定正文 hash；合法空表须显式给出。
免费重验核对区间范围、排序、非重叠、逐字称谓、身份授权和候选覆盖。未标记候选报告
`name_text_unclassified`，不伪称确定泄漏；缺表不是没有人物，旧正文必须通过有语义声明
的新回答重建，不能由程序包进普通义片段。

Stage7 按 char_id 和登记构词生成身份映射，仅变换回执中的名称表达；普通义区间和
正文其余字节不改。声明表参与交付身份。模型是否把真实人物误标成普通文字仍是语义
未评边界；机械通过不证明标注准确、事实正确或文学质量，不新增生产 Judge。

旧 Design v9/v10 只供集中只读诊断，不能免费补出 v11 的语义选择。旧 Preserve checkpoint
保留原 policy 与原字节，可作为新 Design 的源材料；其中未标记源文字只按原有完整登记面
读取，不宣称已具备新提及证据。Names v4 只读保持原身份和序列化形状；新 v5 显式保存
对已有 Book 人物的补充称谓证据，经唯一 compiler 合入 Characters。兼容删除条件见
[REQUIREMENTS.md](../REQUIREMENTS.md)。
