# 三层小说重写系统重设计执行计划

## 一、目标、范围与已确认决策

以“理解原书 → 建模新书 → 完成高质量正文”为主线，重新设计 Stage2、Stage4、Stage5 的核心模型、节点职责、交接契约和恢复机制。目标是稳定自动出书，提高首答可用率，失败后能够定位窄修，同时保留重设计自由并控制整书成本。

本计划确定采用：

| 决策 | 执行口径 |
|---|---|
| 改造范围 | 三层核心设计及其契约、编排、恢复、API/UI、测试完整闭合 |
| 源事实整合 | 逐章理解之后，固定执行一个全书语义整合工作单元 |
| 目标故事建模 | 整书骨架先行，再逐章展开场景与行动 |
| 原文矛盾 | Stage2 如实记录；Stage4 可进行有记录的局部一致化 |
| 写手权限 | 表达自由；故事决定、关键动机、沟通和剧情桥梁归 Stage4 |
| 正文连续性 | 按章顺序写作，读取有限的已接受前文 |
| 超长材料 | 支持受限检索与材料补全，每次模型续答独立留账和计费 |
| 存量迁移 | 独立新输出根重建，完整保留旧根和历史账 |

继续遵守现役产品边界：全自动单模式、Stage 页面只读、章数和章号与源书一致，不合并、删除、拆分或重排章节。保留核心情节骨架、关键身份关系、结局和受保护的信息差；场景、对白、局部行动、呈现方式及非必保细节可以重新设计。

本执行规格为当前重设计依据。批次进度和未完成工作只登记在 `docs/REQUIREMENTS.md`，执行规格不维护第二份活动账。

本计划不包含真实付费或正文外发授权；工程实现、免费验证和付费验证准备可以独立完成。

## 二、目标架构与契约

### 2.1 三层真相与工程角色

| 层级 | 唯一职责 | 正式结果 |
|---|---|---|
| Stage2 事实理解层 | 原书发生了什么、各方如何认识、依据是什么、哪些尚不确定 | `SourceStory` |
| Stage4 目标建模层 | 决定保留与改造范围，建立能够独立成立的新故事 | `PreservationContract`、`TargetStory` |
| Stage5 写作执行层 | 将既定目标故事写成自然、连贯、有表现力的正文 | 章正文、Hook、写作回执 |

状态轴是事实与目标故事的持续约束投影。人物选择、因果联系、时间和信息差均有自己的正式表达，不再全部压入状态键。

工程角色保持单一职责：

- **semantic unit**：理解、判断、生成及明确的语义消歧。
- **compiler**：ID、引用、证据定位、归一、投影和确定性组装。
- **validator**：检查并报告，不修改输入、不补猜语义。
- **repository**：持久化、原子提交、历史字节和恢复材料。
- **orchestrator**：依赖、许可、预算、执行与恢复调度。

所有新 wire、canonical artifact、请求投影和回执显式版本化。旧格式不靠默认值或补字段混入新链。

### 2.2 Stage2：先局部理解，再全书整合

正常依赖顺序调整为：

```text
Stage1 冻结源文
  → chapters：逐章并行理解
  → book：全书语义整合
  → associate：仅处理剩余窄未决，无未决零调用
  → names：名称结构与词面解析
  → compile：唯一发布 SourceStory
```

保留现有五个 Stage2 节点标识，升级其协议、依赖、描述和工作单元定义。`book` 后置；取消章节对前置全书人物闭集和真相词表的依赖。

**chapters 的职责**

- 从本章原文抽取局部指称、事件、事实陈述、认识变化、读者披露、时间关系、明确前因后果及线程提及。
- 本章未具名人物可以用语义局部指称表达；临时句柄由代码派发。
- 允许关键事件没有持续状态变化，不为通过检查补造转移。
- 缺少前文依据时报告材料需求；取得前文材料只扩大读取范围，不扩大本章修改权限。
- 第 1 章同时处理章前文字：背景、开场行动、预告、重复和无法判断分别表达，由全书整合确认归属。

**book 的职责**

- 对照全书章观察及原文证据，统一实体、命题、状态事项和源线程。
- 整理开场事实、开场认识、跨章因果、人物变化及误解纠正。
- 可以发现局部漏抽或错抽，但只能提交定位到章节条目的 `source_issue`，不能暗改章观察。
- 正常路径形成一份全书整合结果；源问题修复后，只修订受影响的整合条目。

**associate 的职责**

- 只处理 book 留下的具体身份、命题、时间或线程关联未决。
- 每项包含候选、问题和必要原文。
- 支持指出候选缺失及其证据；候选集外不等于不存在。
- 上游漏项、复合问题或错误收束立即回派原 owner，不反复购买关联答案。

**names 的职责**

- 基于已确定实体解析姓、名、化名、称谓构词和字面变体。
- 人物存在、指称绑定和揭名许可分别处理。
- 不使用最早姓名出现时间限制人物出场，也不将未绑定人物转挂为 `world`。

#### SourceStory 最小正式结构

| 部分 | 必须表达的内容 |
|---|---|
| 实体与局部指称 | 实体身份、原文指称、绑定证据；已解析、原文未知、抽取未决分开 |
| 事件 | 参与者、处境、触发、行动或选择、结果、源章与证据 |
| 命题 | 独立陈述及涉及实体；世界成立、被否定、尚未确定分开 |
| 认识 | 持有者、命题、模式、取得时点及纠正对象；初始认识复用同一结构 |
| 读者披露 | 展示、声称、暗示、确认及其阅读位置；不再按拍级 `access` 推定确认 |
| 状态事项 | 主体、属性类别、具体对象或事项；多个意图、持有物和关系可以并存 |
| 状态更新 | 操作、值、有效时间及 actual/planned/expected/conditional 身份 |
| 时间关系 | 阅读位置与故事时间分开；支持过去、当前、未来、概括和未说明 |
| 因果联系 | 章内外共用的原因、动机、条件与伏笔回收，附证据及明确/推断身份 |
| 源线程 | 开启、推进、部分回答、解决、放弃及原书未收束 |
| 世界与表达 | 世界限制、叙述权限、声线和已有表达机制 |
| 证据表 | 代码生成的段地址与原文；语义条目仅引用证据地址 |

同一命题只建立一次，世界状态、人物认识和读者披露分别引用它。禁止以“避免重复”为由丢失正交关系。

证据覆盖区间与语义支持范围分开：多个事件可以引用同一自然段，跨拍证据必须明确列出。机械校验只能证明地址和引用合法；证据是否支持陈述仍属于语义判断。

SourceStory 是唯一正式源故事真相。旧 Characters、Blueprint 不再作为新链的双写产物或长期适配入口。

### 2.3 材料索引与上下文补全

新增从冻结 Stage1 确定性生成的 `SourceIndex`，提供两类受限查询：

- 按段地址读取原文及指定邻段。
- 按字面、章范围和分页参数检索。

查询结果必须公开 `complete/truncated/empty`，空命中不证明事实不存在。章节查询限定当前章及此前；全书整合可读取整书。

当前 transport 没有原生工具调用能力。本期通过普通 JSON tagged union 实现：

```text
need_materials：请求受限材料
result：提交完整语义候选
```

runner 执行查询并冻结材料，再通过现有付费会话续答。每次请求记录源身份、索引版本、查询、返回段、文本摘要及预算消耗；崩溃后重放相同字节。

上下文内能够容纳时，全书整合读取一份带地址的原文和章观察索引；超限时保留全书事件索引，通过材料协议读取细节。不能静默删章、截断证据或把摘要当作原文。

材料请求、续答均受现有工作单元和整书额度限制。最低索引、必要材料与输出仍无法容纳时，明确停止，不无限循环查询。

### 2.4 Stage4：独立建立目标故事

Stage4 使用以下职责链：

```text
SourceStory
  → naming：目标命名
  → preserve：应用版本化改写政策
  → body_design：整书目标骨架
  → chapters：逐章场景与行动展开，可并行
  → compile：发布 TargetStory、AdaptationMap 与写手材料
  → hook_design：基于目标故事设计 Hook
  → hook_compile：生成 HookContext
```

新增逐章建模节点和免费 Hook 编译节点。将正文目标故事与 Hook 分开发布，避免修改 Hook 重新决定正文故事。

**PreservationContract**

由 Preserve 应用固定产品政策生成，明确：

- 必保语义及满足条件。
- 必须保留的因果、人物转变和信息差。
- 可以替代的机制与可改写细节。
- 必须保持的未知、未解和秘密。
- 允许局部一致化的范围。

它不规定目标场景、目标细拍，也不把所有源认知逐条升级成目标硬锁。Design 只读取源盲交接材料；引文、源坐标和原句保留在审计面。

**TargetStory**

整书骨架必须明确：

- 目标世界规则、资源与限制。
- 人物处境、诉求、顾虑、关系条件和关键转变。
- 触发—行动/选择—结果及必要因果、信息前提。
- 事实成立、人物认识、读者披露的不同时间。
- 持续状态事项、开放线程和结局。
- 每章目的、关键里程碑及入章、出章条件。

源世界规则由 Stage4 明确选择 `keep/adapt/omit`；改造或省略须记录理由，不得破坏必保语义。Hook、正文和检查均读取同一份目标规则表。

源文存在矛盾时，Stage2 保留原始冲突。Stage4 以 `AdaptationDecision` 记录采用解释、修补行动、受影响条件和目标结果。超出核心骨架、关键身份或结局保护范围时明确停止，不自行改写产品边界。

**逐章 ChapterPlan**

每章只展开冻结骨架授权的事件和变化，必须交接：

- 从哪里、什么时间和什么处境进入本章。
- 人物为何作出本章选择。
- 关键行动、反应、权衡、结果和自然转场。
- 信息取得与披露渠道。
- 本章结束后对后续章成立的条件。

局部计划不得偷偷增加跨章秘密、前史或持久条件。需要新增时，回到整书骨架的对应条目修订，再重编译影响范围。

目标语义的承载声明只有一处。沿用 `real/Binding` 的单一声明原则，由 compiler 派生 `AdaptationMap`；不再另购一次绑定判断。

全书骨架和逐章设计作为内部已购材料留存，`compile` 是正式 TargetStory 的唯一发布者。

### 2.5 Stage5：顺序写作、表达自由、明确窄修

正文按 `chapter_ordinal` 顺序执行；Stage2 抽取和 Stage4 逐章规划继续支持并发。并发登记、配置和 UI 同步调整，正文节点不再承诺章间独立并行。

写手只读取目标章包及有限前文，不读取原小说：

- 本章必须演出的变化、选择和结果。
- 必须遵守的世界、状态、认识和称谓条件。
- 正式入章、出章条件及开放线程。
- 场景重点、声线、节奏和展开方向。
- 当前可用背景与尚未获准披露的内容。

前文默认取上一章已接受正文末尾不超过 800 个非空白字符，优先在自然段边界截取；其真实字节进入请求身份。前文用于表达衔接，正式事实仍由 TargetStory 决定。

写手可以自由组织对白、即时心理、表情、动作和自然移步。新增关键动机、决定、沟通、剧情桥梁或跨章事实时，必须回派 Stage4。

新增同一正文 owner 内的局部修订协议：

- 代码提供旧正文自然段句柄、允许修改范围和未改区域摘要。
- 模型可返回保留、局部替换或范围不足；替换只能选择给定段落。
- 章缝问题先限定在开篇连续片段，初始范围为前 8 个非空自然段；范围不足时显式扩大，不截断语义修复。
- compiler 拼接后验证未授权区域字节不变，再进行完整章级检查。
- 修改前章短尾后，下章真实输入失效；通过同一写手的兼容复核或开篇窄修重新接受。下章短尾未变时，不继续传播。
- 语义入章、出章条件变化时，按目标依赖扩大修订范围，不能承诺所有改动只影响一章。

不增加泛化的“打分—低分重写”生产 Judge。机械检查、模型自检和文学质量评价分别报告。

## 三、恢复、失效、成本与迁移

### 3.1 问题归属

| 问题 | 唯一修订责任 |
|---|---|
| 原文章内主体、事实、证据、局部时间错误 | Stage2 chapters 对应条目 |
| 全书实体、命题、初态、因果或线程整合错误 | Stage2 book 对应整合项 |
| 指定候选关联未决 | Stage2 associate 对应候选 |
| 姓名结构或字面变体 | names |
| 必保选择或改写边界错误 | Preserve |
| 目标人物弧、跨章因果、信息安排错误 | 整书目标骨架 |
| 本章触发、行动、转场或可演出性不足 | Stage4 chapters |
| 表达、包装、局部文字承接错误 | Stage5 正文 owner |

发现位置不授予修订权限。结构化问题必须包含 node、item、证据、规则和允许修改范围。

### 3.2 局部身份与失效

- 首次 ID 由代码派发；后续补丁引用既有 ID，新增条目由代码增配，不整书重编号。
- 依赖记录实际读取的语义切片、证据和前文，不以整书 hash 替代全部消费者身份。
- 章观察修订后，先圈定已知实体、命题、因果和线程闭包；补丁发现新联系时明确扩大范围。
- 无法确定影响范围时保留 unknown，不假装无影响，也不默认整书重跑。
- 修订基线只用于验封和比较，不能串入兄弟节点的上游依赖。
- 已购响应先耐久，再校验和发布；prepared、响应落盘和正式提交之间的中断均可恢复。
- unknown 调用、损坏来源和未闭合账保持阻断，禁止重复购买掩盖。

### 3.3 成本与首答口径

两级目标建模会增加逐章规划调用；取消章节重复全文前文、压缩机械输出和减少返修是否足以抵消，必须用账实测。

所有材料续答、消歧、失败和窄修均计入整书成本，沿用现役额度和授权闸，不自动追加预算或换模型档位。

分别统计：

1. **首响应直接可用**：第一次模型响应即给出完整候选并通过交接。
2. **首候选接受**：首个完整候选通过；此前材料请求次数单列。
3. **最终自动完成**：允许模型窄修，未发生人工内容介入。
4. **语义与阅读达标**：通过冻结标注或人工核读。

材料控制与上游问题响应不能用来美化首答率。当前根的缓存重放、免费复验、窄修和真实调用分别登记；reasoning 不重复计费。不支持历史根回答采用，也不把人工核读冒充模型首答。

### 3.4 独立新根与旧面退出

- 当前旧输出根完整保留，包括原文、请求、回答、账、失败和人工介入记录。
- 新根重新执行 Stage0/1，由 repository 冻结本根当前材料并建立后续运行，绑定源字节身份，不覆盖源语料；不采用旧根产物。
- 旧回答用于反例和只读诊断，不改版本后冒充新版首答。
- 本期不建设同根语义迁移转换器。
- 新链成为唯一主路径后，旧 Characters/Blueprint、旧全书设计协议及其活动读写入口进入退役。
- 历史格式识别和拒绝集中处理，不保留双写、隐式 fallback 或新系统反向适配旧内部结构。

## 四、实施批次与交付顺序

| 批次 | 实施内容 | 完成条件 |
|---|---|---|
| P0：冻结反例与规格 | 登记活动批次，冻结历史证据，定义新旧契约与评价口径 | 两个已坐实事故及关联死锁形成最小红绿反例；文档与契约职责一致 |
| P1：契约与材料设施 | SourceStory、TargetStory 及中间协议；SourceIndex、材料请求和稳定引用 | schema、版本、权限、预算、耐久恢复及错误归属测试通过 |
| P2：Stage2 主链 | 章节先行、后置全书整合、窄消歧、名称解析和唯一发布 | 新源故事能够从真实入口发布、拒绝、修订和免费恢复 |
| P3：Stage4 主链 | Preserve、整书骨架、逐章展开、目标规则与局部一致化 | SourceStory→目标故事→实际写手材料贯通，保真与重设计边界明确 |
| P4：Stage5 写作与窄修 | 顺序调度、前章短尾、段落补丁、章缝恢复及回执 | 文本依赖真实；未改区域不变；无必要的级联能够停止 |
| P5：跨层闭合 | 节点、消费登记、失效、API/UI、Hook、Stage7 和旧面退出 | 新链可被真实消费者读取；刷新、重启、下载与最终盘面一致 |
| P6：工程验收与效果验证准备 | 回归、离线语义核读、评估 manifest 和运行工具 | 工程证据完整；付费验证就绪；未实测质量与成本明确标为未验证 |

批次按上述顺序落地；契约、producer、consumer、恢复和测试在同一行为批次内闭合。过渡代码不成为可长期选择的第二条主路径。

公开接口同步完成：

- 后端发布 SourceStory、目标故事、章节计划和结构化问题的只读视图。
- 现有监控页增加人物、事件、因果、认识、时间和修订导航。
- 前端类型、查询、fixture、状态展示与后端同批变更；不新增 Stage 编辑或批准按钮。
- 进度顺序、并发能力和可用控制继续由后端提供。
- Stage7 核对当前章包、正文、Hook 和回执后装配，最终文件仍为 `stage7/final/{书名}_rewriting.txt`。

## 五、验证与验收

### 5.1 必须保护的反例

| 场景 | 必须得到的新行为 |
|---|---|
| 婴儿先出场、后具名 | 同一实体持续存在；姓名晚揭不影响参与关系和身体事实 |
| 主角误信阿姐安排，后文否定 | 信念、说法、世界事实和纠正分开，不生成错误确认或假收束 |
| 开场已知与后续获知 | 正式交接开场认识，支持初始误信和后续纠正 |
| 同人多个目标或持有物 | 多个事项并存，互不覆盖 |
| 插叙病史、过去赠物 | 阅读顺序不覆盖当前状态；有效时间与计划身份保留 |
| 无词表、无悬念的行动因果 | 必要前因与结果仍能进入目标建模 |
| 部分回答和孤立 close | 部分回答保持推进；源错误首次定位后回派正确 owner |
| 无持续转移的关键事件 | 能进入保真选择、目标计划和真实写手材料 |
| 世界规则改造 | 正文与 Hook 一致消费目标规则，不能绕过必保机制 |
| 目标章内缺少转场或决定前提 | 回派章计划，写手不自行补关键剧情 |
| 前章短尾修改 | 下章重新核对或窄修；未变短尾不制造后续级联 |
| 耐久响应后崩溃、重复执行 | 免费恢复、不重复业务实体、不重复购买 |
| 旧版本与 unknown 账 | 明确拒绝或阻断，不静默采用和补签 |

### 5.2 工程验证

- 使用 `novel_refactor`；按目录指南执行测试，不并行共享 pytest 临时根。
- 各批先跑 unit/contract、相关 stage 和精确消费者回归。
- 契约稳定后运行 BACKEND_CONTRACT §9.5 五文件。
- 多层公开契约、调度与恢复改动完成并准备合入时，运行一次默认非 corpus 回归。
- 前端完成定向交互测试、typecheck、seams、build，并提供监控页截图。
- 使用确定性 transport 走真实 SourceStory→Stage4→正文/Hook→Stage7，检查最终 TXT、manifest、HTTP 下载及重启读回。

### 5.3 语义、首答和成书质量

新增开发用离线事实标注与比较工具，不恢复已退役的生产判官。冻结源身份、证据、关键事实、实体绑定、因果、认识、时间和线程预期，开发样例与保留样例分开。

评价至少覆盖：

- 关键事实与必要联系召回。
- 无依据新增、主体错误和错误强断言。
- 人物转变、因果与场景衔接的交接充分性。
- 误信纠正、信息差和读者揭示。
- 首响应、首候选、最终自动完成、窄修范围和实际总成本。
- 最终小说的故事自洽、人物连续、自然推进与阅读质量。

首批使用现役 golden manifest 登记的代表书目；第三人称和长上下文能力未实测时单独披露。真实模型验证冻结代码、协议、模型配置、源材料、输出根、书目及额度，经另行授权后执行。

最终验收分开报告工程通过、事实理解、目标设计、首次成文、人工介入和整书质量。合成测试、最终机械接受或人工修订后的成功，均不能代签“首答可用率已经提高”或“整书成本已经下降”。
