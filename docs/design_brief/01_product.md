# 这个工具是什么

## 一句话

把一本网络小说的原作，经过 8 个阶段（stage0~7）的流水线，**重构成一本新书**——
情节骨架保留，文字全部重写，人名全部替换。
每个阶段的产出都要**由人验收**之后才往下走。

## 谁在用

**一个人，在自己的电脑上，用桌面浏览器。** 服务只绑 `127.0.0.1`。
没有登录、没有协作、没有权限、没有通知。他一次处理一本书，一本书从头到尾大概几小时，
中间要停下来看很多遍。

## 界面存在的唯一理由

流水线的每一步都是 LLM 产出的。**它的错误不会崩溃，会安静地通过。**
典型的三种：

- 它把原文的「江随野身边人」写成「江家丫头」——**造了一个事实**，读起来毫无破绽；
- 它在第 1 章就说出了第 14 章才揭晓的秘密——**剧透**，只有对着原文才看得出来；
- 它把一段该保留的关键台词整段丢了——**漏了内容**，成稿依然通顺。

自动校验器抓得住一部分（能写成结构不变量的那些），抓不住的那部分**只能靠人眼**。
所以这个界面的主体动作永远是同一个：

> **把两份东西并排放在一起，让人自己看，然后由人做决定。**

「原文 ↔ 抽出来的骨架」「计划 ↔ 写手真正拿到的材料」「原文 ↔ 重构稿」
「校验报告 ↔ 可编辑的成稿」「三个候选 ↔ 选一个」「旧人名表 ↔ 新人名表」。

**它不是 dashboard，不是监控大屏，不是项目管理工具。**
它更接近一个「审校台」：主体是大段中文文本，需要长时间盯着读、来回对照。
图表在这里几乎没有用武之地——全书只有极少数地方需要一个数字对比条。

## 八个阶段（用户视角）

| 阶段 | 做什么 | 人在这一步看什么 |
|---|---|---|
| **stage0 剔除番外** | 自动删掉番外/后记/尾声/作者有话说，**人批准后才能往下走** | 删对了吗？有没有把正文当番外删掉、有没有漏掉一段番外？**可以直接改** |
| **stage1 摄入分章** | 把批准过的文本切成章 | 切对了吗？有没有漏章？ |
| **stage2 抽骨架** | 逐章抽出「发生了什么」——事件拍（beat）、人物、关系、世界规则、秘密 | 抽全了吗？抽错了吗？**对着原文逐段看** |
| **stage3 量文风** | 量原作的句长/段长/对白比/篇幅，转成「档位词」发给写手 | 量出来的事实 ↔ 真正发给写手的指令，是不是一回事 |
| **stage4 定计划** | 定每章目标、每一拍分多少字预算 | 计划决定了什么 ↔ 写手手里实际会有什么 |
| **stage5 写作 + 验收** | 两条臂：**深度**=闭卷重构（写手看不到原文）/ **浅层**=开卷改写。写完自动验收，能自救的自救 | 成稿 ↔ 它该守住的材料；原文 ↔ 重构稿 |
| **stage6 开篇文案** | 产 3 个候选文案，**人选一个定稿** | 三候选并排 |
| **stage7 人名替换 + 成书** | 产一份新人名表，确定性替换全书，拼出 `book.txt` | 新旧人名表并排 + 逐章替换前后对照，**人定稿** |

**阶段号是 0~7。** 〔2026-08-10 推翻了原来那条「没有 stage0」——
加了一层非正文剔除 + 人工审阅闸门，理由见 `docs/BACKEND_CONTRACT.md` 的 `R-0`。
**它与 1~7 性质不同**：那七层都在**产出**，stage0 是**进料前的清洗**，
而且是全链唯一一个「不点批准就不往下走」的硬闸门。〕

## 三种动作，界面上必须分得清清楚楚

| 类别 | 例子 | 用户的心理 |
|---|---|---|
| **看**（纯读） | 打开任何一屏 | 随便点 |
| **0 成本重算**（免费，但会写盘） | `--recheck` 按当前规则重判已有成稿、`--context-only` 重建写作上下文、`--approve` 定稿 | 放心点，但它改了盘上的东西 |
| **调 LLM**（**要花真钱**） | 抽骨架、写一章、产文案 | **点之前要想一下**，点错了钱就没了 |

第三类必须二次确认，且确认框里要显示**将要执行的那条完整命令**。
第一类和第二类不能长得像第三类，第三类也不能长得像它们（`U-08`~`U-10`）。

## 一次完整的流程叙事（读一遍就懂这个工具的节奏）

1. 打开 **语料库**，把一个 `.txt` 拖进去。
2. 跑 stage0（免费）→ 打开**剔除审阅**：整本原文摊开，判据认出的番外段被标成待删。
   **这一步是全链唯一的硬闸门，不点批准就走不下去。** 要看的是两件事：
   有没有把正文当番外删掉（判据能报警）· **有没有漏掉一段番外**（判据完全看不见——
   番外若用纯数字章节号写，它和正常章节长得一模一样）。
   漏了就**直接在这儿圈掉或改掉**，这是唯一能改正文的地方。批准。
3. 跑 stage1（免费）→ 打开**原文↔切分对照**：批准过的文本按「文案 / 8 章正文」分区着色。
   扫一眼确认没有漏章、章号没断。
   **纯读，没有任何写操作**：分章是确定性的，切错了改算法重跑，不在界面上手改。
4. 跑 stage2（**花钱**）→ 打开**原文↔骨架对照**，逐章翻：左边原文按段落分块并高亮，
   右边是抽出来的 8 个 beat。发现第 3 章开头那段环境交代没有被任何 beat 覆盖 → 定向重跑第 3 章。
5. 打开**全局设定**：15 个人物、15 条关系。默认**关着剧透**——因为写手不该知道结局。
   要检查的时候手动打开开关。
6. 跑 stage3（花钱）→ **文风页**左边是量出来的数字，右边是真正发给写手的档位词。
   **档位词有没有变，比数字有没有变更要紧。**
7. 跑 stage4（花钱）→ **计划页**逐拍并排：左「这一拍 130 字预算、由源章第 1~2 拍合成」，
   右「写手为这一拍拿到的两句事件摘要 + 一句必须逐字写进去的原话 + 在场的人」。
8. 跑 stage5（花钱，逐章）→ **成稿页**：左边材料、右边成稿，成稿里再按「必须逐字保留的原话」
   把原文和重构稿切成对齐的块并排。
9. 验收自动跑完，产出 61 条结论（其中 41 条只是「度量」）。打开**待人工**：6 条需要人处理。
   点进**验收/修订页**，左边是这一章判出来的问题、右边是可编辑的成稿，直接改，保存落成新的一轮。
10. 跑 stage6 → **三候选文案并排**，选一个，**定稿**。
11. 跑 stage7 → **新旧人名表并排**，看「漏网叫法候选」（这是唯一能发现人名表本身漏了人的地方），
    看逐章替换前后对照，**定稿** → 组装出 `book.txt`。

第 2、4、7、8、9 步是这个工具的核心，也是设计难度所在。
**第 2 步（stage0 审阅）是新加的**，它和第 9 步一样属于「人必须做决定」那一类。
