**你要设计的是一个已经跑通、但界面很难看的本地工具的全新前端。**
后端逻辑不改、数据形状不改——**只重做界面**。

## `05_samples/` 是真实数据，不是示意

这 19 个文件是把现役后端跑起来、逐个 endpoint 抓下来的原始响应，**一个字节都没改**。
它们有三重用途，请务必都用上：

1. **真实的文本密度。** 中文长文本的排版只能拿真文本试——一章正文 1100~1500 字、
   一个 beat 的 `events` 两三句、一条校验结论 60~200 字。用 lorem ipsum 或短假数据设计出来的版式，
   放进真数据就塌。
2. **真实的数量级。** 一本书 8 章、15 个人物、15 条关系、一份验收报告 61 条结论
   （其中 41 条是「度量」不是「问题」）、一屏 76 行替换对照。**极端值也在里面**：
   有的数组是空的（`secrets: []`、`jobs: []`），空态要照着它设计。
3. **前后端的契约。** 你写的 TypeScript 类型直接从这些 JSON 推。后端会照着同样的形状产出——
   所以**不要重命名字段、不要压平嵌套、不要把两个 endpoint 的数据合成一个**。
   想要不同的形状，写在交付说明里告诉我们，不要自己在前端改。

映射见 `02_screens.md` 每屏的「数据来源」行。

> 样本里含小说原文与重构稿片段（这是工具的处理对象）。只用于排版设计。

## 你要交付什么

一个能 `npm run dev` 跑起来的 **React + Vite + TypeScript** 仓库，用 `05_samples/` 当 mock 数据，
13 屏全部可点、可导航、四种状态（加载/空/错误/正常）都做出来。细节见 `04_delivery.md`。

## 你**不要**做的四件事

1. **不要设计 API。** 不新增 endpoint、不改字段名、不改 URL 形状。
2. **不要在前端算判定。** 「这个通过了吗」「这一步花不花钱」「这份产物过期了吗」——
   **服务端已经算好并下发了**（`badge` / `paid` / `freshness`）。前端照着画，不许自己推。
   这条是硬的，理由见 `03_ui_rules.md` U-11。
3. **不要发明新的评分、进度百分比、健康度、AI 建议卡片。** 这个工具的全部价值在于
   「让人自己看两份东西并做判断」，一个编出来的分数会直接取代那个判断。
4. **不要做登录、多用户、权限、移动端优先、国际化。** 单人、本机、桌面浏览器。

## 现有界面的截图

如果同时收到截图：**只看信息结构，不要看样式。**
现有界面是功能原型，配色、字体、间距、层级全部作废，重新设计。
截图能回答的只有一件事——「这一屏上同时摆着哪些东西」，尤其是几个左右并排的对照视图，
那个用文字描述不如看一眼。
