# 硬规则

每条都来自这个项目踩过的真实损失。**当验收清单用，逐条对。**

贯穿全部的一条总纲：

> ## U-00 · 「不知道」永远不能画成「没问题」
>
> 这个工具处理的是 LLM 产出，而 LLM 的错误不会崩溃，会**安静地通过**。
> 界面上每一处把「查过，没问题」和「查不了 / 没查 / 不知道」画成同一个样子的地方，
> 都是在替用户断言一件没人验证过的事。下面 U-01~U-06 全是它的具体形态。

---

## 一、状态与颜色

### U-01 · 产物新鲜度是**三态**
`freshness ∈ {fresh, stale, unknown}`。
- `fresh` = 它记录的上游指纹与盘上现在这份对得上
- `stale` = 对不上，**这是这个界面最值钱的信号**
- `unknown` = 这份产物没有来源记录，**无从判断**

`unknown` 必须与 `fresh` 一眼可分。画成同一个绿点，就等于宣布「已验证」。
（历史上这里出过一次事故：23 章成稿与任何一版上下文都配不上，而界面全绿。）

### U-02 · 校验徽章是**三态**
`badge ∈ {pass, amber, fail}`。
**`amber` = 通过了，但有 N 项查不了**（`passed: true` 且 `unver_count > 0`）。
它**不是绿色**。样本 `check_stage5_review.json` 就是这个态：0 条 hard、2 条 unver。

### U-03 · 结论严重度是**四级**，其中一级不是问题
`sev ∈ {hard, info, metric, unver}`：
| sev | 含义 | 视觉 |
|---|---|---|
| `hard` | 阻断级 | 最强 |
| `info` | 提示级，要人看一眼 | 中 |
| `metric` | **度量，不是问题** | **不能用警告色**。它是「篇幅 1135/1120 = 1.01×」这类事实 |
| `unver` | 查不了 | 独立的第四种，不是 pass 也不是 fail |

样本里一本书 61 条结论，**41 条是 `metric`**。把它们画成警告，整屏都是红黄，真正的 `info` 就淹了。

### U-04 · 作业状态有 `unknown`
`state ∈ {running, ok, failed, unknown}`。服务重启后原本 `running` 的一律改判 `unknown`——
不是 `ok`。重启前它是死是活，我们真的不知道。

### U-05 · 空数组不等于「没问题」
`secrets: []` 的意思是「这本书没抽到秘密」，那**可能是漏抽了**。
不要渲染成一个安静的空白或一句「无」。

### U-06 · 遮蔽只要是部分的，就必须标注为部分
全局设定页的剧透开关只遮住四个字段，**已知还有旁路会漏**（`role`、
`relations.valid_from_chapter`、`world_rules[].desc`）。
后端下发了 `partial_mask_note` 这句话，**它必须常驻显示在开关旁边**，不能收进 tooltip。
一个没标注的部分遮蔽，会被当成完整遮蔽用。

---

## 二、钱

### U-07 · 花钱和不花钱必须一眼分得开
依据只有一个：服务端下发的 **`paid` 布尔值**。
**36 个动作里只有 7 个真花钱**，其余全是 0 成本诊断——**视觉权重应该反过来**：
免费动作是日常操作，花钱动作是需要停一下的操作。

### U-08 · 有第三类：免费，但会写盘
`--recheck` / `--revalidate` / `--approve` / `--apply-edit` 不花钱，
但它们**会改盘上的产物**（刷新指标、提升问题稿、落定稿、归档旧轮）。
它们和「纯读」不是一回事，值得一个中间态的视觉。

### U-09 · 付费确认框里要显示**将要执行的那条完整命令**
不是「你确定要跑 stage2 吗」，而是把服务端 preview 给的那条 argv 原样摆出来。
用户靠它确认参数没点错——尤其是 `--chapters 3,7` 这种。

### U-10 · 不要显示预估花费 / 预估调用次数
后端不提供，也不打算提供。**猜一个数写在界面上，比不显示更坏**。

---

## 三、判定归谁算

### U-11 · 前端一行判定逻辑都不许有
`badge` / `paid` / `freshness` / `sev` / `passed` **全部由服务端算好下发**，前端照着画。
不要写 `paid && !extra`、不要写 `hard.length === 0 ? '绿' : '红'`、
不要自己判断一份产物新不新。

> 这条不是洁癖。历史上前端自己算过一次「贵不贵」，结果免费的迁移按钮带着 💰 和付费警告，
> 而真正花钱的按钮画成了普通按钮。同一件事有两个落点，它们一定会分家。

### U-12 · 不要从文案里正则抠结构
一条结论涉及哪几章（`chapters`）、修它要跑什么（`fix`），
**服务端已经结构化下发了**。不要去解析 `detail` 那段中文。
文案改一个字，正则就会**静默**失效。
没有 `fix` 字段的结论，界面就不该画「重跑修它」按钮。

---

## 四、文本与排版

### U-13 · 服务端已经切好片，前端不要按下标切字符串
`segments` / `spans` 里的 `start` / `end` 是 **Python 码点下标**，而 JS 字符串是 **UTF-16 码元**。
纯中文两者重合，但网文常带 emoji，**出现一个就让其后所有偏移静默错位**。
服务端把切好的 `text` 一起发过来了，直接用。

### U-14 · 这是一个中文阅读界面
- 字体栈**中文优先**，不要 Latin-first 的默认栈把中文落到宋体或系统兜底字体
- 正文区行高要按长时间阅读设计（中文比拉丁字母更需要行距）
- **不要 `text-align: justify`**（中文两端对齐会拉出难看的字距）
- 段落之间用间距分隔，不要首行缩进 + 零间距的纸书排法（原文本身是网文，段落极短，
  常常一句一段——样本里能看到）
- 正文块的宽度要有上限，但**并排视图里两栏各自的上限要一致**，否则对照会错位

### U-15 · 并排是主视图，不是 tab
S-04 / S-07 / S-08 / S-09 / S-11 / S-12 的价值**全部在于同屏对照**。
把左右做成两个 tab、或者做成「点开看详情」的弹层，等于把这个工具的核心功能删掉。
两栏高度天然不等（左边 1461 字原文 vs 右边 9 个结构化 beat），这是要解决的设计问题，
不是改成 tab 的理由。

### U-16 · 对照视图里，「对不齐」的部分要显式标出来
S-08 的原文↔成稿并排，只有 3/8 拍能锚定，其余的拍并进相邻块。
**这种块必须有视觉标记**，并且锚点覆盖率（`锚 3/8 拍`）要常驻显示。
没有这个数，「这一行盖了 3 拍」和「这一行就是第 3 拍」长得一模一样。

---

## 五、行为

### U-17 · 空态要说「还没跑」，并给出下一步
不要「暂无数据」。用户需要知道的是「这一步还没做 / 做了但被拦下了 / 上游还没好」，
以及现在该点哪个按钮。
有两屏的空态特别重要：**S-01 一本书都没有**（首次使用）和 **S-10 待人工清空**（这是目标状态，
应该让人觉得「好了」）。

### U-18 · 不要发明进度百分比、健康分、AI 建议
「跑到哪一步了」是一串产物在不在盘上，不是一个百分比。
一个编出来的分数会直接取代用户自己的判断，而这个工具的全部价值就是那个判断。

### U-19 · 没有取消按钮
LLM 调用在途时钱已经花了，kill 掉省不回来。不要设计取消。

### U-20 · 视口 1280~2560 宽，桌面浏览器
不做移动端、不做响应式抽屉。但**要用满宽屏**——并排视图在 2560 上应该更好用，
而不是把内容锁在 1200px 居中。
